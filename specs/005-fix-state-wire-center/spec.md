# 기능 명세: 상태 외곽 연결과 Resize 좌표 보정

**작성일**: 2026-10-26
**상태**: 명확화 완료
**입력**: 상태 외곽 연결은 유지하고 Magnetic 격자 우선순위 변경은 원복한다. Activity Resize 시 Wire 상대 좌표를 재계산하여 화면 위치가 어긋나지 않게 한다.

## 사용자 시나리오와 검증

### 사용자 이야기 1 - 상태 외곽 연결 유지 (우선순위: P1)

편집자는 상태의 중심을 향하되 원 외곽에서 끝나는 연결을 사용한다.
우선순위 근거는 기존에 합의한 상태 표현 보존이다.
독립 검증은 양 상태의 반지름 10과 인접점·접점·중심의 일직선 확인이다.
직선·꺾임·명시적 접점·미리보기·이동에서 같은 규칙을 적용한다.

### 사용자 이야기 2 - Magnetic 원복 (우선순위: P1)

편집자는 이전처럼 양 Activity의 후보 중 마우스에 가까운 격자를 선택한다.
우선순위 근거는 사용자가 직전 수정의 원복을 명시했다는 것이다.
독립 검증은 두 중심이 어긋난 공통 범위에서 양쪽 격자 후보가 선택되는지 확인한다.
시작 Activity 우선 규칙을 제거하고 기존 단일 Activity 스냅 및 범위 밖 자유 이동을 보존한다.

### 사용자 이야기 3 - Resize 중 Wire 위치 유지 (우선순위: P1)

편집자는 Activity 너비를 바꿔도 Wire 꺾임점이 중심 변화량에 따라 밀리지 않기를 원한다.
우선순위 근거는 크기 조절 후 화면 좌표의 불일치를 해결하는 것이다.
독립 검증은 Resize 전후 꺾임점 절대 좌표를 비교하고 저장·재열기·실행 취소를 확인한다.

1. 좌우 확대·축소 시 각 꺾임점의 화면상 좌표를 유지한다.
2. 시작 또는 끝 또는 양쪽 Activity를 Resize해도 동일하다.
3. 미리보기와 저장 후 표시가 일치하고 실행 취소·재실행으로 노드와 상대 좌표가 함께 복원된다.

### 경계 조건

꺾임점 0~여러 개, 서로 다른 상대 좌표와 weight, 다중 선택 Resize, 상태와 연결된 Activity를 포함한다.
Resize가 아닌 기존 노드 이동은 꺾임점의 비례 이동 규칙을 유지한다.
Activity 끝점은 새 경계에 접하도록 기존 계산을 유지하며 불가피한 경계 이동을 꺾임점 이동과 구별한다.
방향이 없는 동일 중심의 상태 연결은 중심 좌표의 퇴화 경로다.

## 요구사항

- **FR-001**: 상태 끝점은 저장 접점과 무관하게 중심 방향의 원 외곽에서 끝나야 한다.
- **FR-002**: Magnetic 후보 선택을 양 Activity의 가장 가까운 후보를 사용하는 기존 동작으로 되돌린다.
- **FR-003**: Resize된 노드의 중심 변화량을 Wire 상대 꺾임점 좌표에서 보정하여 절대 위치를 유지한다.
- **FR-004**: Resize 미리보기와 XML 저장에 같은 보정을 적용하고 weight·추가 속성·꺾임점 순서와 개수를 보존한다.
- **FR-005**: 좌우·시작/끝·다중 선택 Resize, 실행 취소·재실행·저장 후 재열기와 기존 이동 동작을 보장한다.

### 주요 개체

상태는 중심과 반지름 10의 원이다. Activity는 위치와 너비로 중심을 정한다.
Wire 꺾임점은 양 끝 중심 기준 상대 좌표와 weight를 가진다. 저장 형식은 유지한다.

## 성공 기준

- **SC-001**: 상태 외곽 회귀 검사에서 반지름 및 방향 오차가 0.000001 이하다.
- **SC-002**: Magnetic 원복이 이전 선택 함수와 동일하며 양쪽 후보 회귀 검사가 통과한다.
- **SC-003**: Resize 직후 꺾임점 절대 좌표 오차는 0.000001 이하이고 XML 정수 직렬화 후에는 기존 반올림 오차 범위 이내다.
- **SC-004**: 관련 Resize 및 저장·실행 취소 회귀 검사가 통과한다.

## 가정과 명확화

Resize는 연결된 노드의 크기가 바뀌는 경우다. 왼쪽 Resize의 위치 변화도 중심 보정에 포함한다.
연결 끝점은 변경된 도형 경계를 따르고 내부 꺾임점의 화면 위치를 보존하는 것이 목적이다.
사용자 요청과 기존 좌표 모델로 범위가 명확하여 추가 질문은 0건이다.
기존 읽기 전용 전환의 화면 복원 실패는 변경 전에도 확인된 별도 문제다.

## 추가 사용자 이야기 4 - Snap 토글 통합 (우선순위: P1)

편집자는 Snap이라는 공통 토글로 Wire와 Child 간 붙이기 및 보조선을 제어한다.
우선순위 근거는 표시 명칭과 동작 범위를 일치시키는 것이다.
독립 검증은 Snap 꺼짐에서 자유 이동·Resize·보조선 없음, 켜짐에서 기존 정렬·보조선을 비교한다.
기본값은 기존 Wire 토글과 같은 꺼짐이다. 켜짐에서도 Alt 우회를 유지한다. 드래그 중 끄면 보조선을 즉시 정리한다.

### 추가 요구사항

- **FR-006**: Magnetic 표시 명칭과 관련 코드 용어를 Snap으로 변경한다.
- **FR-007**: Child 이동·Resize의 다른 Child 참조 정렬과 보조선은 Snap 켜짐에서만 작동한다.
- **FR-008**: Snap 꺼짐·드래그 중 끄기·Alt 우회에서 자유 조작과 보조선 정리를 보장하고 최소 너비를 유지한다.
- **SC-005**: Snap 토글 켜짐·꺼짐 및 Alt·동작 중 끄기 회귀 검사가 통과한다.

기존 Wire 토글 상태를 공통 기준으로 확장한다. 추가로 명확화가 필요한 사항은 없어 질문은 0건이다.


## 추가 사용자 이야기 5 - 전역 Snap 상태 (우선순위: P1)

사용자는 한 모델 편집기에서 바꾼 Snap 상태를 모든 열린 편집기와 이후 여는 파일에서 동일하게 사용한다.
우선순위 근거는 파일별 토글 불일치 방지다. 전역은 애플리케이션 범위이며 프로젝트가 달라도 같은 설정이다.
독립 검증은 두 파일 편집기를 열고 한쪽 토글 변경이 다른 쪽 Canvas와 툴바에 즉시 반영되는지 확인한다.

1. 한 편집기에서 켜고 끄면 이미 열린 편집기 모두 같은 상태가 된다.
2. 파일을 닫고 다시 열거나 다른 파일을 새로 열면 마지막 상태를 사용한다.
3. 저장된 애플리케이션 설정을 복원하면 기존 및 새 편집기에 반영한다.
4. 편집기를 닫으면 구독을 해제하여 이후 상태 변경 때 닫힌 화면을 갱신하지 않는다.

### 추가 요구사항과 성공 기준

- **FR-009**: Snap의 기준 상태는 애플리케이션 전역의 영속 설정 한 곳에서 관리한다. 최초 기본값은 꺼짐이다.
- **FR-010**: 열린 모든 모델 편집기와 툴바에 변경을 반영하고 새 편집기는 저장된 상태로 시작한다.
- **FR-011**: 설정 복원 및 편집기 해제에 안전하게 대응하고 모델 XML과 기존 프로젝트별 모델 설정을 변경하지 않는다.
- **SC-006**: 두 개 이상의 편집기에서 양방향 토글과 닫기·재열기·설정 복원 검증이 통과한다.

전역 범위와 재열기 보존 요구가 명확하여 질문은 0건이다. IDE 재시작도 애플리케이션 설정 영속화로 지원한다.
