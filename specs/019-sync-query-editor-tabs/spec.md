# 기능 명세: 쿼리 편집기 탭 위치 동기화

**작성일**: 2026-11-04
**상태**: 명세 검증 완료
**입력**: Design에서 Source로 이동하면 선택한 쿼리로 커서를 이동하고, Source에서 Design으로 이동하면 커서가 있는 쿼리를 선택한다. 대응 쿼리가 없으면 첫 번째 쿼리를 선택한다.

## 사용자 시나리오 및 검증

### 사용자 이야기 1: Design에서 Source로 이동 (우선순위: P1)

사용자는 선택한 쿼리의 원문을 바로 확인한다. 독립 검증은 두 번째 쿼리를 선택한 후 Source 탭으로 전환해 커서 위치를 확인한다.

1. 두 번째 쿼리를 선택하고 전환하면 해당 query 여는 태그 시작으로 커서가 이동하며 화면에 표시된다.
2. 선택한 쿼리의 이름이나 SQL을 수정한 직후 전환해도 수정 내용을 반영한 동일 쿼리로 이동한다.

### 사용자 이야기 2: Source에서 Design으로 이동 (우선순위: P1)

사용자는 원문의 현재 위치에 해당하는 쿼리를 편집한다. 독립 검증은 쿼리의 속성·본문·닫는 태그 안에서 전환해 선택과 편집 내용을 확인한다.

1. query 범위 내부의 커서에 대응하는 쿼리를 목록에서 선택하고 화면에 표시한다.
2. 루트 속성, 쿼리 사이 공백, 주석, 문서 끝처럼 대응하는 쿼리가 없으면 문서 순서상 첫 번째 쿼리를 선택한다.
3. 쿼리 ID가 중복되거나 비어 있어도 위치로 실제 쿼리를 구별한다.

### 경계 조건

- 쿼리가 없는 문서나 잘못된 XML은 예외 없이 기존 빈 화면 또는 오류 안내를 유지한다.
- 삭제된 선택 쿼리는 첫 번째 쿼리로 대체한다.
- 읽기 전용에서도 탐색할 수 있다. 탭 전환만으로 문서와 실행 취소 이력이 변경되지 않는다.
- 파일별 탐색 상태를 분리하고 폐기된 편집기의 예약 작업은 무시한다.
- 기존 외부 쿼리 ID 탐색 요청은 계속 우선 처리한다.

## 요구사항

- **FR-001**: Design의 선택 쿼리에 대응하는 Source 위치로 커서를 이동하고 스크롤한다.
- **FR-002**: Source 커서가 포함된 query를 Design에서 선택하고 목록에 표시한다.
- **FR-003**: 대응 쿼리가 없으면 문서 순서상 첫 쿼리를 사용한다. 쿼리가 없으면 선택하지 않는다.
- **FR-004**: 저장 전 편집 내용, 중복 ID, 빈 ID, 읽기 전용, 오류 XML 및 편집기 폐기를 처리한다.
- **FR-005**: 탭 전환 자체는 문서나 실행 취소 이력을 바꾸지 않으며 기존 외부 탐색을 보존한다.

### 주요 개체

- 쿼리: queryMap 직계 query, 현재 문서 위치와 선택 상태.
- 탭 전환 위치: Design의 선택 쿼리와 Source를 떠날 때의 커서 위치.

## 성공 기준

- **SC-001**: 양방향 전환·첫 쿼리 대체·중복 및 빈 ID·읽기 전용·오류 문서 자동 검증이 통과한다.
- **SC-002**: 저장하지 않은 수정 직후에도 최신 쿼리를 선택하고, 탐색만 수행한 전환 전후 문서 내용이 동일하다.

## 가정 및 명확성 검토

2026-11-04: 질문 0개. Source 목적지는 query 여는 태그 시작으로 정한다. query 범위는 시작을 포함하고 끝 바로 다음 위치는 포함하지 않는다. 대응 쿼리가 없는 위치는 첫 쿼리로 대체한다. 모든 범주에서 구현을 막는 중대한 모호성이 없다.

## SQL 글자 위치 양방향 보존

이 절이 기존 Design → Source의 여는 태그 시작 이동 정책을 대체한다.

- FR-006: Source의 SQL 글자 위치에서 Design으로 전환하면 같은 쿼리 SQL의 해당 글자 위치에 커서를 둔다. CDATA·XML 엔티티·여러 텍스트 구간을 실제 SQL 글자 기준으로 대응시킨다.
- FR-007: Design에서 Source로 전환하면 SQL 커서가 가리키던 글자의 원문 위치로 이동한다. 저장 전 SQL 변경도 최신 원문에 적용한 뒤 대응시킨다.
- FR-008: 쿼리별 마지막 SQL 커서 위치를 보관하고 문서 갱신·쿼리 전환으로 끝에 밀리지 않게 한다. SQL 대응 위치가 없는 Source 속성·태그는 해당 쿼리의 마지막 위치 또는 SQL 처음으로 대체한다. 본문이 없으면 기존 query 시작을 사용한다.
- SC-003: 여러 줄·CDATA·엔티티·분할 CDATA·중복 ID에서 SQL 중간 글자와 끝 위치의 양방향 대응 및 반복 전환이 통과한다.
- SC-004: Source 수정·Design의 미반영 SQL 수정·반복 갱신 후에도 대응 위치를 보존하고 탐색만으로 원문과 실행 취소 이력을 바꾸지 않는다.
- 명확화: 사용자가 Source → Design의 해당 글자 위치 보존과 역방향도 요청했다. SQL 본문 기준이며 쿼리 선택·첫 쿼리 대체·외부 탐색 우선순위와 수명 보호는 유지한다. 추가 질문이 필요한 중대한 모호성은 없다.
