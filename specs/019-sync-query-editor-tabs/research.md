# 조사 및 결정

- 결정: 쿼리 ID 대신 스마트 XML 요소 포인터를 사용한다. 근거: 중복·빈 ID와 이름 변경에도 실제 쿼리를 구별할 수 있다.
- 결정: Source의 커서 위치는 비활성화 시 기록하고 Design에서 한 번 소비한다. 근거: 숨겨진 Source의 오래된 커서가 Design 목록 변경을 되돌리지 않게 한다.
- 결정: Source 목적지는 query 시작이다. SQL 본문보다 속성과 본문 전체의 위치가 명확하다.
- 결정: 커밋 및 선택 갱신에는 기존 쓰기 안전 조건과 모달리티를 사용한다. 읽기 전용에서도 탐색 자체는 동작한다.
- 대안: 매번 FileEditorManager에서 다른 탭을 검색하는 방식은 편집기 생성 순서와 테스트·분할 화면에 의존하므로 채택하지 않는다.
- 미확정 사항 없음. 기존 외부 ID 탐색 요청은 우선 처리한다.
글자 위치 보존 결정: IntelliJ XmlText의 physicalToDisplay·displayToPhysical API로 CDATA와 엔티티를 대응시킨다. 원문 문자열의 단순 인덱스 차이는 엔티티와 분할 CDATA에서 잘못되므로 제외한다. SQL 버퍼별 커서 위치를 문서 갱신 전후 복원하고 공유 위치는 스마트 포인터와 함께 전달한다.
