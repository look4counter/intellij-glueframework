# 기능 명세: QueryEditor SQL 포매팅

작성일: 2026-11-07
상태: 명확화 완료
입력: 사용자가 제공한 SELECT T 열 정렬·앞쪽 콤마·CTE 4칸·CASE 정렬로 SQL 포매팅을 추가한다.

## 사용자 시나리오와 검증

### 사용자 이야기 1: 지정 스타일 (우선순위 P1)

사용자는 선택한 SQL을 아래 스타일로 정리한다.
독립 검증: 한 줄로 입력한 같은 SQL을 포매팅했을 때 기준 결과와 정확히 일치하고 두 번 적용해도 같아야 한다.

```sql
WITH TB_MAST AS (
    SELECT *
      FROM DUAL A
     WHERE A.COL1 = COL
)
, TB_SUB AS (
    SELECT *
      FROM DUAL
)
SELECT COL1
     , COL2
     , COL3
     , CASE
       WHEN COL4 = COL3
       THEN CC
       ELSE 'ABC'
       END AS BB
  FROM TABLE
 WHERE COL1 = COL
   AND COL2 = COL
 GROUP BY COL1
 ORDER BY COL2
```

1. SELECT의 마지막 T 열에 FROM·WHERE·AND 등 앞쪽 키워드의 마지막 글자를 맞춘다. GROUP BY·ORDER BY는 첫 단어의 마지막 글자를 맞춘다.
2. SELECT 목록의 후속 콤마는 T 열에 두며 CTE 정의 사이 콤마는 예시처럼 줄 맨 앞에 둔다.
3. CTE 본문은 4칸씩 들여쓴다. CASE의 WHEN·THEN·ELSE·END는 CASE 시작 열에 맞춘다.

### 사용자 이야기 2: 편집기 적용과 복원 (우선순위 P1)

사용자는 SQL 영역의 IDE 코드 정리 단축키로 선택한 쿼리 전체를 정리한다.
독립 검증: 두 쿼리가 있는 파일에서 하나를 정리하고 Source 반영·저장·단일 Undo/Redo를 확인한다.

1. 선택한 쿼리의 SQL만 변경하고 ID·설명·다른 쿼리·XML 주변 내용은 유지한다.
2. 읽기 전용·잘못된 XML·혼합 SQL 본문·대상 없음·폐기 상태에는 변경하지 않는다.
3. 형식이 같으면 불필요한 수정 명령을 만들지 않는다. 지연 실행 중 선택이 바뀌면 이전 요청을 적용하지 않는다.

### 경계 조건

- 문자열·인용 식별자·파라미터·주석의 본문은 바꾸지 않는다. 줄 주석 다음 SQL이 주석에 포함되지 않도록 줄바꿈한다.
- 닫히지 않은 문자열·블록 주석·괄호와 분석 한계 초과는 원문을 유지하고 편집기에 사유를 안내한다.
- 함수 인자의 콤마는 인라인으로 유지한다. GROUP BY·ORDER BY의 여러 항목은 첫 항목에 맞춰 앞쪽 콤마로 정렬한다.
- JOIN·ON·OR·HAVING도 같은 키워드 기준 열을 사용한다. BETWEEN의 첫 AND는 조건 분리로 취급하지 않는다.
- SELECT 별표와 함수·괄호·서브쿼리·CASE 중첩은 SQL 토큰 의미를 보존한다.

## 요구사항

### 기능 요구사항

- FR-001: 위 기준 결과에 정확히 일치하는 SELECT·WITH·CASE·조건·GROUP BY·ORDER BY 정렬을 제공한다.
- FR-002: 콤마는 목록 항목 앞에 배치하고 중첩 쿼리 본문은 4칸 들여쓴다. 함수 인자는 인라인으로 유지한다.
- FR-003: SQL 키워드는 대문자로 정리하되 문자열·인용 식별자·파라미터·주석 내용은 보존한다.
- FR-004: IDE 코드 정리 단축키로 선택 영역이 있으면 그 부분에, 없으면 현재 쿼리 전체에 적용한다. 열기·저장 때 자동 적용하지 않는다.
- FR-005: Source 반영과 저장, 한 번의 Undo/Redo를 지원하고 다른 쿼리와 XML 속성·주변 내용을 보존한다.
- FR-006: 읽기 전용·오류 XML·혼합 본문·대상 없음·폐기·지연 중 선택 변경·안전하지 않은 쓰기 문맥을 보호한다.
- FR-007: 잘못된 입력·과도한 길이·깊이를 안전하게 거부하고 원문을 유지하며, 같은 입력에 반복 적용해도 결과가 변하지 않는다.
- FR-008: 단위·편집기 통합·기존 전체 회귀 검증과 지원 규칙·제한 문서화를 수행한다.

### 주요 개체

- 포매팅 요청: 선택 쿼리와 실행 시점의 문서·선택 상태.
- SQL 토큰: 원래 문자열·종류·위치와 괄호 관계.
- 정렬 범위: 쿼리 시작 열·SELECT T 기준 열·목록 표현식 열·CASE 열.
- 결과: 포맷한 SQL 또는 원문 유지가 필요한 거부 사유.

## 성공 기준

- SC-001: 기준 결과 정확 일치, 반복 적용 동일성, 문자열·주석 보존 검증이 모두 통과한다.
- SC-002: 실제 편집기에서 선택 SQL만 반영되고 단일 Undo/Redo·저장·보호 검증이 통과한다.
- SC-003: 문맥 자동완성을 포함한 전체 회귀 테스트에서 실패·오류·건너뜀이 0개이며 ZIP 구조 검증이 통과한다.

## 가정과 명확화

- 질문 0개. 사용자 예제를 기준으로 현재 쿼리 또는 SQL 선택 영역을 포맷한다. Source XML 전체 포맷은 추가하지 않는다.
- 일반 코드 정리 단축키는 사용자 IDE 키맵 설정을 따른다. SQL 편집기에 포커스가 있을 때만 전용 동작을 사용한다.
- 주석·리터럴을 제외한 원래 식별자 대소문자는 유지한다. DB별 모든 문법·절차형 SQL의 자동 교정은 보장하지 않는다.
- 구문 오류를 고치거나 SQL을 실행하지 않는다. 기존 저장 여백 정리 정책은 유지한다.

## 후속 요구사항: 버튼 제거와 DML 정렬

- FR-009: SQL 포맷 버튼을 제거하고 기존 코드 정리 단축키는 유지한다.
- FR-010: UPDATE와 INSERT는 첫 키워드 마지막 E·T 열에 SET·INTO·VALUES·WHERE 등을 정렬하고 SET·컬럼·값 목록의 콤마를 앞에 둔다. MERGE는 E 열을 기준으로 INTO·USING·ON과 WHEN 분기 및 UPDATE·INSERT 절을 정렬한다.
- 수용 기준: UPDATE·INSERT VALUES·INSERT SELECT·MERGE의 정확 결과와 반복 적용 동일성을 검증한다. 함수 인자는 기존 인라인 콤마를 유지한다. MERGE 내부 UPDATE·INSERT는 바깥 MERGE 기준 열을 유지한다.
- 명확화 질문 0개: MERGE도 첫 단어 마지막 글자를 기준으로 한다는 동일 원칙을 적용한다.

## 추가 편집 보호 요구

- FR-011: 주석만 있는 줄은 원래 들여쓰기·앞뒤 공백을 보존한다. 인라인 주석 내용도 유지한다.
- FR-012: SQL 선택 영역이 있으면 그 범위만 포맷하고 없으면 현재 쿼리 전체를 포맷한다. 선택 밖의 문자열은 정확히 보존하며 단일 Undo/Redo를 유지한다.
- 명확화: 주석 라인은 SQL 없이 주석만 있는 물리적 줄을 의미한다. 선택 포맷은 선택한 텍스트 자체를 포맷하며 선택 밖 구문을 재작성하지 않는다.

## 정확 배치 보완

- FR-013: SELECT 목록의 서브쿼리는 여는 괄호 다음 줄에서 괄호 열+4에 SELECT를 놓고 닫는 괄호는 여는 괄호 열에 놓는다.
- FR-014: INSERT INTO 헤더는 한 줄이다. 컬럼과 값은 괄호 다음 줄 6칸, 콤마는 4칸이며 닫는 괄호는 시작 열이다. 일반 INSERT는 닫는 컬럼 괄호와 VALUES를 같은 줄에 둔다.
- FR-015: MERGE INTO·USING 및 ON·WHEN MATCHED THEN·WHEN NOT MATCHED THEN을 사용자 예제대로 배치한다. 내부 INSERT와 VALUES의 괄호는 각각 예제대로 별도 줄을 사용한다. 이전 MERGE 앞 한 칸 규칙과 INSERT 배치는 이 요구로 대체한다.
- 명확화 질문 0개. 최신 사용자 예제를 정확 결과로 적용하고 기존 주석·선택 범위 보호를 유지한다.

## PIVOT·UNPIVOT 요구

- FR-016: 사용자 PIVOT 예제의 서브쿼리·별칭·PIVOT 본문·FOR IN 목록을 정확히 배치한다. 원문 토큰과 순서는 유지하고 빠진 구분자를 추가하지 않는다.
- FR-017: UNPIVOT도 같은 블록·목록 원칙을 사용하며 INCLUDE/EXCLUDE NULLS, 튜플과 인용 값·주석을 보존한다. 함수 인자는 인라인이며 반복 포맷 결과는 같다.
- 명확화 질문 0개. PIVOT 본문은 키워드 시작 열+4, IN 첫 항목은 본문 시작 열+6, 앞쪽 콤마는 항목 두 칸 앞, 닫는 괄호는 각 블록 시작 열이다. 긴 UNPIVOT은 줄 시작에서 시작한다.
