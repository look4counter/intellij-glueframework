# 조사 결과

- 결정: 기존 SqlLexer로 문자열·파라미터·주석을 구분한다. 문맥 자동완성 분석기는 주석을 버리므로 그 출력으로 SQL을 재생성하지 않고 별도 보존 토큰을 사용한다.
- 결정: SELECT 시작 열에 5를 더한 T 열을 기준으로 첫 키워드를 오른쪽 정렬한다. GROUP BY와 ORDER BY는 첫 단어만 맞추고 목록의 후속 콤마는 첫 표현식 두 칸 앞에 둔다. CTE 목록 콤마는 사용자 예제대로 해당 쿼리 시작 열에 둔다.
- 결정: CASE의 분기 키워드는 CASE 시작 열에 맞추고 함수 인자 목록은 인라인으로 유지한다. BETWEEN의 범위 AND는 줄을 나누지 않는다.
- 결정: QueryMapDocumentModel.apply로 Source XML을 변경한다. 근거: 기존 모델은 선택 대상·원본 일치·혼합 본문·쓰기 가능 여부를 검사하고 단일 WriteCommandAction 및 CDATA 처리를 이미 제공한다. SQL 버퍼를 별도 쓰기 명령으로 바꾸면 Undo 중복 위험이 있어 사용하지 않는다.
- 결정: IDE의 ReformatCode 단축키 집합을 SQL 컴포넌트에만 등록한다. SQL 상단 버튼을 함께 제공해 발견 가능성을 확보한다.
- 대안: 자동 저장 때 포맷, XML 전체 재포맷, 외부 범용 스타일 엔진은 사용자 명시적 SQL 스타일과 선택 쿼리 보존에 맞지 않아 채택하지 않는다.
- 미해결 기술 질문과 새 의존성 없음.
