# 설계 조사

- 결정: 첫 패닝 시 화면 주변까지 한 번 캡처한다. 기존 미니맵 이미지 처리 방식을 참고한다.
- 근거: 이동 중 도형·텍스트 재렌더링을 제거한다. 화면 전체 모델 캡처는 메모리 비용으로 제외한다.
- 대안: 이벤트마다 재생성은 목적과 충돌한다. 영역 밖은 기존 벡터 렌더링으로 보충한다.
- 무효화: 모델·외형·폰트·확대율·화면 크기 변경 시 정상 렌더링으로 복귀한다.
- 검증 중 확인: 미니맵이 화면 영역을 포함해 축척을 변경하면 전체 모델을 다시 그린다. 패닝 중에는 미니맵 배경의 투영을 고정하고 현재 화면 사각형만 갱신한다. 종료 후 자동 맞춤으로 복귀한다.
- 실제 픽셀 재현 결과: 기본 배율에서 내부 원의 가로 중심은 약 29.995, 외부 윤곽은 30.513이었다. 외부 윤곽이 오른쪽 아래로 정규화되어 내부가 상대적으로 왼쪽 위에 보인다. 종료 상태만 순수 윤곽 좌표로 그린다.

## 상태 조회 비용 조사

- 결정: 서비스 편집본의 변경 강조 결과를 수정 시각과 객체 식별자로 캐시한다.
- 근거: hasPendingChanges는 changeHighlights에서 전체 XML 파싱과 노드·연결 비교를 수행하며 isModified와 Commit/Rollback 상태 조회가 반복 호출한다. 모델이 불변인 패닝 중에도 이 비용이 발생한다.
- 대안: 드래그 중 변경 여부를 무조건 거짓으로 반환하면 저장 상태가 부정확해진다. 내용 변경에 따라 무효화하는 캐시로 정확성을 유지한다.
- 클립보드: isPasteEnabled의 드래그 검사만으로는 별도 isPastePossible 호출을 막지 못한다. 가능 여부 진입점에도 동일한 검사를 둔다.
- 실제 IDE 프로파일 없이 이 경로를 유일한 원인으로 단정하지 않는다.

## 미니맵 위치 동기화 조사

결정: 현재 투영은 자동 맞춤하고 시작 투영의 배경 이미지를 변환해 재사용한다. 근거: 표시가 콘텐츠를 가득 채우면 경계 제한으로 이동량이 사라진다. 대안인 매 프레임 전체 미니맵 렌더링은 성능 목표와 충돌한다. 기존 고정 투영 결정을 대체한다.
첫 수정 검증에서 자동 맞춤만으로는 작은 이동의 화면 사각형이 고정될 수 있음을 확인했다. 시작 전체 범위를 두 배로 확장하여 이동 여유를 확보하고 그 밖의 이동에는 자동 맞춤을 적용한다.
배율 유지 결정: 고정 투영에서 화면 사각형 전체의 위치를 제한하면 표시가 멈춘다. 각 경계를 별도로 제한해 교집합을 표시하면 고정 배율에서도 이동이 보인다. 범위를 넓혀 축소하는 방식은 사용자 요청에 따라 폐기한다.
균등 여백·요소 이동 결정: 위쪽 24픽셀은 제목이 없는 현재 미니맵에서 불필요하므로 8픽셀로 통일한다. 패닝 표시 중심을 시작·현재 화면 중심의 중간으로 따라가게 하면 고정 배율에서 요소와 화면 표시가 모두 움직이며 정확한 상대 거리를 유지한다. 화면 중심을 완전히 따라가면 파란 표시가 정지하므로 제외한다. 캐시 배경은 평행 이동으로 재사용한다.
자동 배율 결정: 현재 표시 중심에 대해 모델·화면 합집합의 좌우·상하 최대 거리를 사용하면 요소와 화면 표시가 함께 이동하면서 전체 범위를 맞출 수 있다. 시작 여백을 늘리는 방식은 재도입하지 않는다. 배경은 배율 비율과 평행 이동으로 재사용하고 메인 캔버스 줌은 변경하지 않는다.
