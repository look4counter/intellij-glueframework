# 기능 명세: SQL 컬럼 TRACE

작성일: 2026-11-07
상태: 명확화 완료
입력: 커서의 컬럼이 CTE와 SELECT 별표를 거쳐 전달된 경로를 우측 하단 줄 목록으로 보여주고 클릭하면 해당 SQL 줄로 이동한다.

## 사용자 시나리오와 검증

### 사용자 이야기 1: 컬럼 경로 확인 (P1)

어느 단계의 SS에 커서를 놓아도 TB_MAST의 SELECT SS, TB_SUB의 SELECT *, 최종 SELECT SS가 원본부터 끝까지 보인다. SQL 편집기 기준 실제 줄 번호와 줄 내용을 표시한다. 독립 검증은 원본·중간·최종 위치 각각에서 사용자 예제의 2·6·9행과 각 내용의 일치다.

### 사용자 이야기 2: 경로 이동과 갱신 (P1)

우측 하단 TRACE 목록을 클릭하거나 Enter로 실행하면 해당 위치로 커서와 화면이 이동한다. 목록으로 이동하는 동안 기존 경로를 유지해 다른 단계도 클릭할 수 있다. 일반 커서 이동, SQL 수정, 쿼리 전환에는 새 내용을 반영한다.

### 경계 조건

별칭·CTE 명시 컬럼·파생 쿼리·다단계 별표를 추적한다. 표현식은 참조 컬럼별 경로를 함께 표시한다. 중복 출처, 순환, 미지원 입력은 확인 가능한 경로만 제공하며 추정 결과를 확정 경로로 위장하지 않는다. 문자열·주석·다른 문장과 무관한 컬럼에서는 경로를 노출하지 않는다.

## 요구사항

- FR-001: 커서 식별자의 현재 문장과 범위를 분석해 CTE·파생 쿼리의 출력 컬럼 및 별표 전달을 추적한다.
- FR-002: 실제 SQL의 1부터 시작하는 줄 번호·줄 내용과 이동 위치를 원본 → 최종 사용처 순서로 제공하고 같은 위치는 중복 표시하지 않는다.
- FR-003: 우측 속성 패널 하단에 제목 라벨 없이 경로 목록과 고정된 빈 상태 안내를 제공한다.
- FR-004: 클릭·Enter로 해당 SQL 위치에 이동하고 화면을 스크롤하며 SQL·Source·Undo 기록을 수정하지 않는다.
- FR-005: 커서·문서·선택 쿼리 변경 시 갱신하고, 오래된 분석 결과나 이동 요청을 버리며 편집기 종료 후 작업을 중단한다.
- FR-006: DB 조회 없이 기존 캐시와 SQL만 읽는다. 분석 길이 262,144자·토큰 20,000개·깊이 48 제한을 유지하고 UI 밖에서 분석한다.
- FR-007: 별칭, 명시적 출력 컬럼, 표현식, 재귀·모호함·불완전 입력·문장 격리와 UI 이동·갱신을 자동 검증하고 사용 방법을 기록한다.
- FR-008: 커서 위치는 추적 대상 컬럼을 선택하는 기준으로만 사용한다. 같은 문장 안에서 해당 컬럼의 상위 출처·하위 사용처·분기 전체를 보여준다. 같은 이름이어도 다른 출처인 컬럼과 별표의 다른 출력 슬롯은 섞지 않는다. 컬럼 이름 변경과 표현식 변환은 실제 연결 관계를 따른다.
- FR-009: TRACE는 SELECT 출력과 CTE·파생 테이블을 통한 데이터 전달 경로만 표시한다. WHERE·ON·HAVING·GROUP BY·ORDER BY의 사용 위치와 필터 조건 안의 서브쿼리는 경로에서 제외한다. 해당 절에서 컬럼을 선택하더라도 그 컬럼의 SELECT 전달 경로만 보여주며 조건절 자체는 표시하지 않는다. SELECT 표현식의 CASE·계산식 입력 컬럼은 출력 값의 출처로 계속 추적한다.
- FR-010: TRACE 목록 아래 상태 문구를 제거한다. 목록이 비어 있으면 초기·분석 중·출처 불명 등 모든 상태에서 `추적할 컬럼에 커서를 놓으세요.`만 표시하고 목록 영역의 세로 가운데에 배치한다. 경로가 있으면 안내 문구를 표시하지 않는다. 내부 분석 결과와 기존 항목 이동·갱신·수명 보호는 유지한다.
- FR-011: TRACE의 각 항목에 쿼리 목록과 동일한 좌우 여백을 적용한다. 기본 선택·포커스 표시와 빈 상태 안내·항목 이동은 유지한다.

## 주요 개체

- 추적 항목: 줄 번호, 줄 내용, 컬럼 이동 오프셋.
- 추적 결과: 원본부터 정렬된 항목과 불확실성 설명.
- 분석 요청: SQL 스냅샷, 커서, 문서 식별자와 변경 세대.

## 성공 기준

- SC-001: 사용자 예제의 원본·중간·최종 SS 각각에서 2·6·9행 전체가 표시되고 각 항목 이동 검증이 통과한다.
- SC-002: 문서 수정·쿼리 전환 후 과거 줄로 이동하지 않으며 탐색은 문서를 변경하지 않는다.
- SC-003: 전체 회귀 테스트와 설치 ZIP 구조 검사를 통과한다.

## 가정과 명확화

질문 0개. 사용자 예제는 필드 목록이 아니라 전달 단계 목록이며 SQL 편집기의 줄 번호를 사용한다. 자동 갱신과 기존 경로를 유지하는 목록 탐색을 기본으로 한다. 실제 테이블의 물리적 정의 위치는 현재 SQL 밖이므로 표시하지 않는다. DB별 전체 문법과 서버 실행 계획은 범위 밖이다.

후속 명확화 질문 0개. 처음부터 끝까지는 현재 문장 내 선택 컬럼과 실제로 연결된 전체 전달 경로이며 다른 SQL 문장까지 이름 검색으로 확장하지 않는다. 여러 입력으로 계산된 출력 컬럼은 그 입력과 연결된 사용처를 함께 보여준다. 우측 하단 TRACE 제목만 제거하고 접근성 이름과 목록 탐색은 유지한다.

출처 목적 보완의 명확화 질문 0개. 전체 사용처는 SELECT 출력으로 전달되는 사용처를 뜻하며 필터·조인·그룹·정렬의 단순 참조는 포함하지 않는다. 기존 커서의 대상 컬럼 선택 기능은 유지하며 출력 경로가 없는 컬럼은 빈 목록으로 표시한다. 조건 서브쿼리의 SELECT도 상위 결과로 컬럼을 전달하는 단계가 아니므로 제외한다.

안내 표시 보완의 명확화 질문 0개. 하단 상태 라벨은 제거하며 빈 상태의 목록 내부 안내만 남긴다. 가로 정렬은 기존 가운데 정렬을 사용하고 세로 위치도 가운데로 변경한다. 분석 오류 메시지는 화면과 툴팁에 노출하지 않는다.

패딩 보완의 명확화 질문 0개. 기존 쿼리 목록의 항목 렌더러와 동일하게 좌우 각각 8 논리 픽셀의 여백을 사용하며 IDE 배율을 따른다.
