# 기능 명세: Activity 추가 스레드 오류 수정 및 Snap 적용

**작성일**: 2026-11-04
**상태**: 명세 검증 완료
**입력**: Activity 추가 클릭 시 쓰기 스레드 오류를 해결하고 추가할 때도 Snap이 동작하게 한다.

## 사용자 시나리오 및 검증

### 사용자 이야기 1: 오류 없는 추가 (우선순위: P1)

사용자는 빈 Activity와 프리셋을 클릭 또는 드래그로 추가한다. 독립 검증은 쓰기 권한 없는 UI 입력에서 추가 후 노드 개수와 실행 취소를 확인한다.

1. 쓰기 스레드 권한 없는 입력에서도 오류 없이 노드 하나가 추가된다.
2. 예약된 추가 전에 취소하거나 추가 종류·프리셋을 바꾸면 이전 요청은 반영되지 않는다.
3. 편집기 폐기·읽기 전용·오류 문서에서는 추가하지 않는다.

### 사용자 이야기 2: 추가 위치 Snap (우선순위: P1)

사용자는 기존 도형 이동과 같은 정렬 및 간격 규칙으로 새 Activity를 배치한다. 독립 검증은 Ghost 좌표와 추가된 좌표를 비교한다.

1. Snap 활성화 상태에서 기존 노드의 모서리·중심·동일 간격에 가까워지면 Ghost가 맞춰지고 안내선이 표시된다.
2. 클릭과 드래그 놓기 모두 Ghost와 같은 위치에 노드를 추가한다.
3. Snap 비활성화 또는 Alt 입력에서는 원래 마우스 위치를 사용한다.
4. 확대·축소, 음수 좌표, 프리셋에서도 같은 모델 좌표 규칙을 적용한다.

### 경계 조건

- Ghost 이동 자체는 원문을 바꾸지 않으며 추가는 한 번의 실행 취소로 복원한다.
- 안내선은 이동·영역 이탈·모드 취소 때 잔상이 남지 않는다.
- 미니맵과 캔버스 외부 놓기 및 중복 클릭 방지를 유지한다.
- 기존 Ghost 부분 갱신 최적화를 유지하고 정렬 계산을 화면 그리기마다 반복하지 않는다.

## 요구사항

- **FR-001**: 추가를 수행하기 전에 안전한 쓰기 스레드 및 실행 문맥을 확보한다.
- **FR-002**: 예약된 요청의 모드 세대·편집 가능 상태·수명을 다시 검사한다.
- **FR-003**: 추가 Ghost와 확정 위치에 기존 Snap 정렬·간격 규칙을 동일하게 적용한다.
- **FR-004**: Snap 설정 및 Alt 우회를 존중하고 안내선을 정리한다.
- **FR-005**: 원문 형식, 실행 취소, 읽기 전용 보호 및 부분 화면 갱신 동작을 보존한다.

### 주요 개체

- 추가 요청: 종류, 좌표, 프리셋, 모드 세대, 입력 식별자.
- 추가 미리보기: 원래 마우스 위치, 보정 위치, 정렬 안내선, Alt 우회 여부.

## 성공 기준

- **SC-001**: 쓰기 권한 없는 UI 입력의 클릭·놓기 추가 및 취소·폐기·실행 취소 자동 검증이 통과한다.
- **SC-002**: Snap 켜기·끄기·Alt·정렬·동일 간격·확대·축소 검증에서 Ghost와 실제 추가 좌표가 일치한다.
- **SC-003**: 기존 모델 편집 및 Ghost 부분 갱신 회귀 검증이 통과한다.

## 가정 및 명확성 검토

2026-11-04: 질문 0개. Snap은 기존 도형 이동과 같은 5 모델 좌표 단위 허용 범위의 정렬·간격 규칙을 의미한다. 빈 Activity와 프리셋에 공통 적용하며 다른 child 종류도 같은 입력 경로를 사용한다. 중대한 모호성 없음.
