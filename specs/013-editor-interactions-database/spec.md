# 기능 명세: 편집기 조작과 DB 연결 개선

**작성일**: 2026-10-27
**상태**: 명확화 완료
**입력**: Child 이동·크기 조절·Wire 드래그 임계치, SQL 괄호 짝 강조, Oracle 메타데이터 최적화, DB 연결 테스트 버튼을 추가한다.

## 사용자 시나리오와 검증

### 사용자 이야기 1 — 클릭과 드래그 구분 (우선순위: P1)

사용자는 작은 손떨림으로 도형이 변형되지 않게 하고 더블클릭 편집을 안정적으로 사용한다.
**독립 검증**: Child 이동·양쪽 크기 조절·Wire 끝점·꺾임점에서 임계치 미만/초과 마우스 이벤트를 전달한다.

1. 임계치 미만에서는 미리보기·저장·드래그 시작이 발생하지 않고 더블클릭 편집이 가능하다.
2. 임계치 이상 움직이면 원래 누른 위치 기준으로 드래그하고 놓을 때 한 번 확정한다.
3. 드래그 이후 같은 제스처의 더블클릭 이벤트는 편집 창을 열지 않는다. 새 클릭은 정상 처리한다.
4. 확대·축소와 무관하게 화면상 임계치가 같고 취소·읽기 전용·실행 취소 동작을 유지한다.

### 사용자 이야기 2 — SQL 괄호 짝 확인 (우선순위: P2)

사용자는 SQL 괄호에 커서를 두고 대응 위치를 확인한다.
**독립 검증**: 중첩 괄호의 양쪽, 커서 이동·문서 변경, 문자열·주석·불일치를 검사한다.

1. 소괄호 및 대괄호·중괄호의 앞이나 바로 뒤에 커서가 있으면 짝을 강조한다.
2. 문자열·주석 안의 괄호는 제외하고 중첩 구조를 따른다.
3. 짝이 없거나 잘못 중첩되면 잘못된 위치를 짝으로 표시하지 않는다. 이동·문서 변경 후 갱신한다.
4. 쿼리 전환·에디터 폐기 후 강조가 남지 않는다.

### 사용자 이야기 3 — Oracle 메타데이터 수집 개선 (우선순위: P1)

사용자는 접근 가능한 Oracle 테이블·뷰·컬럼을 적은 조회 횟수로 수집한다.
**독립 검증**: 가짜 JDBC 연결로 여러 스키마의 테이블·뷰와 컬럼을 반환하여 결과와 쿼리 수를 검사한다.

1. Oracle은 ALL_TABLES 기반으로 테이블을 조회하고 기존 뷰 지원을 유지한다.
2. 컬럼을 일괄 수집하여 테이블 수에 비례한 개별 조회를 없앤다.
3. 스키마가 다른 동명 테이블을 구분하며 컬럼 순서를 보존한다.
4. 취소·오류 시 자원을 닫고 기존 캐시를 성공 결과로 덮어쓰지 않는다. 다른 DB의 기존 경로는 유지한다.

### 사용자 이야기 4 — 저장 전 연결 테스트 (우선순위: P1)

사용자는 GlueQueryEditor 설정에서 현재 입력 정보로 DB 연결 가능 여부를 확인한다.
**독립 검증**: 저장 전 입력·비밀번호 우선순위·성공·실패·취소와 메타데이터 미수집을 검사한다.

1. 선택한 DataSource의 연결 테스트 버튼으로 미적용 접속 정보를 확인하고 성공·실패를 표시한다.
2. 새 비밀번호 입력을 우선하고, 삭제가 선택되면 저장 비밀번호를 사용하지 않으며, 그 외에는 저장 비밀번호를 사용한다.
3. 연결만 확인하고 메타데이터 수집이나 설정·비밀번호 저장은 하지 않는다.
4. 접속 작업은 화면을 멈추지 않고 취소 가능해야 한다. 비밀번호를 결과에 노출하지 않는다.

## 요구사항

- **FR-001**: Child 이동·크기 조절·Wire 편집은 화면 거리 임계치를 넘긴 뒤 시작해야 한다.
- **FR-002**: 활성 드래그는 더블클릭과 중복 처리하지 않고 작은 움직임에서는 클릭을 유지해야 한다.
- **FR-003**: SQL 커서 인접 괄호와 대응 괄호를 문법 영역을 구분하여 강조하고 수명에 맞게 정리해야 한다.
- **FR-004**: Oracle 메타데이터는 테이블·뷰와 컬럼을 고정 횟수의 일괄 조회로 수집해야 한다.
- **FR-005**: 다른 DB의 동작과 메타데이터 취소·실패 보호를 유지해야 한다.
- **FR-006**: 연결 테스트는 현재 입력과 비밀번호 정책을 사용하여 접속만 확인하고 결과를 표시해야 한다.
- **FR-007**: 연결 테스트는 취소 가능하며 UI 응답성과 자원 해제를 보장하고 비밀번호를 노출하지 않아야 한다.

### 주요 개체

드래그 후보와 활성 드래그, SQL 괄호 쌍, 스키마별 메타데이터, 미적용 접속 정보 및 테스트 결과를 다룬다. 영속 설정 구조는 바꾸지 않는다.

## 성공 기준

- **SC-001**: 모든 지정 드래그 유형의 임계치 미만/이상과 더블클릭 회귀가 통과한다.
- **SC-002**: 중첩·주석·문자열·불일치·갱신·폐기를 포함한 괄호 강조 회귀가 통과한다.
- **SC-003**: Oracle의 테이블 수가 증가해도 메타데이터 SQL 실행은 2회 이내이며 결과에서 기존 테이블·뷰·컬럼을 유지한다.
- **SC-004**: 연결 테스트 성공·실패·취소·미저장 입력·비밀번호 정책 회귀가 통과한다.

## 가정과 명확화

임계치는 운영체제의 드래그 기준을 사용하고 별도 설정 항목은 추가하지 않는다. Oracle은 기존 접근 범위를 좁히지 않고 접근 가능한 전체 스키마와 뷰를 유지한다. SQL 디자인 탭의 내장 SQL 에디터에 적용한다. 연결 테스트는 현재 선택한 DataSource 하나에 대해 수행한다. 대화의 연속 요청에 따른 범위·동작·검증·실패 정책을 검토했으며 추가 질문이 필요한 중대한 모호함은 없다. 각 사용자 이야기에 자동 회귀 테스트를 추가한다.
