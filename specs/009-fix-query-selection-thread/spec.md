# 기능 명세: Query 목록 전환의 쓰기 스레드 오류 수정

**작성일**: 2026-10-26
**상태**: 명세 검토 완료
**입력**: queryeditor 쿼리 목록에서 다른 Query를 선택하면 Access is allowed from write thread only 오류가 발생한다.

## 사용자 시나리오 및 검증

### 사용자 이야기 1: 목록에서 Query 전환 (우선순위: P1)

사용자는 목록에서 다른 Query를 선택하여 해당 ID·설명·ResultType·SQL을 확인하고 편집한다. 기본 전환이 차단되므로 최우선 수정한다. 실제 목록 선택 이벤트로 독립 검증한다.

1. 변경이 없는 상태에서 다른 Query를 선택하면 오류 없이 해당 내용을 표시한다.
2. 설명·SQL 편집이 대기 중이어도 이전 Query에만 반영하고 선택한 Query를 표시한다.
3. 빠른 연속 선택은 최종 선택을 유지한다.

### 경계 조건

- 쓰기 잠금 또는 쓰기 안전 문맥이 없는 UI 이벤트에서도 전환한다.
- 편집기 폐기 뒤 예약된 선택은 무시한다.
- 기존에 예약된 자동 갱신 때문에 선택이 이전 Query로 돌아가지 않는다.
- 읽기 전용·실행 취소·문서 저장 및 SQL 편집 동작을 보존한다.

## 요구사항

### 기능 요구사항

- **FR-001**: 다른 Query 선택은 보고된 쓰기 스레드 오류 없이 동작해야 한다.
- **FR-002**: 대기 중인 편집은 원래 Query에 반영하고 새 선택의 내용은 보존해야 한다.
- **FR-003**: 연속 선택의 최종 대상을 유지하고 폐기된 편집기는 예약 전환을 실행하지 않아야 한다.
- **FR-004**: 기존 저장·실행 취소·읽기 전용·SQL 편집 동작을 보존해야 한다.

### 주요 개체

- Query: 기존 XML 대상과 속성·SQL을 유지한다.
- 선택 요청: 선택 이벤트 시점의 Query 대상을 기억하며 새 선택으로 대체될 수 있다.

## 성공 기준

- **SC-001**: 잠금 없는 선택·대기 편집·연속 선택·폐기 회귀 검증이 모두 통과한다.
- **SC-002**: 기존 QueryDesignEditorTest와 QuerySqlEditorTest가 모두 통과한다.

## 가정

- 목록 선택 경로의 오류 수정이며 외부 탐색 기능 추가나 저장 형식 변경은 없다.
- 자동 회귀 검증을 추가한다.
