# 조사 결과

## 결정과 근거

- 미니맵은 모델 범위·화면 투영·배경 모델 이미지·뷰포트 표시를 분리한다. 현재 getter는 모든 점과 라벨을 매번 생성하며 drawMiniMap은 전체를 다시 그린다.
- 클립과 요소 경계로 그리기를 줄인다. 현재 본 화면은 모든 경로와 도형을 순회하며 도형 텍스트도 매번 측정한다. 화면 밖 요소를 숨기되 선분이 화면을 통과하거나 라벨만 들어오는 경우를 보존한다.
- 이동 원본과 연결 인덱스를 제스처 동안 재사용한다. 현재 previewChildDrag는 전체 노드 맵을 만들고 모든 Wire에 relocateNodes를 적용하며 replaceDiagram은 모든 경로를 재계산한다.
- 좌표별 개수와 변경 영역으로 범위 및 미니맵을 부분 갱신한다. 정렬 맵의 양끝으로 전체 범위를 얻으면 드래그 중 전체 노드 재탐색이 필요 없다.

## 고려한 대안

미니맵 제거·텍스트 생략은 승인된 기능을 줄이므로 제외한다. 계산을 무조건 다른 스레드로 옮기면 Swing 상태 동기화와 오래된 결과 적용 문제가 생겨 제외한다. 타이머로 프레임 수만 제한하면 불필요한 계산 자체는 남으므로 이번 작업의 중심으로 삼지 않는다. 본 화면의 공간 분할 트리는 경계 필터링 이후에도 순회 비용이 남는 경우에 별도로 고려한다.

기술 미확정 항목은 없다. 기존 프로젝트의 렌더링·geometry·설정 구독과 테스트만으로 설계가 가능하다.

- 대안: 드래그 중 그래픽 품질 저하나 주기 제한은 시각 품질·입력 계약에 영향을 주므로 채택하지 않는다.
