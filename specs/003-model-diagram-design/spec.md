# 기능 명세: 모델 다이어그램 표시

작성일: 2026-10-23

## 사용자 시나리오 및 검증

### 사용자 이야기 1: 노드 표시 (P1)

사용자가 glue_uml_ad 파일의 Design 탭을 열면 XML의 좌표대로 Activity와 시작·종료 State를 본다. Activity는 XML 너비, 높이 30, 모서리 반경 8로 표시한다. State는 20×20이며 시작은 검정 채움, 종료는 외곽 원 안에 채운 원으로 표시한다. Activity 이름을 표시한다.

독립 검증: 샘플의 노드 8개와 각 도형의 크기·위치를 확인한다.

### 사용자 이야기 2: 연결선 표시 (P1)

사용자는 XML 선언 순서로 연결된 선과 꺾임점을 본다. wire ID 대신 0부터 시작하는 순서와 child의 input/output 참조를 사용한다. 양 끝 노드가 모두 있을 때만 그린다.

독립 검증: 샘플의 연결선 12개, 분기 조건, 꺾임점을 확인한다.

### 사용자 이야기 3: Source 변경 반영 (P2)

Source의 미저장 변경도 Design에 반영한다. 표시·선택·탐색은 원문을 변경하지 않으며 Child 이동은 해당 location만 갱신한다. 잘못된 XML에는 안내를 표시하고 Source는 계속 사용할 수 있다.

## 기능 요구사항

- FR-001: Activity 높이 30, XML 너비, 반경 8과 State 20×20 도형을 XML location에 그린다.
- FR-002: wire 선언 순서와 child input/output의 인덱스로 방향을 결정하며 어느 한쪽이 없으면 생략한다.
- FR-003: State끼리도 반경 10 원 외곽을 연결한다. State와 Activity 연결의 State 쪽은 반지름 10 원둘레로 보정한다. State x가 Activity 범위에 있으면 위·아래 변으로 수직 연결한다. x가 밖이고 y가 Activity 세로 범위 안이면 좌·우 변의 y를 8px 여백으로 제한한다. 나머지는 사분면의 안쪽 8px 모서리점을 반지름 9로 보정한다.
- FR-004: 꺾임점이 없는 Activity끼리는 좌우 8px를 제외한 가로 범위가 겹치면 firstRelativePoint.x를 겹침 구간으로 제한하여 수직 연결한다. y는 두 Activity의 가장 가까운 위·아래 변을 사용한다. 가로 유효 겹침이 없고 위아래 8px를 제외한 세로 범위가 겹치면 firstRelativePoint.y를 제한하여 수평 연결하며 x는 가장 가까운 좌·우 변이다. 둘 다 아니면 마주보는 가장 가까운 둥근 모서리의 안쪽 8px 점을 반지름 9로 보정해 대각선으로 연결한다.
- FR-005: 꺾임점 i는 시작 중심+firstDimension과 종료 중심+secondDimension을 (i+1)/(n+1)로 보간한다. 처음·마지막 선분만 노드 종류별 보정을 적용하고 중간은 단순 선분이다. weight는 보관하되 그리기에 사용하지 않는다.
- FR-006: Source 변경 시 다시 표시하며 단순 표시는 XML을 재작성하지 않는다. Child 이동은 해당 location만 갱신한다. 잘못된 XML과 누락 참조를 안전하게 처리하고 스크롤로 전체 도형을 볼 수 있다.

## 주요 엔터티

노드: 종류, 식별자, 이름, 위치, 크기, input/output 참조. 연결선: 선언 인덱스, ID, 분기 조건, 양 끝 노드, 상대점, 꺾임점 목록. 꺾임점: 두 상대 벡터와 보관용 weight.

## 경계 조건과 가정

지원하지 않는 child는 생략한다. 양수 너비가 없는 Activity는 기본 너비 100을 사용한다. 좌표가 없으면 0으로 처리한다. 빈 파일은 안내를 표시한다. Child 이동은 location만 편집하므로 weight 및 알 수 없는 속성도 유지한다. XML 외부 엔터티를 불러오지 않는다. 화살표와 분기 조건 이름을 표시한다. 빈 공간 좌측 드래그는 범위 선택이며 우측 드래그는 화면 탐색이다.

## 성공 기준

- SC-001: 샘플의 노드 8개와 유효한 연결선 12개를 표시한다.
- SC-002: 종류별 연결과 다중 꺾임점 좌표 검증을 통과한다.
- SC-003: Design 전환 및 표시 후 원문이 동일하고 Source 변경을 반영한다.

## 명확화

사용자 확인: State↔Activity에서는 State 쪽도 반지름 10 원둘레로 보정한다. State↔State도 후속 FR-085에 따라 원 외곽 접속으로 변경한다. 꺾임점은 면적 없는 상대점으로 취급하여 인접 Activity 및 혼합 연결의 State 끝점을 보정한다. 나머지 규칙은 사용자 입력 그대로 적용한다.

## 표시 및 탐색 개선

### 사용자 이야기 4: 기본 색상과 중앙 라벨 (P1)

- FR-007: 캔버스와 조건 라벨 배경은 IDE 기본 패널 배경색을 사용한다. Wire와 화살표 및 조건 글자는 GRAY_145(RGB 145,145,145)로 그린다. Activity 기본 채움은 흰색이며 InitialState 검정 채움은 유지한다.
- FR-008: 조건 라벨은 실제 글자 폭과 글꼴 높이에서 3px 줄인 높이만큼 배경을 칠하고 중심을 선택 선분의 중점에 맞춘다. 글자는 세로 가운데 정렬한다. 꺾임점이 n개면 0부터 세는 floor(n/2)번 선분을 선택한다. 꺾임점이 없으면 유일한 선분을 사용한다.
- FR-009: FinalState 안쪽 검정 원은 지름 15이며 외곽 원 기준 오프셋 (3,3)을 유지한다. 외곽 원에는 흰색 채움을 하지 않는다.

독립 검증: 직선 및 꺾임점 1~4개의 라벨 중심과 배경·글자색, 밝은/어두운 배경, 최종 원 크기를 확인한다.

### 사용자 이야기 5: 빈 공간 드래그 탐색 (P1)

- FR-010: 마우스 오른쪽 버튼으로 어디에서든 드래그하면 드래그 거리만큼 전체 다이어그램을 이동한다. 이동 중 커서를 표시하고 버튼을 놓으면 종료한다. 노드 좌표와 XML 및 선택은 변경하지 않는다.

독립 검증: 빈 공간과 노드·선 위에서 시작한 우측 드래그로 표시 위치가 이동한다. Source 갱신 후에도 탐색 위치와 XML은 유지한다.

명확화: n은 꺾임점 수이며 선분 인덱스는 0부터 계산한다. 안쪽 원은 지름 12에서 16으로 키운다. 탐색은 화면 이동만 수행한다.

### 사용자 이야기 6: Child 선택 (P1)

- FR-011: Child의 글자는 GRAY_145를 사용한다.
- FR-012: 빈 공간의 좌측 드래그는 범위 Box를 표시하고 Child의 경계 사각형 네 모서리가 모두 들어온 경우에만 선택한다. 드래그 방향과 관계없이 동작하고 좌측 드래그는 화면을 이동하지 않는다.
- FR-013: 선택되지 않은 Child 좌측 Down은 단독 선택한다. 이미 선택된 Child를 누르면 다중 선택을 유지하고 해당 Child를 마지막 선택 대상으로 만든다. Shift+좌측 Down은 이전 선택을 유지하고 해당 Child를 추가한다.
- FR-014: 선택된 Child 경계의 모서리와 변 중앙 8곳에 6×6 흰색 핸들과 외곽선을 표시한다. 마지막 선택 Child는 핸들 중앙에 4×4 검정을 추가한다. 그 외 Child 핸들은 검정 테두리를 그린다. 좌우 변 중앙 핸들은 Activity 너비 조절을 지원하며 그 외 핸들은 표시용이다.

독립 검증: 부분 교차한 Child는 선택되지 않으며 완전히 포함된 State·Activity만 선택된다. 클릭 시 즉시 선택되고 Shift 추가 선택 및 마지막 선택 표시가 일치한다. 화면 이동 이후에도 같은 위치 변환으로 선택한다. XML은 유지한다.

추가 명확화: 빈 공간 일반 클릭은 선택을 해제한다. Shift 범위 선택은 기존 선택을 유지한다. 범위 선택의 마지막 Child는 XML 순서상 마지막으로 포함된 Child다. 우측 드래그는 선택을 바꾸지 않는다.

### 사용자 이야기 7: Wire 선택과 Child 이동 (P1)

- FR-015: 조건 배경은 기존 위쪽 위치와 폭을 유지하고 아래쪽에 1px를 더 칠한다. 조건 글자는 최초 세로 가운데 기준선보다 2px 위에 그린다. 배경 확장으로 글자의 기준선은 움직이지 않는다.
- FR-016: 선분에서 4px 이내 또는 조건 라벨 배경에 좌측 Down하면 Wire를 선택한다. 마지막 선택 요소가 앞에 있으면 해당 요소의 Hit를 우선한다. 그 외 겹침은 Child가 우선이다. Wire 선택은 Child 선택을 해제하며 Child 선택도 Wire 선택을 해제한다.
- FR-017: 선택 Wire의 시작·끝·꺾임점은 6×6 흰색 내부 4×4 검정 핸들로 표시한다. 모든 인접 경로점 사이 중점에는 4×4 흰색 내부 2×2 검정 핸들을 표시한다. 저장된 ID가 아닌 선언 순서로 선택을 유지한다. 시작·끝 핸들은 재연결 드래그, 꺾임점은 이동, 중점은 꺾임점 삽입을 지원한다.
- FR-018: Child 좌측 드래그는 이동 미리보기를 제공하고 버튼을 놓을 때 XML location을 한 번의 실행 취소 가능한 편집으로 갱신한다. 연결선과 선택 표시도 갱신한다. 화면 탐색 이동량은 바뀌지 않는다. 읽기 전용 파일은 이동하지 않는다.

독립 검증: 선의 4px/5px 거리와 라벨 클릭, 화면 이동 후 선택, 끝점·꺾임점 핸들 크기, Child 이동의 Source·저장·실행 취소 및 읽기 전용 처리를 확인한다.

명확화: 내부 원 이동은 오른쪽·아래쪽 각 1px이다. Shift로 추가 선택한 Child들은 함께 이동한다. 드래그 도중 외부 Source 변경이 발생하면 이동을 취소하고 최신 Source를 표시한다. 이동은 location, 너비 조절은 size 너비 및 필요한 location만 갱신하며 기타 속성과 weight는 유지한다.

### 사용자 이야기 8: 앞쪽 표시와 Activity 너비 조절 (P1)

- FR-019: 마지막 선택 Child 또는 Wire와 그 선택 표시를 다른 다이어그램 요소보다 앞에 그린다. XML 순서는 변경하지 않는다.
- FR-020: 화면 좌측 상단에 Navigation 누적 이동량의 x,y를 GRAY_145로 표시한다. 표시 위치는 화면 이동에 따라 움직이지 않으며 스크롤 시에도 현재 보이는 영역 좌측 상단에 둔다.
- FR-021: 선택된 Activity의 좌·우 변 중앙 핸들을 좌측 드래그하면 너비를 조절한다. 오른쪽 핸들은 왼쪽 변을 고정하고 왼쪽 핸들은 오른쪽 변을 고정한다. 최소 너비는 모서리 반경의 두 배인 16px이며 높이 30은 유지한다. release 시 XML size의 너비만 바꾸고 왼쪽 조절에 필요한 location도 반영한다. 기존 size 높이 값·기타 속성은 유지한다. 한 번의 Undo, 저장, 읽기 전용 차단과 Source 변경 중 취소를 지원한다.

독립 검증: 겹친 요소의 선택 순서별 표시 및 Hit, 선택 Wire의 각 경로점·선분 중점 핸들, Navigation 고정 좌표, 양쪽 너비 조절과 Source·Undo를 확인한다.

추가 명확화: 원의 가로·세로 크기는 각각 16에서 15로 줄인다. guardcondition은 글자만 추가 1px 위로 이동하며 배경은 아래로 1px 확장한다. 좌우 핸들은 각 변의 중앙 핸들을 의미한다.

### 사용자 이야기 9: 안정된 화면과 끝점 드래그 미리보기 (P1)

- FR-022: 선택 Activity 좌·우 중앙 핸들 위에 마우스를 올리면 해당 방향의 resize 커서를 표시한다. 선택 Wire의 모든 경로점·중점 핸들은 move 커서를 표시한다. 빈 공간으로 나가면 기본 커서로 복귀한다.
- FR-023: Child 이동·너비 변경 및 Source 재파싱 시 기존 화면 원점과 Navigation 이동량을 유지한다. 음수 위치로 이동해도 다른 노드의 화면 위치가 바뀌지 않으며 캔버스 크기 축소로 스크롤 위치가 자동 보정되지 않는다. 연결된 Wire 경로는 이동한 Child에 맞게 갱신한다.
- FR-024: 선택 Wire 시작·끝 핸들을 좌측 드래그하면 빈 공간에서는 마우스 위치를 가상 State의 중심으로 삼아 기존 State↔State·Activity↔State·State↔Activity 규칙으로 미리보기한다. 유효한 Child 위에서는 해당 Child를 시작·끝으로 삼는다. 반대 끝과 같은 Child는 연결 대상으로 무시한다. release 시 유효한 Child이면 XML 연결을 갱신하고 빈 공간 또는 반대 끝과 같은 Child이면 드래그 이전 연결·모양으로 원복한다. Navigation은 유지한다.

독립 검증: 4px/5px 선택 경계, 축소 핸들과 커서, 음수 Child 이동·release·Undo 후 다른 노드/Navigation/스크롤 위치 고정, 양쪽 Wire 끝점 드래그 시 마우스 위치 일치를 확인한다.

명확화: 끝점 재연결은 child input/output의 wire 선언 인덱스 참조를 갱신한다. 원래 반대편 노드는 유지한다. Source 변경 중인 드래그는 취소하고 읽기 전용에서는 편집하지 않는다.

### 사용자 이야기 10: 일괄 편집과 Wire 경로 편집 (P1)

- FR-025: 다중 선택 Child를 드래그하면 선택된 모든 Child가 동일한 이동량으로 움직인다. 좌우 너비 조절은 선택된 Activity에 같은 너비 변화량을 적용하고 State는 유지한다. 최소 너비 16에 도달하면 전체 변화량을 제한한다. 각 Activity의 반대 변을 유지한다.
- FR-026: Wire 경로점과 중점 핸들의 마우스 판정 범위는 표시 크기와 무관하게 모두 6×6이다.
- FR-027: 기존 꺾임점 핸들을 드래그하면 이동하며, 해당 점을 제거한 경로의 양옆 점을 잇는 직선에서 5px 이내이면 해당 꺾임점을 제거해 병합한다. 선분 중점의 작은 핸들은 원래 직선에서 5px 초과이면 새 꺾임점을 삽입하고 5px 이내이면 원래 선분으로 합친다. firstDimension과 secondDimension은 원래 노드 중심 기준으로 저장하고 기존 weight는 유지한다. 삽입·삭제 시 다른 꺾임점의 화면 위치를 유지한다.
- FR-028: 일괄 이동·일괄 너비 조절·꺾임점 편집·끝점 재연결은 각각 release마다 한 번의 Undo 가능한 XML 편집으로 저장한다. 다른 속성·wire 순서·weight 및 관련 없는 input/output 참조는 유지한다. 읽기 전용과 Source 동시 변경을 보호한다.

독립 검증: 선택 집합 유지, 혼합 State/Activity 이동과 Activity만 일괄 조절, 6×6 핸들 경계, 기존 꺾임점 이동과 중점 삽입, 양 끝 재연결 및 null/동일 대상 원복, Source·저장·Undo·읽기 전용을 확인한다.

명확화: 작은 중점 핸들은 해당 선분의 꺾임점 생성 핸들로 사용한다. 새 꺾임점 weight 기본값은 0.5다. XML 연결 참조는 ID가 아닌 wire 선언 인덱스를 사용한다.

### 사용자 이야기 11: 가상 State를 이용한 끝점 미리보기 (P1)

- FR-029: 마우스 위치를 20×20 가상 State의 중심으로 사용한다. 반대편이 State이면 양쪽 반경 10 원 외곽을 연결하고 Activity이면 State 반지름 10 및 Activity의 변·모서리 보정을 적용한다. 시작·끝 방향을 대칭으로 처리한다. 가상 State 도형 자체는 표시하거나 XML에 추가하지 않는다.
- FR-030: 끝점이 이동하면 각 꺾임점의 first=start 중심+firstDimension, second=end 중심+secondDimension을 다시 계산하고 bendpoint[i]=first+(second-first)×(i+1)/(n+1)을 적용한다. 미리보기에서도 저장된 상대 벡터를 유지하여 꺾임점이 비율만큼 따라 움직인다. 기존 재연결·잘못된 대상 원복·Navigation·Source 보호 동작은 유지한다.

명확화: 가상 State는 기존 State와 같은 크기와 보정 규칙을 사용한다. 끝점 핸들은 마우스 좌표 자체가 아닌 계산된 앵커에 표시한다. 실제 Child 위에서는 실제 Child를 우선한다.

독립 검증: 양방향 State↔State, 수직·사분면 Activity↔가상 State, 시작·끝 이동에 따른 꺾임점 비례 이동, Navigation 이동 후 미리보기와 유효 연결·잘못된 대상 원복을 확인한다.

명확화: first와 second는 각 꺾임점의 두 기준점이며 모든 i에 동일한 비율을 적용한다. 꺾임점이 하나이면 비율은 1/2이다. 시작 중심 변화량의 (1-t), 끝 중심 변화량의 t만큼 이동하며 weight는 계산하지 않고 보존한다. 중점 삽입 시 기존 꺾임점 위치 보존은 별도 편집 규칙으로 유지한다.

### 사용자 이야기 12: Activity 직결 연결의 대칭 규칙 (P1)

- FR-031: Activity 직결 연결의 수직·수평 유효 범위는 두 도형에서 각각 8px를 제외한 구간의 교집합이다. 유효 구간이 없으면 다음 방향 또는 대각선으로 처리하며 잘못된 범위 clamp를 하지 않는다. 수직을 우선하며 가장자리 간 거리가 같은 경우 기존 중심 방향의 마주보는 변을 우선한다.

명확화: firstRelativePoint를 유효 구간으로 제한하는 기존 좌표 선택과 대각선의 둥근 모서리 보정은 유지한다. 꺾임점이 있는 경로 및 State 연결은 변경하지 않는다.

독립 검증: 위·아래 및 좌·우 방향의 8px 교집합, 양끝 clamp, 가장 가까운 변, 대각선 사분면과 유효 구간 없는 좁은 겹침을 확인한다.

### 사용자 이야기 13: 작은 핸들 분할·병합 임계치 (P1)

- FR-032: 작은 중점 핸들 드래그의 분할·병합은 Down 당시 선분을 지나는 직선으로부터 마우스의 수직 거리로 판정한다. 양쪽 방향 모두 거리 5px 이내이면 원본 선분이며 5px 초과이면 임시 꺾임점을 가진다. 드래그 중 반복 전환을 지원하고 선분 연장선 위에서도 같은 규칙을 사용한다. 길이 0인 선분은 해당 점까지의 거리를 사용한다.
- FR-033: 5px 이내에서 release하면 XML·기존 꺾임점·weight를 변경하지 않고 Undo 편집도 만들지 않는다. 초과해서 release한 경우만 하나의 꺾임점을 기존 방식으로 저장한다. 기존 큰 꺾임점 핸들 이동과 끝점 재연결은 유지한다.

명확화: 기준선은 새 꺾임점으로 분할된 두 선이 아닌 드래그 시작 당시 선분의 직선이다. 이번 제스처에서 생성한 임시 꺾임점만 병합하며 이미 저장된 다른 꺾임점은 삭제하지 않는다.

### 사용자 이야기 14: 기존 꺾임점 병합 (P1)

- FR-034: 기존 bendpoint 핸들 드래그에서도 제거 후보 경로의 이웃점 직선과 마우스의 수직 거리가 5px 이내이면 해당 bendpoint를 병합하고, 초과하면 원래 bendpoint를 이동한 상태로 복원한다. 매 이벤트는 Down 당시 원본을 기준으로 계산한다. 첫·마지막 및 단일 bendpoint도 지원한다.
- FR-035: 범위 안에서 release하면 해당 XML bendpoint만 삭제하고 남은 점의 절대 위치·weight·알 수 없는 속성을 유지한다. 범위 밖에서 release하면 위치 이동을 저장한다. 한 번의 Undo/Redo, 저장 및 Source 변경·읽기 전용 보호를 유지한다.

명확화: 제거 후보 경로는 해당 점을 제외하고 기존 연결 규칙으로 계산한 경로다. 처음·마지막 점의 이웃은 보정된 연결 끝점이다. 중점 삽입 병합과 달리 기존 핸들은 드래그한 기존 점의 삭제를 허용하며 다른 점은 삭제하지 않는다.

독립 검증: 양쪽 5px 경계, 첫·중간·마지막·단일 점, 병합 후 복원 반복, 남은 위치·weight 보존과 정확한 XML 삭제·Undo/Redo를 확인한다.

### 사용자 이야기 15: Activity 직결 끝점 드래그 대칭 (P1)

- FR-036: 꺾임점 없는 Activity↔Activity 연결에서 시작·끝 어느 핸들을 드래그하든 유효한 대상 Activity 위의 현재 마우스 좌표를 공통 x/y 선택 기준으로 사용한다. 기존 8px 유효 구간 제한과 수직·수평 방향 선택을 유지한다. end 드래그 시 lastRelativePoint뿐 아니라 렌더링·저장에 쓰이는 firstRelativePoint도 갱신한다.
- FR-037: 유효 대상에 release한 뒤 Source 재파싱·저장에도 좌표가 유지되고 Undo/Redo가 가능하다. 빈 공간의 가상 State, 꺾임점 경로 및 다른 State 연결은 기존 동작을 유지한다.

명확화: 기존 XML 형식을 유지하기 위해 Activity 직결의 공통 좌표 기준은 firstRelativePoint에 저장한다. end 드래그는 lastRelativePoint도 유지하며 시작·끝 연결 참조는 대상 Child가 바뀐 경우에만 변경한다.

독립 검증: 수직·수평 연결 양 끝의 드래그와 유효 구간 clamp, 놓은 뒤 Source·저장·Undo/Redo, Navigation 후 드래그를 확인한다.

독립 검증: 수평·수직·대각선의 양쪽 5px 경계, 바깥/안쪽 반복 전환, Navigation 이후 판정, 안쪽 release 무편집 및 바깥 release의 저장·Undo를 확인한다.

### 사용자 이야기 16: Child 관통 방지 병합 (P1)

- FR-038: 기존 bendpoint 및 중점 핸들 드래그에서 5px 병합 임계치에 들어와도 드래그 위치 B의 인접 선분 A–B 또는 B–C가 해당 Wire의 start·end Child의 내부를 통과하면 병합하지 않고 드래그 위치의 bendpoint를 유지한다. 연결된 시작·끝 Child도 검사한다.
- FR-039: Child 내부를 통과하지 않으면 기존 병합 동작과 임계치를 유지한다. 경계에 접하기만 하는 선분은 허용한다. 미리보기와 release에 같은 조건을 적용하며 기존 저장·Undo/Redo 보호를 유지한다.

명확화: 사용자 요청과 기존 도형 정의로 범위가 명확하여 추가 질문은 없다. Activity는 둥근 사각형, State는 원의 내부를 기준으로 검사한다. 드래그 위치의 인접 두 선분 이외의 교차는 이번 병합 판단에 사용하지 않는다.

독립 검증: 수평·수직·대각선 관통, 경계 접촉, 연결 Child 관통, 중점/기존점 병합 차단과 장애물이 없는 병합을 확인한다.

### 사용자 이야기 17: 드래그 위치의 인접 선분으로 관통 판단

- FR-040: B 핸들을 드래그하면 현재 마우스 위치 B와 양옆 점 A, C로 형성되는 A–B 및 B–C의 Child 내부 관통을 검사한다. 어느 하나라도 관통하면 직선 임계치 안에서도 병합하지 않는다. 병합 후 A–C는 관통 검사의 기준이 아니다.
- FR-041: 기존점과 중점 핸들 모두 같은 규칙을 적용하며 연결 끝점은 이동한 B를 기준으로 기존 도형 연결 규칙으로 보정한다. 경계 접촉 허용, 정상 State 원 외곽 접속, 5px 기준, 저장과 Undo 동작은 유지한다.

명확화: 사용자 지적으로 기존 FR-038의 검사 대상은 병합 후보 새 선분이 아니라 드래그 위치의 인접 두 선분으로 정정한다. 추가 질문은 없다.

수용 검증: A–C는 비관통이나 A–B 또는 B–C가 관통하는 경우 병합을 차단하고, A–C만 관통하고 두 인접 선분은 비관통이면 병합을 허용한다.

### 사용자 이야기 18: 연결 Child만 병합 관통 검사

- FR-042: 병합 시 A–B와 B–C의 관통 검사 대상은 해당 Wire의 start와 end Child만이다. 연결되지 않은 Child는 겹치거나 내부를 지나더라도 병합 여부에 영향을 주지 않는다. 기존점과 중점 핸들 모두 동일하다.
- FR-043: start 또는 end Child 관통 차단, 5px 임계치, 정상 연결 접점과 State 원 외곽 접속, 경계 접촉 허용, 저장·Undo/Redo는 유지한다.

명확화: 사용자가 start·end만 대상으로 한다고 확인했다. 추가 질문은 없다.

수용 검증: 연결되지 않은 Activity·State가 인접 선분 위에 있어도 병합하고, start 또는 end를 관통하면 병합하지 않는다.

### 사용자 이야기 19: 겹침 구간의 작은 핸들로 직선 이동 (P1)

- FR-044: 꺾임점 없는 Activity↔Activity Wire의 작은 중점 핸들을 드래그하면, 가로 유효 구간이 겹치는 수직 연결은 양 접점의 x를 함께 이동하고, 그 구간이 없고 세로 유효 구간이 겹치는 수평 연결은 양 접점의 y를 함께 이동한다.
- FR-045: 이동 범위는 각 Activity에서 양쪽 8px를 제외한 구간의 교집합이며 마우스가 범위를 벗어나면 현재 마우스 위치에 bendpoint를 삽입하여 두 선분으로 나눈다. 범위 안이며 A–B와 B–C가 start·end Child를 관통하지 않을 때만 이동 축 이외의 마우스 좌표를 무시하고 직선을 유지한다. 가로·세로가 모두 겹치면 기존 수직 우선 규칙을 따른다.
- FR-046: 미리보기·release·Source·저장에 결과가 유지되고 제스처당 한 번의 Undo/Redo를 지원한다. Navigation 후에도 같은 좌표 규칙을 적용한다. 읽기 전용·Source 동시 변경 보호를 유지한다. State 연결, 대각선 직결 및 기존 bendpoint 경로는 기존 분할·병합을 유지한다.

명확화: 앞선 끝점 드래그와 같은 겹침 및 제한 범위를 사용한다. 제한 범위 밖에서는 bendpoint 삽입으로 전환하며 다시 안으로 돌아오고 start·end 관통이 없어지면 직결 이동으로 복원한다. 사용자 요청과 기존 규칙으로 범위가 명확하여 추가 질문은 없다.

수용 검증: 수평·수직 양 방향, 양쪽 범위 경계와 바깥 분할, 5px를 넘는 이동, 축 외 이동 무시, 단일점 교집합, Source·저장·Undo/Redo와 Navigation을 확인한다.

### 사용자 이야기 20: 작은 핸들의 제한 범위 밖 분할 (P1)

- FR-047: Activity 직결 중점 드래그에서 해당 축의 좌표가 공통 유효 범위 경계를 포함한 안쪽이며 A–B와 B–C가 start·end Child를 관통하지 않으면 양 접점을 함께 이동한다. 경계를 조금이라도 벗어나면 5px 임계치와 관계없이 현재 마우스 위치에 bendpoint 하나를 만들어 분할한다.
- FR-048: 같은 드래그에서 안·밖 전환을 반복하며 원본 Wire 기준으로 복원·분할한다. 범위 밖 release는 단일 bendpoint와 weight 0.5를 저장하고 한 번의 Undo/Redo를 지원한다. 수평·수직, 단일점 교집합, Navigation과 기존 보호 처리를 유지한다.

명확화: 사용자가 범위 밖에서는 기존처럼 두 선분으로 나누도록 정정했다. 범위 밖 분할은 A–B/B–C가 아닌 기존 직선 거리 5px 기준에 의해 다시 병합되지 않는다. 다른 Wire 유형의 기존 분할·병합 규칙은 유지한다.

### 사용자 이야기 21: 직선 복원에도 연결 Child 관통 방지 (P1)

- FR-049: 작은 핸들의 공통 이동 범위 안에서도 이동한 B의 A–B 또는 B–C가 Wire의 start·end Child 내부를 통과하면 병합·직선 복원을 금지하고 B의 bendpoint를 유지한다. 연결되지 않은 Child는 검사하지 않는다.
- FR-050: 범위 안이며 start·end 관통이 없어진 경우에만 양 접점 직결 이동으로 복원한다. 반복 전환, 미리보기·release·저장 및 한 번의 Undo/Redo에도 같은 조건을 적용한다. 범위 밖 분할과 경계 접촉 허용은 유지한다.

명확화: 사용자 확인에 따라 기존 관통 방지 조건은 직결 공통 이동 분기에도 동일하게 적용한다. 추가 질문은 없다.

수용 검증: 수평·수직 양 방향에서 범위 안의 B가 start 또는 end 내부에 위치해도 분할을 유지하고, 안전한 위치로 돌아오면 직결로 복원한다.

### 사용자 이야기 22: Esc로 드래그 취소 (P1)

- FR-051: Child 단일·일괄 이동, 너비 조절, Wire 끝점 재연결·bendpoint·중점 편집 중 Esc를 누르면 제스처 시작 당시 모양으로 복원하고 이후 release를 무시한다. XML 변경이나 Undo 기록을 만들지 않는다.
- FR-052: 화면 이동과 범위 선택도 Esc로 취소하여 시작 당시 Navigation·선택을 복원한다. 다른 Source 변경으로 이미 제스처가 취소되었으면 최신 Source를 되돌리지 않는다. 취소 후 커서와 다음 제스처는 정상 동작한다.

### 사용자 이야기 23: 선택 Child와 내부 Wire 복사·붙여넣기 (P1)

- FR-053: 복사는 선택된 Child만 대상으로 하며 양쪽 Child가 모두 선택된 Wire를 선언 순서대로 함께 포함한다. 선택되지 않은 Child로 이어지는 Wire와 외부 input/output 참조는 복제하지 않는다. Wire 단독 선택은 복사를 활성화하지 않는다.
- FR-054: 붙여넣기는 복사 당시 보이던 화면 위치를 현재 Navigation·스크롤·캔버스 원점에 맞춰 보정하고 첫 붙여넣기는 (15,15)px, 같은 복사본의 반복 붙여넣기는 (30,30), (45,45)px씩 누적 이동한다. 새 복사 시 누적 횟수를 초기화한다.
- FR-055: 대상 문서 전체 Child·Wire의 숫자 ID 최댓값+1부터 새 Child 다음 새 Wire 순으로 연속 ID를 부여한다. 숫자 ID가 없으면 1부터 시작한다. 숫자가 아닌 기존 ID와 알 수 없는 요소는 보존하고 새 ID가 기존 요소 ID와 충돌하지 않게 한다. input/output은 ID가 아닌 새 Wire 선언 인덱스로 재연결한다.
- FR-056: Child 종류·이름·크기·속성·하위 property 및 내부 Wire 조건·상대 bendpoint·weight·알 수 없는 속성을 보존한다. 복제 Child와 절대 Wire 접점 좌표는 같은 이동량을 적용하여 전체 경로를 함께 옮긴다. 원본 요소와 참조를 변경하지 않는다. XML 네임스페이스도 유지한다.
- FR-057: IDE의 Copy/Paste 동작과 현재 키맵의 단축키(기본 Ctrl+C/Ctrl+V)를 적용한다. 복사는 읽기 전용에서도 가능하고 붙여넣기는 읽기 전용·유효하지 않은 문서·호환되지 않는 클립보드·진행 중인 드래그에서는 비활성화한다. 선택이 없으면 기존 클립보드를 덮어쓰지 않는다.
- FR-058: 붙여넣기 한 번은 하나의 Undo/Redo로 처리하며 Source·저장에 반영한다. 붙여넣은 Child를 선택하고 Navigation은 유지한다. 복사 시점의 내용을 보관하여 이후 원본 편집·삭제에도 복사본은 바뀌지 않는다. 열린 다른 모델 문서에도 붙여넣을 수 있다.

명확화(2026-10-24): 사용자가 Navigation 변경 후에도 복사 당시 화면 위치에서 15px 이동한 위치를 선택했다. 반복 붙여넣기는 같은 기준에서 15px씩 누적한다. ID는 대상 문서의 Child·Wire를 합친 숫자 최댓값을 사용하며 재연결 대상 선택의 기존 동작은 변경하지 않고 작업 후 설명한다.

수용 검증: Esc 후 release 무편집·Undo 없음, 혼합 Child 선택과 내부/외부 Wire 포함 여부, 속성·weight·네임스페이스 보존, ID·선언 인덱스 재매핑, Navigation·스크롤 보정, 반복·다른 문서 붙여넣기, 단축키와 저장·Undo/Redo를 확인한다.

### 사용자 이야기 24: Delete로 선택 요소와 연결 참조 삭제 (P1)

- FR-059: Design에서 Delete를 누르면 선택된 Child 전체 또는 선택된 Wire를 삭제한다. 선택이 없으면 아무것도 변경하지 않는다. Wire와 Child의 기존 상호 배타적 선택 규칙을 유지한다.
- FR-060: Child 삭제 시 해당 Child의 input/output에 연결된 모든 Wire를 함께 삭제하고, 남은 모든 Child의 input/output에서도 삭제한 Wire 참조를 제거한다. 상대편 Child 자체는 유지하며 참조만 정리한다. 여러 Child가 공유하는 Wire는 한 번만 삭제한다.
- FR-061: Wire 삭제 후 남은 Wire 선언 인덱스가 바뀌면 모든 Child의 input/output을 새 인덱스로 재매핑한다. Wire의 id 값과 남은 요소의 선언 순서·속성·경로·property는 유지한다. 화면에 표시하지 않는 종류의 Child도 참조 정리 대상이다.
- FR-062: 전체 삭제와 참조 정리는 하나의 Undo/Redo로 복원하며 Source·저장과 동기화한다. 삭제 후 선택을 해제하고 Navigation·스크롤·캔버스 원점은 유지한다. 기존 복사본은 삭제에 영향받지 않는다.
- FR-063: 읽기 전용·유효하지 않은 문서·진행 중인 드래그·Source 갱신 대기 상태에서는 삭제하지 않는다. 삭제 직전 Source를 다시 확인하여 오래된 선택으로 최신 문서를 변경하지 않는다. IDE Delete 동작과 Delete 키를 함께 지원한다.

명확화: 연쇄 삭제는 선택 Child→연결 Wire→남은 Child의 Wire 참조 정리까지다. 연결된 다른 Child 자체는 삭제하지 않는다. 참조는 Wire ID가 아니라 선언 인덱스이므로 삭제된 위치 뒤의 모든 참조를 재매핑한다. 추가 질문은 없다.

수용 검증: 첫·중간·마지막 Wire 삭제, 여러 Child와 공유 Wire 삭제, 외부/미지원 Child 참조 정리, 남은 ID·속성·경로 보존, Delete 단축키·Undo/Redo·저장·Navigation 및 비활성 조건을 확인한다.

### 사용자 이야기 25: Wire 조건 편집 창 (P1)

- FR-064: Wire 선 또는 guardcondition 라벨을 더블클릭하면 현재 조건을 담은 편집 창을 연다. 확인을 누를 때만 해당 Wire의 guardcondition을 변경하며 취소·닫기는 변경하지 않는다. 빈 문자열도 허용한다.
- FR-065: 조건 변경은 한 번의 Undo/Redo·Source·저장과 연동하고 Wire 경로·ID·참조·기타 속성은 유지한다. 창을 연 뒤 Source가 바뀌거나 읽기 전용이 되면 오래된 값으로 덮어쓰지 않는다. 같은 값을 확인하면 편집 명령을 만들지 않는다.

### 사용자 이야기 26: Activity 이름과 property 편집 창 (P1)

- FR-066: Activity 더블클릭 시 name 전용 입력, 일반 property의 key/value 편집 테이블, description 전용 다중 행 textarea를 제공한다. State에는 이 창을 열지 않는다. 테이블은 행 추가·삭제와 셀 편집을 지원하고 description은 테이블에 중복 노출하지 않는다.
- FR-067: 확인 시에만 name과 property 변경을 한 XML 명령으로 반영한다. 기존 property의 기타 속성과 Activity의 ID·종류·위치·크기·연결·기타 하위 요소를 유지한다. 기존 행의 key 변경도 지원한다. 빈 description은 해당 property를 제거하며 새 내용은 description property로 저장한다. 테이블의 빈 key·중복 key·description key는 확인 전에 안내한다.
- FR-068: 취소·닫기·무변경 확인은 문서를 바꾸지 않는다. 편집 중 Source 변경·읽기 전용 전환을 보호하고 Undo/Redo·저장·Source 동기화를 지원한다. description의 줄바꿈과 XML 특수문자는 보존한다.

### 사용자 이야기 27: 툴바의 Child 추가 모드 (P1)

- FR-069: 상단 툴바에 Activity·시작 State·종료 State 종류 메뉴가 결합된 Child 추가 토글 버튼 하나를 제공한다. 마지막 선택 종류는 프로젝트에서 기억하고 토글을 다시 켤 때 사용한다. 종류 선택만으로 추가 모드를 켜지는 않는다.
- FR-070: 추가 모드에서 선택한 종류와 동일한 스타일의 ghost 중심이 마우스를 따라다닌다. 왼쪽 클릭 위치에 같은 종류·크기의 Child를 생성한다. Activity 기본 너비 100·높이 30·이름 Activity, State 크기 20을 사용한다. ID는 대상 문서 숫자 최댓값+1이며 기존 Wire 선언 인덱스와 참조는 유지한다.
- FR-071: 추가 모드는 클릭 후 유지하여 연속 배치할 수 있으며 종류를 바꾸면 ghost도 바뀐다. 토글 해제·Esc로 종료하고 마우스가 캔버스 밖에 있으면 ghost를 숨긴다. 오른쪽 드래그 Navigation도 유지한다. 모드 중 일반 선택·이동·더블클릭 편집 및 Copy/Paste/Delete와 충돌하지 않는다.
- FR-072: 생성은 클릭당 한 Undo/Redo로 처리하고 새 Child를 선택한다. Navigation·스크롤·원점 변환을 적용하여 ghost와 실제 생성 위치가 일치하며 음수 위치도 지원한다. 미리보기는 XML을 바꾸지 않고 읽기 전용·잘못된 문서·Source 갱신 대기에서는 생성하지 않는다. namespace·Source·저장을 지원한다.

명확화(2026-10-24): 사용자는 종류별 토글 대신 Select 박스에 3종류를 제공하고 마지막 선택 종류를 사용하도록 요청했다. 추가 모드는 반복 배치 후 토글 또는 Esc로 종료하며 마우스가 Child 중심을 가리킨다. 기존 property 행의 알 수 없는 속성을 보존하고 description은 전용 textarea에서만 편집한다.

수용 검증: 실제 더블클릭의 대상 분기·편집 창 초기값·확인/취소·무변경·동시 Source 보호, name/property/description 수정과 줄바꿈, 종류 기억·토글/ghost/연속 배치·Esc·Navigation·ID·namespace 및 Undo/Redo를 확인한다.

### 사용자 이야기 28: 편집 창 배치와 property 행 클립보드 (P1)

- FR-073: Wire 조건 창 제목은 Transition 편집으로 바꾸고 guardcondition 라벨을 제거한다. 입력 영역과 초기 창 너비는 기존의 약 절반으로 줄이며 확인·취소 동작은 유지한다.
- FR-074: Activity 창의 Name·Properties·Description 첫 글자를 대문자로 표시한다. Description textarea 내부에는 8px 여백을 둔다. 버튼은 Add·Delete·Open Class·Open Query·Open Service 순서로 같은 너비로 가로 전체를 채운다. Key 컬럼의 초기 너비는 기존 절반인 테이블의 약 1/4로 하고 Value가 나머지를 사용한다.
- FR-075: property 테이블에서 선택한 여러 행을 Ctrl+C/Ctrl+V 및 IDE Copy/Paste로 복사·붙여넣기한다. 복사본은 key/value만 보관하고 원래 XML sourceIndex는 재사용하지 않는다. 선택한 마지막 행 뒤 또는 선택이 없으면 끝에 삽입하고 새 행을 선택한다. 탭·줄바꿈이 있는 value도 보존하며 TSV 클립보드도 지원한다.
- FR-076: 행 복사·붙여넣기는 창 안의 입력만 바꾸며 Activity 확인 전에는 XML을 변경하지 않는다. 기존 key 중복·빈 값·description 예약 키 검증은 유지한다. 셀 텍스트 편집의 복사·붙여넣기와 충돌하지 않는다.

### 사용자 이야기 29: class property의 에디터 열기 (P1)

- FR-077: Open Class는 테이블에서 현재 입력한 key=class의 value를 기준으로 프로젝트와 라이브러리에서 클래스를 찾아 에디터로 연다. 편집 중인 셀 값을 먼저 반영하고 양끝 공백은 제외한다. 클래스 열기는 Activity XML을 저장하지 않는다.
- FR-078: class 값이 비었거나 클래스를 찾을 수 없으면 창 안에 안내하며 입력값을 유지한다. Open Query·Open Service는 버튼을 제공하되 이번 요청에 실행 동작이 정의되지 않았으므로 비활성으로 둔다.

### 사용자 이야기 30: 통합 Child 추가 버튼과 동일한 ghost 모양 (P1)

- FR-079: 기존 종류 Select와 추가 토글을 드롭다운이 붙은 토글 버튼 하나로 합친다. 본체는 추가 모드 on/off, 화살표는 3종류 선택이다. 마지막 종류 기억·Esc·연속 배치·읽기 전용 보호는 유지한다. 종류 선택만으로 꺼진 모드를 켜지 않는다.
- FR-080: ghost는 실제 추가될 Child와 같은 채움색·테두리·크기·텍스트를 사용한다. 반투명 합성은 제거한다. 선택 핸들은 ghost에 표시하지 않고 클릭 전 XML은 만들지 않는다.

명확화(2026-10-24): 작업 중 사용자가 툴바의 Select/버튼 통합과 실제 도형과 같은 ghost 스타일을 추가 요청했다. 통합 컨트롤은 한 토글 버튼의 본체와 종류 선택 화살표로 제공한다. Open Query·Open Service 실행은 별도 정의 전까지 비활성으로 제공한다. 행 붙여넣기는 복제 후 key를 편집할 수 있고 확인 시 중복 검증을 적용한다.

수용 검증: 제목·라벨·폭·패딩·버튼 균등 배치, 여러 행 및 TSV·줄바꿈 복사/붙여넣기·XML sourceIndex 분리, class 탐색/실제 파일 열기·실패 안내·XML 무변경, 통합 버튼 종류 선택과 토글·Esc·ghost/실제 도형 픽셀 일치를 확인한다.

### 사용자 이야기 31: IntelliJ 표준 생성 툴바 (P1)

### 사용자 이야기 40: 메모리 Query ID 인덱스와 sql-key 자동완성 (P1)

- FR-104: 프로젝트를 처음 열 때 프로젝트 콘텐츠의 .glue_sql 파일을 백그라운드에서 읽고 queryMap의 직접 자식 query의 id·설명·소속 파일을 메모리에 수집한다. 인덱스 파일·영속 설정은 만들지 않으며 프로젝트를 닫으면 폐기하고 다음 실행에 다시 구성한다.

- FR-136: Esc·토글 off·다른 생성 모드 전환·Source 변경은 미완료 미리보기를 해제한다. 같은 Child 재클릭이나 빈 화면 클릭으로 잘못된 Wire를 만들지 않는다. 읽기 전용·동시 문서 변경·미니맵 위 클릭을 보호한다.

명확화: Wire 추가는 시작과 끝을 순서대로 클릭한다. 자기 자신 연결은 기존 재연결 제한과 같이 허용하지 않는다. 프리셋 class 중복은 첫 항목 우선이고 프리셋 선택은 현재 에디터에서 유지한다. Service는 프로젝트 콘텐츠와 설정 폴더에서 찾으며 프로젝트 밖은 탐색하지 않는다.

수용 검증: 경로 설정 없이 프로젝트 폴더의 sample2.glue_uml_ad를 찾고 중복 경로를 구분한다. 프리셋 메뉴·생성 이름/속성/Description·ghost/기존 class 색상·설정 변경·일치 없음·미니맵을 확인한다. Wire 토글 위치·모드 배타성·미리보기/취소·참조·저장/Undo/Redo·Source/읽기 전용·State 접점을 검증한다.
## 후속 사용자 시나리오 52: 생성과 표시 개선

- FR-137: Open Service로 새 파일 또는 이미 열린 파일을 열면 Design을 선택한다.
- FR-138: Activity 추가 메뉴에서 일반 종류나 프리셋을 선택하면 즉시 생성 토글을 켠다. 본체 토글과 Esc로 끌 수 있고 편집 불가 문서는 보호한다. 이전 FR-132의 선택만으로 켜지지 않는 조건을 대체한다.
- FR-139: 프리셋의 Color 라벨을 Background로 변경하고 Foreground 피커를 추가한다. 기본 Foreground는 GRAY_145(#919191)이며 저장·취소·재시작을 지원한다. 기존 배경 설정을 보존하고 같은 class의 Activity name 글자에 Foreground를 적용한다. 기존 Activity·ghost·미니맵을 함께 갱신하며 테두리는 유지한다.
- FR-140: Wire 생성 미리보기는 실제 Wire와 같은 굵기·색·화살표로 그린다. 빈 화면으로 향하는 미리보기에 불필요한 꺾임을 생성하지 않고 목표 Child에서의 미리보기와 최종 저장 경로를 일치시킨다. 자석과 기존 접점 제한은 유지한다.

인수 시나리오: Source가 선택된 Service를 Open Service로 다시 열면 Design이 보인다. 메뉴에서 프리셋 또는 State를 선택하면 ghost가 바로 표시된다. Foreground 변경은 name에만 적용되고 기존 설정에는 #919191을 사용한다. 자석 on/off 모두 빈 화면 미리보기가 직선이며 목표 선택 후 실제 경로와 같다.

명확화 검토: 질문 없이 진행 가능하다. GRAY_145는 RGB(145,145,145)로 해석한다. 실제 Child에 붙일 때 자석이 접점 확보를 위해 필요한 꺾임은 기존 규칙을 유지하고 빈 화면용 가상 State 때문에 생기는 꺾임만 제거한다.

## 후속 사용자 이야기 53: 텍스트 툴바와 확대·축소 (P1)

- FR-141: Child 추가 툴바는 아이콘 대신 선택한 일반 종류 또는 프리셋 이름을 표시한다. 일반 메뉴 명칭은 빈 Activity·InitialState·FinalState이다. Wire 추가는 아이콘 대신 Wire로 표시한다.
- FR-142: 일반 종류·프리셋을 고르면 드롭다운을 닫고 생성 모드를 켠다. 본체 토글·Esc·읽기 전용 보호를 유지한다.
- FR-143: 툴바에 [-][100%][+] 세 버튼을 한 묶음으로 제공한다. 확대율은 25~200% 범위에서 25%씩 바뀌며 가운데는 현재 비율을 표시하고 누르면 100%로 복원한다. 확대 중심은 화면 중앙이고 모델 좌표·XML을 변경하지 않는다.
- FR-144: 확대율을 그리기·클릭·드래그·resize·범위 선택·ghost·Wire·Navigation·미니맵·붙여넣기에 일관되게 반영한다. 미니맵과 좌표/속성 HUD는 고정 화면 크기로 표시한다. 확대율을 바꿔도 복사 요소의 크기는 유지하고 복사 당시 화면 기준 위치에서 15px 이동해 붙인다.

인수 시나리오: 메뉴 선택 뒤 선택 텍스트·토글 on·닫힌 메뉴를 확인한다. 150%에서 Child를 30px 움직이면 모델 좌표는 20만큼 변한다. 50%와 200%에서도 생성과 Wire 클릭이 포인터를 따르고 미니맵 커서가 실제 표시 범위를 반영한다. 가운데 버튼은 XML 변경 없이 100%로 돌아간다.

명확화: 확대율은 에디터별로 유지하며 다시 열면 100%로 시작한다. 설정 가능한 범위와 간격은 위 기본값을 사용한다. Service XML은 사용자의 답변에 따라 glue_uml_ad 저장 시 생성하며 아래 사용자 이야기 54의 property 변환 규칙을 따른다.

## 후속 사용자 이야기 54: Service XML 저장 (P1)

- FR-145: 프로젝트의 glue_uml_ad 파일 저장 시 Settings의 Service 저장 경로에 원본 파일명-service.xml을 생성·갱신한다. 경로 미설정이면 생성하지 않고 원본 XML과 모델 좌표는 변경하지 않는다. 생성 XML은 UTF-8 선언과 http://www.poscoict.com/glueframework/service 네임스페이스를 사용한다.
- FR-146: service name은 파일명-service이며 initial은 InitialState에서 연결된 Activity name이다. Activity를 선언 순서대로 name·class와 함께 출력하고 class와 description을 제외한 property는 name·value로 출력한다. 빈 description과 내용 있는 description 모두 제외한다. Activity의 output 참조 순서대로 transition name=guardcondition, value=대상 Activity name을 출력하고 FinalState 대상은 end로 출력한다. 위치·ID·State·bendpoint는 출력하지 않는다.
- FR-147: Diagram의 description을 제외한 각 property를 transaction-manager id=key, commit=true/false로 항상 출력한다. false인 항목도 포함한다. 불완전한 XML·모호한 InitialState·중복 Activity name·없는 class·끊긴 참조·비논리값 transaction property는 기존 출력 파일을 덮어쓰지 않고 생성 실패를 알린다. 저장 대상 폴더는 기존 프로젝트 내부 제한을 유지한다. 출력은 안정적인 원본 순서를 사용하며 XML 특수문자와 한글을 보존한다.

인수 시나리오: 제공한 sample11을 저장하면 sample11-service.xml에 같은 service·initial·transaction·Activity·transition·property 내용을 만든다. false transaction도 commit=false로 생성한다. Source와 Design 저장 모두 동작하며 잘못된 XML 저장은 마지막 정상 출력을 보존한다.

### 명확화 답변 2026-10-24

- 자동 생성 시점은 수정 즉시가 아닌 glue_uml_ad 저장 시점이다.
- 사용자의 최종 정정에 따라 transaction-manager는 true/false 모두 추가하고 property 값을 commit에 넣는다.
- Activity description은 내용 유무와 무관하게 항상 제외한다.

## 후속 사용자 이야기 55: 안전한 Design 갱신 (P1)

- FR-148: Design 선택 알림에서 문서 커밋을 즉시 실행하지 않는다. 에디터 생성·선택·문서 변경이 쓰기 불가 문맥에서 호출되어도 Write-unsafe context 오류 없이 안전한 UI 실행 시점에 최신 문서를 표시한다. 문서 내용은 갱신 때문에 변경하지 않는다.
- FR-149: 예약 갱신은 중복 요청을 병합하고 위치 유지 요청을 보존한다. 예약 후 에디터 폐기·파일 무효화·프로젝트 종료 시 갱신하지 않는다. 기존 편집 명령의 안전한 동기 갱신과 Source/Design 전환을 유지한다.

인수 시나리오: 쓰기 불가 문맥에서 미커밋 문서의 Design을 선택하거나 에디터를 생성해도 오류가 나지 않으며 예약 실행 후 최신 노드가 보인다. 연속 변경은 마지막 내용을 반영하며 폐기한 에디터는 예약 실행으로 갱신되지 않는다.

명확화 검토: 사용자가 제시한 호출 스택과 승인한 수정 방향이 명확하므로 추가 질문 없이 진행한다.

## 후속 사용자 이야기 56: 예약 갱신 중 Child 생성 (P1)

- FR-150: Child 생성은 예약 갱신이 있다는 이유로 클릭을 버리지 않는다. 탭 선택 직후·연속 생성·미반영 Source 변경 상황에서도 최신 정상 문서를 확인하여 클릭한 모델 위치에 한 번 생성하고 기존 내용을 보존한다. ID는 최신 문서의 최대값 이후를 사용한다.
- FR-151: 쓰기 불가 문맥의 생성 요청은 안전한 비모달 실행으로 넘긴다. 실행 시 모드·프리셋·문서 쓰기 권한·에디터 생명주기를 다시 확인하고 잘못된 XML에는 생성하지 않는다. 기존 더블클릭 중복 방지·미니맵·드래그 입력 규칙은 유지한다.

인수 시나리오: selectNotify로 갱신을 예약한 직후 클릭해도 생성된다. 이벤트 큐를 비우지 않고 연속으로 생성하면 클릭마다 서로 다른 ID를 가진 Child가 생긴다. Source를 수정하고 즉시 생성하면 Source 수정과 새 Child를 모두 보존한다. 쓰기 불가 콜백에서도 이전 TransactionGuard 오류가 재발하지 않는다.

명확화 검토: 앞서 제안한 예약 상태 검사와 최신 문서 검증 개선을 승인한 요청이므로 추가 질문은 없다. 더블클릭·드래그 규칙 변경은 이번 범위에 포함하지 않는다.

## 후속 사용자 이야기 57: 배율 선택 목록 (P1)

- FR-152: 확대·축소 버튼 묶음을 Select 하나로 교체하고 20%부터 150%까지 10% 간격의 14개 항목을 제공한다. 기본은 100%이며 선택 시 기존 화면 중앙 유지·좌표 변환·문서 무변경 동작을 유지한다. FR-143의 버튼과 범위·간격을 이 요구사항으로 대체한다.

인수 시나리오: 목록이 20%, 30%, …, 150%를 순서대로 표시한다. 20%와 150%를 고르면 해당 배율로 표시하고 100% 선택으로 원래 배율을 복원한다. 생성 클릭 누락 수정은 함께 유지한다.

명확화 검토: 항목 범위와 간격이 명확하여 질문 없이 진행한다. 새 에디터의 기본값은 기존대로 100%이다.

## 후속 사용자 이야기 58: 생성 요청 큐 (P1)

- FR-153: Child 생성 요청은 클릭 시 종류·모델 위치·프리셋·모드 세대를 캡처하여 FIFO 큐에 보관한다. 안전한 비모달 UI 작업에서 최신 문서를 확인하고 요청을 순서대로 한 번씩 처리한다. 갱신과 겹쳐도 요청을 병합하거나 버리지 않는다. 모드 취소·변경·에디터 폐기·쓰기 권한 해제·잘못된 문서는 재검증 후 취소한다. 기존 더블클릭 방지 정책은 유지하고 클릭 횟수 예외는 추가하지 않는다.

인수 시나리오: 종류 메뉴 선택 직후 도착한 클릭과 연속 클릭 요청이 실행 대기 후 순서대로 생성된다. 요청 시점의 위치와 프리셋을 사용한다. 생성 전 모드를 껐다 같은 종류로 다시 켜도 이전 요청은 실행하지 않는다. Source 갱신과 겹쳐도 최신 ID를 사용하고 폐기 후 생성하지 않는다.

명확화 답변: 사용자는 ghost는 보이지만 일정 시간이 지나야 생성된다고 확인했고 클릭 횟수 예외의 타당성에 의문을 제기하며 큐로 예약할 것을 제안했다. 클릭 횟수 가설은 확정하지 않고 생성 요청 큐로 처리 순서를 보장한다. 팝업이 Canvas 이전에 소비한 이벤트는 생성 큐가 복구할 수 없다는 범위 제한을 구분한다.

## 후속 사용자 이야기 59: 생성 클릭 진단 기록 (P1)

- FR-154: Activity 추가 문제를 재현할 때 종류/프리셋 선택·팝업 열기/닫힘·모드 변경·IDE 원시 마우스 이벤트·Canvas press/release/click 수신·무시 사유·큐 등록/시작/취소/완료를 INFO 로그로 기록한다. editor 세션·입력 이벤트·생성 요청 식별자로 연결하고 클릭 횟수·좌표·모드 세대·갱신 예약·큐 길이·문서 변경 번호·쓰기 가능 여부를 포함한다.
- FR-155: 원시 이벤트 관찰은 해당 캔버스 영역의 생성 모드 입력으로 제한하고 이벤트를 소비·재전송하지 않는다. move 이벤트나 속성/Description/XML 본문은 기록하지 않는다. 폐기 시 관찰자를 제거한다. 진단 추가로 기존 생성·더블클릭·큐·Undo 동작을 바꾸지 않는다. 별도 Debug 설정 없이 idea.log의 [ModelChildCreation]으로 찾을 수 있어야 한다.

인수 시나리오: clickCount=2로 거부된 입력은 Canvas 수신과 ignore 이유가 남고 큐 등록이 없어야 한다. 정상 클릭은 같은 input 식별자의 큐 등록과 같은 request 식별자의 실행/완료가 남는다. 모드를 바꿔 취소한 요청은 세대 불일치 이유가 남는다. 원시 기록만 있고 Canvas 기록이 없으면 IDE 입력 전달 단계 문제로 구분한다.

## 사용자 이야기 60: 미세 이동 클릭으로 Child 생성 (P1)

## 사용자 이야기 74: ELK 선 교차 최소화 (P1)

- FR-204: 서비스 직접 배치에서 각 연결의 입·출력 포트는 방향 면(North/South)을 유지하면서 위치가 고정되지 않도록 하여 ELK Layered가 교차 최소화 과정에서 선의 접점 순서와 위치를 조정할 수 있어야 한다.
- FR-205: 교차 최소화는 명시적으로 활성화하고 결정적인 입력 순서를 유지해야 한다. 가능한 배치 중 교차를 줄이되, 위상 구조상 불가피한 교차를 제거한다고 보장하지 않는다.

인수 기준: 고정 좌표 포트 정책이 제거되고 ELK Layered 교차 최소화 단계가 결정적인 입력으로 실행된다. 임의 교차 제거를 보장하지 않으며 기존 서비스 편집 정책은 보존된다.

## 사용자 이야기 78: 서비스 직접 편집 전용 Undo/Redo (P1)

서비스 XML을 직접 편집하는 사용자는 Commit 전 다이어그램 편집을 Undo/Redo로 되돌리고 다시 적용할 수 있어야 한다. 대기 편집 기록은 원본 XML 문서의 IntelliJ Undo/Redo 기록과 섞이지 않아야 한다.

기능 요구사항:
- FR-225: 서비스 직접 편집에서 Commit 전 편집은 별도 Undo/Redo 기록으로 관리하고 원본 XML 문서에 IntelliJ 쓰기 명령 기록을 만들지 않는다.
- FR-226: 서비스 Design에서 Undo/Redo 버튼과 Ctrl+Z/Ctrl+Shift+Z는 대기 projection 변경만 되돌리고 다시 적용한다. `.glue_uml_ad` 편집 및 서비스 XML Source 탭의 기본 Undo/Redo는 기존 동작을 유지한다.
- FR-227: Undo/Redo는 편집 동작 단위로 동작하고, 현재 projection을 기준으로 추가·삭제·수정 색상과 Commit 가능 상태를 갱신한다.
- FR-228: Commit 또는 Rollback은 해당 서비스의 대기 Undo/Redo 기록을 초기화한다. Commit 뒤 Source 변경을 Undo/Redo해도 이미 확정된 XML로 대기 편집을 덮어쓰지 않는다.
- FR-229: 서비스 직접 편집에서 Undo/Redo를 반복해도 XML Source는 Commit 전까지 바뀌지 않으며, Source 탭의 Undo/Redo 기록에 다이어그램 대기 편집이 나타나지 않는다.

수용 기준: 여러 Activity/Wire 편집을 순서대로 Undo/Redo하고 Commit 전 XML과 Source Undo 상태가 그대로인지 확인한다. 마지막 변경을 Undo하면 Commit 비활성화와 변경 표시 제거를 확인한다. Commit·Rollback 뒤 대기 기록이 비워지며 `.glue_uml_ad`와 Source 탭 Undo/Redo가 기존대로 동작하는지 확인한다.

명확화 답변(2026-10-24): 전용 Undo/Redo 버튼과 표준 Ctrl+Z/Ctrl+Shift+Z 입력은 서비스 Design에서 대기 편집 기록에만 작동한다. Commit은 XML의 표준 문서 Undo 기록으로 처리한다.
## 사용자 이야기 79: 서비스 대기 편집 Undo/Redo 금지와 툴바 라벨 (P1)

가장 최근 명확화는 이전 사용자 이야기 78의 서비스 대기 편집 Undo/Redo 지원 결정을 대체한다. Commit 전 요소는 Undo/Redo의 대상이 아니며, 서비스 Design에서 대기 편집을 되돌리거나 다시 실행하는 버튼 또는 전용 단축키를 제공하지 않는다.

- FR-230: 자석 툴바 액션의 텍스트 라벨은 `Magnetic`, Diagram 속성 액션의 텍스트 라벨은 `Properties`로 표시한다.
- FR-231: 서비스 Design의 Commit 전 projection 편집은 IntelliJ Undo/Redo 명령 기록에 넣지 않는다. 대기 편집을 Undo/Redo하는 툴바 액션과 전용 단축키도 제공하지 않는다. 대기 편집은 Commit 또는 Rollback으로만 반영하거나 폐기한다.
- FR-232: Commit으로 원본 XML에 반영한 변경은 일반 XML 편집 기록으로 남고 Source 탭에서 Undo/Redo할 수 있다. `.glue_uml_ad`의 기존 Undo/Redo 동작은 유지한다.

명확화 답변(2026-10-24): 사용자는 미커밋 요소를 Undo/Redo하지 않도록 요청했다. 이는 이전 US78의 staged Undo/Redo 지원을 취소하고 툴바 Undo/Redo 및 Design 전용 단축키를 제거한다. Commit/Source의 일반 XML Undo/Redo는 유지한다.
