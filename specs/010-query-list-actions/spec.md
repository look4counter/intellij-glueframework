# 기능 명세: Query 목록 아이콘 편집

**작성일**: 2026-10-26
**입력**: Query 목록에 추가·삭제·복제·위로·아래로 아이콘 버튼을 제공하고 추가 시 ID·Description·ResultType·IsNamed 입력 팝업을 표시한다.

## 사용자 시나리오 및 검증

### 사용자 이야기 1: Query 추가 (우선순위 P1)

추가 아이콘을 누르면 네 항목을 입력하고 확인하여 새 Query를 목록 끝에 추가한다. 취소는 문서를 바꾸지 않는다. ID는 필수이고 기존 ID와 중복되지 않아야 한다. IsNamed 기본값은 false이며 SQL은 비어 있다. 추가된 Query를 선택한다.

### 사용자 이야기 2: 선택 Query 관리 (우선순위 P1)

삭제는 선택 Query를 즉시 삭제하고 인접 항목을 선택한다. 복제는 SQL·속성·내부 내용을 복사하여 원본 바로 다음에 추가하고 선택한다. 복제 ID는 원본_copy, 원본_copy2 순으로 중복을 피한다. 위로·아래로는 선택 Query를 인접 Query와 한 칸 교환하고 선택을 유지한다.

### 경계 조건

- 선택이 없으면 삭제·복제·이동을 비활성화한다. 첫 항목의 위로와 마지막 항목의 아래로를 비활성화한다.
- 읽기 전용·잘못된 XML에서는 편집 버튼을 비활성화한다.
- 모든 변경은 실행 취소·재실행과 Source·Design 동기화를 지원한다.
- 버튼 실행 전에 대기 중인 편집을 원래 Query에 반영한다.
- 쓰기 잠금 없는 UI 이벤트에서도 기존 스레드 오류를 재발시키지 않는다.
- 루트 속성·주석·다른 네임스페이스 요소와 Query 내부의 CDATA·주석·확장 내용을 보존한다.
- 팝업 중 원문이 변경되면 오래된 입력으로 덮어쓰지 않는다.

## 요구사항

- **FR-001**: 목록에 다섯 아이콘 버튼과 기능을 설명하는 툴팁·접근성 이름을 제공한다.
- **FR-006**: 다섯 버튼은 아이콘 크기를 유지하고 내부 패딩을 넣어 기본 배율에서 전체 32×32 정사각형으로 표시하며 화면 배율에 맞게 확대한다. 기존 기능은 유지한다.
- **FR-002**: 추가 팝업에서 네 값을 입력·검증하고 확인 시에만 새 Query를 생성한다.
- **FR-003**: 삭제·복제·이동은 선택 항목에 적용하고 목록 선택과 정상 XML 구조를 유지한다.
- **FR-004**: 실행 취소·재실행·저장·대기 편집·읽기 전용·스레드 안전성을 보존한다.
- **FR-005**: 원본의 관련 없는 XML 내용과 복제 대상의 내부 내용을 보존한다.

## 주요 개체

- 새 Query 입력: ID, 설명, 결과 타입, 이름 기반 파라미터 여부.
- Query 목록: 기존 XML 선언 순서를 표시하며 선택 항목을 유지한다.

## 성공 기준

- **SC-001**: 다섯 버튼·팝업 확인과 취소·ID 검증·경계 비활성화·실행 취소 회귀 검증이 통과한다.
- **SC-002**: 기존 Query Design·SQL 테스트가 모두 통과한다.
