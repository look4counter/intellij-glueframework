# 기능 명세: 저장 생명주기 안정화

작성일: 2026-11-07
상태: 명확화 완료
입력: 저장·재열기와 Design/Source 전환, 서비스 Commit/Rollback을 안정화한다.

## 사용자 시나리오와 검증

### 사용자 이야기 1: 편집 중인 서비스 보호 (우선순위 P1)

사용자는 모델 저장으로 서비스에서 작성 중인 내용을 잃지 않는다.
독립 검증: 미저장 서비스가 있을 때 모델을 저장하고 문서·디스크·미저장 상태를 비교한다.

1. 서비스에 미저장 변경이 있으면 자동 생성은 사유를 알리고 문서·디스크를 보존한다. 모델 저장 자체는 유지한다.
2. 서비스 문서가 읽기 전용이면 변경 없이 생성을 거부한다.
3. 미저장 변경이 없으면 기존처럼 생성·갱신하고 저장한다.

### 사용자 이야기 2: 직접 편집의 확정과 복구 (우선순위 P1)

사용자는 서비스 Design 편집을 Commit·저장·재열기하여 같은 내용을 확인하고 Rollback하면 최신 Source로 돌아간다.
독립 검증: 편집→탭 재선택→Commit→저장→편집기 재생성과 Source 충돌→Commit 거부→Rollback을 수행한다.

1. 탭 재선택 중 대기 편집이 보존되고 Commit·저장·재열기에서 변경과 확장 정보가 유지된다.
2. 대기 편집 중 Source 변경 시 Commit은 원본을 바꾸지 않고 거부하며 대기 편집을 유지한다.
3. 충돌 후 Rollback은 대기 편집을 버리고 최신 Source를 표시한다.

### 경계 조건

- 생성 결과가 미저장 문서와 같아도 사용자의 저장 결정을 대신하지 않는다.
- 문서 읽기 전용 상태는 파일 쓰기 권한과 별도로 검사한다.
- 자동 생성과 직접 편집은 기존 설정을 따른다.

## 요구사항

### 기능 요구사항

- FR-001: 자동 생성은 미저장 서비스 문서와 디스크를 변경하거나 저장하지 않아야 한다.
- FR-002: 자동 생성은 읽기 전용 서비스 문서를 변경하지 않아야 한다.
- FR-003: 생성 거부는 기존 실패 안내를 사용하며 정상 대상의 생성·갱신을 유지해야 한다.
- FR-004: 직접 편집은 탭 전환과 Commit·저장·재열기에서 의미와 확장 정보를 보존해야 한다.
- FR-005: Source 충돌 시 Commit을 거부하고 Rollback으로 최신 Source를 복구해야 한다.

### 주요 개체

- 모델: 자동 생성 입력 파일.
- 서비스: 디스크 내용, 편집 문서와 저장 상태를 가진 출력 파일.
- 대기 편집: Commit 전까지 원본과 분리되는 Design 변경.

## 성공 기준

- SC-001: 미저장·동일 내용 미저장·읽기 전용 세 보호 시나리오에서 문서·디스크 변경이 0건이다.
- SC-002: 정상 생성, 직접 편집의 저장·재열기 및 충돌 복구 시나리오가 모두 통과한다.
- SC-003: 자동 회귀 검증 결과와 실제 IDE 수동 확인 범위를 구분해 기록한다.

## 가정

- 실제 업무 파일 대신 저장소 샘플과 확장 속성·주석을 가진 테스트 파일로 재현한다.
- 새 기능, CI, 배포 정보 정리와 대규모 리팩터링은 제외한다.
- 기존 직접 편집의 미커밋 Undo/Redo 비활성화 정책을 유지한다.
- 명확화 검토 결과 추가 질문이 필요한 중요한 모호함은 없다.
