# 기능 명세: SQL 테이블 추적

작성일: 2026-11-08
상태: 명확화 완료
입력: QueryEditor의 기존 컬럼 추적 기능을 테이블에도 제공한다.

## 사용자 시나리오와 검증

### 사용자 이야기 1: 테이블의 출처와 전달 경로 확인 (P1)

테이블명·CTE 선언 및 참조·서브쿼리 별칭에 커서를 놓으면 기존 우측 하단 목록에서 원본부터 이후 사용처까지 확인한다. 컬럼 한정자인 `A.COL`의 `A`도 테이블 선택으로 취급한다. 목록을 클릭하거나 Enter를 누르면 해당 위치로 이동한다.

우선순위 이유: 컬럼 추적과 같은 조작으로 쿼리의 테이블 구성을 파악할 수 있다.

독립 검증: 물리 테이블 → 두 단계 CTE → 최종 FROM 예제에서 각 단계의 테이블을 선택하고 전체 경로와 탐색을 검증한다.

인수 시나리오:

1. `WITH a AS (SELECT * FROM physical), b AS (SELECT * FROM a) SELECT * FROM b`에서 어느 단계의 테이블 또는 CTE를 선택해도 원본·CTE 선언·FROM 참조가 표시된다.
2. 파생 테이블 별칭에서 선택하면 내부 FROM과 바깥 별칭이 연결된다. 컬럼 한정자의 별칭을 선택해도 같은 테이블 경로를 표시한다.
3. CTE가 여러 곳에서 참조되면 이후 참조 분기를 모두 표시한다. 단순히 JOIN에 함께 등장한 다른 입력은 선택한 원본의 경로에 섞이지 않는다. 복수 입력으로 정의된 CTE 자체를 선택하면 그 입력을 모두 표시한다.
4. 목록 항목을 선택하면 정확한 SQL 위치로 이동하며 SQL·Source를 수정하지 않는다.

### 사용자 이야기 2: 컬럼 추적과 안전하게 공존 (P1)

기존 컬럼 부분에서의 추적은 유지하고 테이블 부분에서만 테이블 추적을 선택한다. 연결된 DB가 없어도 SQL 본문에서 파악한 관계를 확인한다.

독립 검증: `SELECT A.COL FROM (...) A`의 A와 COL을 각각 선택해 테이블 경로와 기존 컬럼 경로가 분리되는지 검증한다.

인수 시나리오:

1. 같은 테이블명이라도 별개의 FROM 인스턴스나 다른 문장이면 근거 없이 연결하지 않는다. 중첩 WITH의 같은 이름도 가시 범위에 맞게 구분한다.
2. 주석·문자열·일반 키워드·빈 위치에서는 잘못된 테이블 경로를 표시하지 않는다. 재귀·불완전 SQL·큰 입력은 멈추거나 오래된 결과를 표시하지 않는다.
3. 빈 목록 문구는 `추적할 컬럼이나 테이블에 커서를 놓으세요.` 하나만 가운데 표시한다. 기존 패딩과 제목·하단 문구 없는 구성을 유지한다.

## 경계 사례

- 스키마 경로·인용 식별자·동일 테이블의 서로 다른 별칭·CTE 이름 가림·UNION·줄바꿈 형식·한 줄의 여러 참조를 구분한다.
- 한 SQL 줄은 목록에 한 번만 표시하며 이동 위치는 그 줄에 속한 테이블 관련 토큰이다.
- 재귀 CTE는 순환을 끊고 확인 가능한 경로만 표시한다. 실제 DB의 뷰 정의 등 본문 밖 계보는 조회하지 않는다.
- DML에서 구조적으로 확인되는 테이블 참조는 선택할 수 있지만 쓰기 대상과 읽기 입력 사이의 데이터 이동은 추정하지 않는다.

## 요구사항

- FR-001: 테이블명·스키마 경로·CTE 선언 및 참조·파생 테이블 별칭·컬럼 한정자에서 테이블을 선택한다. 컬럼 토큰은 기존 컬럼 추적을 유지한다.
- FR-002: 선택한 관계의 원본과 그 원본에서 이어지는 CTE·파생 테이블의 전체 참조 분기를 표시한다. 커서 위치에서 멈추지 않는다. 원본이 여러 개면 모두 표시하며 이후 소비자의 다른 JOIN 입력은 새 원본으로 추가하지 않는다.
- FR-003: 문장·스코프·인용 식별자·서로 다른 FROM 인스턴스를 구분하고 모호한 별칭을 임의로 연결하지 않는다. DB 연결이나 SQL 실행을 요구하지 않는다.
- FR-004: 기존 목록·행 번호 및 내용·클릭 및 Enter 이동·SQL 비변경·비동기 최신 결과 보호를 재사용한다. 중복 줄은 제거하고 출처가 소비자보다 먼저 표시되도록 한다.
- FR-005: 문자열·주석·불완전 입력·재귀 및 분석 한도에 안전하게 대응한다. 기존 컬럼 추적 회귀와 테이블 추적의 자동 검증을 수행한다.
- FR-006: 안내 문구를 컬럼과 테이블에 맞게 확장하되 가운데 정렬·패딩·별도 제목 및 하단 문구 제거를 유지한다.

## 주요 개체

- 테이블 참조: 물리 테이블·CTE·파생 테이블의 SQL 내 사용 위치와 별칭.
- 관계 정의: CTE 또는 파생 테이블의 직접 입력과 사용처.
- 추적 행: 원본 SQL의 줄 번호·내용·이동 위치.

## 성공 기준

- SC-001: CTE 연쇄·분기·파생 테이블·별칭·UNION 예제에서 예상한 전체 경로와 SQL 위치가 일치한다.
- SC-002: 컬럼 및 테이블 선택 분리, 스코프 격리, SQL 비변경, 목록 탐색 검증이 통과한다.
- SC-003: 관련 회귀·전체 테스트·설치 ZIP 및 플러그인 구조 검사가 통과한다.

## 가정과 명확화

질문 0개. 기존 TRACE의 원본부터 최종 사용처까지 추적하는 동작을 테이블에도 적용한다. 별도 버튼이나 설정 없이 커서 위치로 대상을 구분한다. 동일 이름의 물리 테이블 전체 검색이 아니라 SQL이 증명하는 관계를 추적한다. SQL 밖 뷰 정의나 쓰기 데이터 이동 분석은 범위 밖이다. 중요 모호함은 없으며 다음 계획 단계로 진행한다.
