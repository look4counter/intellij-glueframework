# 연구 결과

- 결정: `SqlQueryParser`가 이미 CTE·파생 테이블·별칭·DML 소스를 구분하므로 선언과 참조 위치만 보존한다. 이유: 이름 규칙을 중복 구현하지 않고 완성·오류 기능과 일치시킨다. 문자열 검색은 스코프를 구분하지 못해 제외했다.
- 결정: 소스 인스턴스와 CTE 정의의 방향 그래프를 사용한다. 이유: 물리 테이블의 이름만 같아도 독립적인 입력을 합치면 잘못된 계보를 만든다. 기존 컬럼 그래프는 컬럼 출력 슬롯에 종속되므로 테이블에는 재사용하지 않는다.
- 결정: 선택한 관계의 원본과 그 원본의 전체 소비자를 표시한다. 이유: 중간에서 멈추지 않고 분기를 표시하면서 다른 JOIN 입력을 새 원본으로 끌어오지 않는다. 선택한 CTE 자체의 입력이 여러 개면 모두 원본이 된다.
- 결정: 컬럼 한정자와 선언/참조 이름에서만 테이블 선택을 한다. 이유: `A.COL`의 COL은 기존 컬럼 추적을 유지해야 한다. 모호한 한정자는 임의 선택하지 않는다.
- 결정: 기존 목록의 비동기 및 탐색을 재사용한다. 새 JDBC·설정·SQL 변경은 필요 없다. 문구만 두 종류의 대상에 맞게 확장한다.

불명확한 기술 항목은 없다. 기존 코드와 자동 검증을 근거로 내부 구조를 결정했으며 외부 자료 조회는 필요하지 않다.
