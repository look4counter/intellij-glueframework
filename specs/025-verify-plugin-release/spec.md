# 기능 명세: 정식 빌드와 설치 산출물 검증

작성일: 2026-11-07
상태: 명확화 완료
입력: 정식 테스트·플러그인 ZIP 빌드를 복구하고 SVG 오류와 설치 가능한 구성을 검증한다.

## 사용자 시나리오와 검증

### 사용자 이야기 1: 전체 회귀 검증 (우선순위 P1)

개발자는 현재 기능에 맞는 전체 테스트 결과를 얻는다.
독립 검증: 전체 자동 테스트에서 실패·오류·건너뜀 없이 결과를 확인한다.

1. Wire 모드에서 시작점과 끝점을 선택하면 미리보기와 한 번의 연결 생성, 양쪽 참조 저장 및 Undo/Redo가 검증된다.
2. 종료 상태의 바깥 원과 안쪽 원 사이에는 배경이 보존되고 중심은 검정이며 캔버스 크기 보존도 검증된다.
3. 저장 보호와 쿼리 외관 검사를 포함한 기존 테스트를 모두 실행하고 SVG 접근 오류 재현 여부를 기록한다.

### 사용자 이야기 2: 설치 산출물 확인 (우선순위 P1)

사용자는 최신 수정이 포함된 설치 파일과 검증 결과를 받는다.
독립 검증: ZIP 생성, 구조 검사, 격리된 IDE 기동의 성공 여부를 각각 확인한다.

1. ZIP에 플러그인 정보, 두 편집기, JDBC 및 필요한 라이선스와 런타임 의존성이 포함된다.
2. 격리된 IDE에서 플러그인 로딩을 확인하며 실제 업무 파일 수동 확인과 구분한다.

### 경계 조건

- 화면에 표시되지 않는 테스트 컴포넌트의 클릭은 실제 사용자의 유효한 클릭으로 간주하지 않는다.
- 렌더링의 반투명 경계 픽셀을 빈 배경으로 오인하지 않는다.
- 기존 사용자 IDE 설정은 수정하지 않고 격리된 검증 환경을 사용한다.
- 빌드나 IDE 기동 실패는 성공으로 표시하지 않으며 근거와 원인을 기록한다.

## 요구사항

### 기능 요구사항

- FR-001: 정식 전체 테스트와 최신 설치 파일 생성을 수행하고 결과를 구분해 기록한다.
- FR-002: Wire 검증은 유효한 화면 영역에서 미리보기·정확히 한 번 생성·양쪽 참조 및 Undo/Redo를 확인한다.
- FR-003: 종료 상태 검증은 실제 빈 링 내부 배경·검정 중심·캔버스 크기 보존을 확인한다.
- FR-004: 설치 ZIP 구성과 최신 변경 포함 여부, 격리된 IDE 로딩을 검증한다.
- FR-005: 필요한 런타임·빌드 명령과 SVG 오류 조사 결과, 실제 IDE 수동 확인 한계를 문서화한다.
- FR-006: 설치 정보에서 기본 템플릿 문구를 제거하고 실제 기능·저장소 소유자를 표시한다. 표시 이름은 GlueFramework이며 기존 플러그인 ID와 버전은 유지한다.

### 주요 개체

- 테스트 결과: 사례별 성공·실패·오류·건너뜀과 실행 환경.
- 설치 ZIP: 플러그인 정보, 클래스·리소스·라이선스·의존성과 해시.
- 격리 IDE: 사용자 설정과 분리한 로딩 검증 환경.

## 성공 기준

- SC-001: 전체 자동 검증에서 실패·오류·건너뜀이 각각 0개다.
- SC-002: 최신 설치 ZIP 한 개와 구조 검증 결과를 제공한다.
- SC-003: 격리 IDE 기동 결과와 수동 확인 미수행 여부를 명시한다.

## 가정과 명확화

- 질문 0개. 전체 검증과 설치 파일 제공이 승인됐으며 실제 업무 파일은 제공되지 않았다.
- 제품 동작을 바꾸지 않고 잘못된 테스트 준비·측정 위치만 보완한다. 검사 삭제·무시로 통과시키지 않는다.
- 구조 검사에서 발견된 기본 소개·공급자·이름 오류도 보완한다. 공급자는 Git 원격 저장소의 look4counter, 주소는 실제 저장소 주소를 사용한다. 기능과 파일 형식은 유지한다.
- 기본 의존성 다운로드와 IDE 포함 런타임을 사용한다. 새로운 버전 업그레이드와 사용자 IDE 설치·설정 변경은 제외한다.
- 범위·데이터·상태·상호작용·품질·의존성·용어·수용 기준을 검토했고 중요한 모호함은 없다.
