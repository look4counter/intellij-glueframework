# 기능 명세: SQL 사용자 줄바꿈 보존

작성일: 2026-11-07
상태: 명확화 완료
입력: 포매팅은 사용자가 넣은 줄바꿈을 존중하며 자동 줄바꿈 요청을 공백으로 대체하지 않는다.

## 사용자 시나리오와 검증

### 사용자 이야기 1: 입력한 행 구성 유지 (P1)

한 줄로 작성한 SELECT·WITH·UPDATE·INSERT·MERGE·PIVOT는 한 줄로 포매팅한다. 이미 여러 줄로 나눈 SQL은 같은 토큰 사이의 줄바꿈과 빈 줄을 유지한다. 키워드 대문자·구문 공백·기존 행의 들여쓰기는 정리할 수 있다.

### 사용자 이야기 2: 기존 옵션과 편집 동작 유지 (P1)

이미 여러 줄로 작성한 WHERE·SELECT에는 저장된 등호·AS 정렬을 적용한다. 한 줄의 여러 항목을 정렬하기 위해 새 줄을 만들지 않는다. 선택한 영역만 처리하며 Source와 Undo/Redo를 유지한다.

## 요구사항

- FR-001: 포매터는 입력에 없는 줄바꿈을 추가하지 않고 입력의 줄바꿈을 제거하거나 다른 토큰 사이로 옮기지 않는다. 빈 줄·시작과 끝의 줄바꿈·LF·CRLF를 보존한다.
- FR-002: 같은 줄에서 기존 자동 줄바꿈 요청은 아무것도 추가하지 않는다. 키워드·연산자 등 구문상 필요한 일반 공백 정리는 별도로 유지한다. 콤마 앞과 괄호 안쪽에 줄바꿈 대체 공백을 넣지 않는다. SELECT 항목·절·CASE·CTE·서브쿼리·DML 목록·세미콜론·PIVOT·UNPIVOT에 일관되게 적용한다.
- FR-003: GROUP BY·ORDER BY·INSERT INTO 같은 복합 키워드 사이에 사용자가 넣은 줄바꿈도 유지한다. 문자열·인용 식별자·파라미터 내용과 주석 줄의 앞뒤 공백은 보존한다.
- FR-004: 등호·AS 옵션은 사용자가 만든 행을 기준으로 동작하며 같은 행의 토큰 때문에 새 줄을 추가하지 않는다. 반복 포매팅 결과는 동일하다.
- FR-005: 전체·선택 포매팅에 같은 규칙을 적용하고 선택 경계 줄바꿈을 중복하지 않는다. 선택 밖 SQL·Source 동기화·Undo/Redo·읽기 전용·오류 보호를 유지한다.
- FR-006: 기존 자동 줄바꿈 기대값을 새 계약에 맞춰 갱신하고 한 줄·기존 여러 줄·빈 줄·복합 키워드·주석·리터럴·선택·옵션을 자동 검증하고 사용법을 기록한다.
- FR-007: 서브쿼리 SELECT가 여는 괄호와 같은 줄에 있으면 실제 SELECT 시작 열을 기준으로 이후 행의 FROM·WHERE·AND·GROUP BY·ORDER BY를 정렬한다. SELECT가 다음 줄에 있는 기존 들여쓰기도 유지하며 각 중첩 쿼리의 기준 열은 독립적이다.

## 주요 개체

- 원본 경계: 연속 토큰 사이와 문서 앞뒤의 공백·줄바꿈.
- 출력 행: 원본 경계에 의해서만 생성되며 들여쓰기와 토큰 공백을 정리할 수 있다.

## 성공 기준

- SC-001: 모든 지원 구문의 한 줄 입력 결과에 새 줄이 없고 다중 행 입력의 줄바꿈 토큰 경계가 유지된다.
- SC-002: 주석·리터럴·LF/CRLF·빈 줄·선택 경계와 정렬 옵션·반복 실행 회귀가 통과한다.
- SC-003: 전체 테스트·설치 ZIP·플러그인 구조 검사가 통과한다.

## 가정과 명확화

질문 0개. 사용자가 공백 대체 요청을 취소한 지시를 우선한다. 기존 줄의 들여쓰기를 정리하는 기능과 정렬 옵션은 유지한다. 콤마를 다른 줄로 옮기지 않으며 같은 줄의 SELECT 목록은 `A, B`, 서브쿼리는 `(SELECT ...)`로 정리한다. 공백만 있는 입력도 줄바꿈을 포함해 그대로 보존한다.

서브쿼리 정렬 보완의 명확화 질문 0개. 실제 SELECT의 T 열에 FROM의 M과 WHERE의 E를 맞추며 새로운 줄바꿈을 넣지 않는다.
