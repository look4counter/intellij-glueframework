# 기능 명세: 전체 Datasource 자동 조회

작성일: 2026-10-23

## 사용자 시나리오 및 검증

### 사용자 이야기 1 (P1): 전체 DB 자동완성

사용자는 에디터에서 Datasource를 선택하지 않고 등록된 모든 DB의 테이블과 컬럼을 자동완성으로 사용한다.

수용 조건: 두 DB에 같은 이름이 있으면 후보는 한 번만 표시하고, 서로 다른 이름은 모두 표시한다. 에디터의 Datasource 도구 모음은 표시하지 않는다.

### 사용자 이야기 2 (P1): 시작 시 자동 조회

사용자가 앱에서 프로젝트를 열면 에디터를 열기 전에도 등록된 DB에 접속해 메타데이터를 가져온다.

수용 조건: 시작 시 전체 DB를 백그라운드로 조회한다. 하나가 실패해도 다른 DB 결과는 사용하며, 전체 새로고침과 설정 변경에도 같은 규칙을 적용한다.

## 경계 조건

등록된 DB가 없으면 빈 후보를 제공한다. 설정 변경 전 요청 결과는 폐기한다. 조회 실패 시 기존 성공 캐시는 유지한다. 프로젝트 종료 시 조회를 취소하며 접속 자원을 정리한다. 오류에 비밀번호와 접속 URL을 노출하지 않는다.

## 기능 요구사항

- FR-001: 모든 등록된 Datasource의 테이블·컬럼 이름을 합쳐 같은 문자열 기준으로 중복을 제거한다.
- FR-002: 에디터의 Datasource 선택, 전체 Datasource 표시, 새로고침과 조회 상태를 제거한다.
- FR-003: 프로젝트 시작 시 모든 DB에서 메타데이터를 비동기로 조회한다.
- FR-004: 설정 변경 및 설정 화면의 수동 새로고침 시 저장된 전체 DB를 조회한다. 미적용 변경은 적용 후 조회하도록 안내한다.
- FR-005: DB별 실패를 격리하고 성공 결과와 이전 유효 캐시를 사용한다. 실패 상태를 안전한 메시지로 표시한다.
- FR-006: 오래된 요청 결과를 폐기하며 종료·취소 시 자원을 정리한다.

## 주요 엔터티

Datasource는 접속 정의와 보안 저장소의 비밀번호를 가진다. 메타데이터 스냅샷은 테이블과 컬럼 관계를 보관하고 이름 후보를 제공한다.

## 성공 기준

- SC-001: 두 DB에 걸친 중복 이름의 자동완성 후보 수는 고유 이름 수와 일치한다.
- SC-002: 에디터를 열거나 선택 작업을 하지 않아도 프로젝트 시작 후 모든 등록 DB에 조회를 시도한다.
- SC-003: 한 DB 실패 시 다른 DB 후보를 계속 제공하고 화면 조작이 가능하다.

## 가정 및 명확화

- 앱은 IntelliJ 플러그인이므로 시작 시점은 프로젝트 열기로 해석한다. Datasource 설정은 프로젝트별이다.
- 가져오는 데이터는 기존 기능과 동일하게 테이블·컬럼 메타데이터이며 업무 행 데이터는 포함하지 않는다.
- 이름의 대소문자는 유지하며 정확히 같은 이름만 중복 제거한다.
- 명확화 검토 결과 위 문맥으로 모두 해소되어 추가 질문은 없다.
