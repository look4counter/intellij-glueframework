# 기능 명세: 이동한 직선 위치에서 bendpoint 병합

작성일: 2026-11-18 | 상태: 명확화 완료
입력: bendpoint 자체를 드래그하면 처음 시작한 위치에서만 사라지고 다른 위치에서 일직선이 되어도 남는다.

## 사용자 시나리오 및 검증

### 사용자 이야기 1: 현재 직선 위치에서 마지막 bendpoint 제거 (우선순위 P1)

사용자는 Activity 사이의 마지막 bendpoint를 드래그해 원하는 위치의 직선으로 만든다. 원래 접점 위치로 돌아갈 필요 없이 불필요한 점이 제거되어야 한다.

1. 가로 연결은 원래 위치와 다른 유효한 높이에서도 bendpoint가 사라지고 현재 높이를 유지한다.
2. 세로 연결은 다른 유효한 가로 위치에서도 같은 결과를 유지한다.
3. 직선 연결 가능 범위 밖이거나 시작·끝 도형 내부를 통과하는 경로는 bendpoint를 유지한다.
4. 미리보기와 놓기·원문 재파싱·저장·한 번의 실행 취소 및 다시 실행 결과가 일치한다.

### 경계 조건

기존 5px 병합 임계치와 도형 관통 방지를 유지한다. 여러 점이 있으면 기존처럼 드래그한 점만 삭제하며 다른 점의 위치·weight·사용자 속성을 보존한다. 읽기 전용과 동시 문서 변경 보호를 유지한다. Activity 이동이나 끝점 재연결로 발생한 정리는 범위에 포함하지 않는다.

## 요구사항

- FR-001: 마지막 bendpoint를 드래그해 유효한 직선 연결을 만들면 원래 접점과 다른 위치에서도 점을 제거하고 현재 직선 위치를 유지해야 한다.
- FR-002: 가로·세로 양 방향에서 기존 임계치·접점 제한·관통 방지·여러 점 편집 규칙을 보존해야 한다.
- FR-003: 결과를 원문과 저장에 반영하고 단일 실행 취소·다시 실행 및 기존 편집 보호를 유지해야 한다.

### 주요 개체

Wire는 시작·끝 Activity와 접점 및 bendpoint 목록을 가진다. 마지막 점이 제거되면 현재 드래그 위치가 직선 접점의 기준이 된다.

## 성공 기준

- SC-001: 원래 위치와 다른 가로·세로 직선 위치의 재현 테스트가 모두 통과한다.
- SC-002: 저장·실행 취소 및 기존 기하·편집 회귀에서 이 변경으로 인한 실패가 없다.

## 가정 및 명확화

질문 1개, 답변 1개. 사용자는 bendpoint 자체를 드래그할 때 발생한다고 확인했고 최초 위치에서는 사라지지만 다른 일직선 위치에서 남는다고 추가 설명했다. 핵심 범위와 경계 조건은 명확하며 형식과 UI 변경은 없다. 자동 회귀를 추가한다.
