# 조사 결과

결정: 마지막 점을 없앤 Activity 직선 후보는 현재 드래그 위치를 접점 기준으로 사용한다.
근거: DiagramGeometry.endpoints는 겹치는 축에서 firstRelativePoint를 직선 위치로 사용한다. 현재 코드는 제거 후보에 과거 기준을 남겨 현재 포인터와의 거리가 5px를 초과하면 화면의 직선과 무관하게 거부한다.
대안: 임계치 확대는 실제 꺾임을 제거할 수 있고 다른 점 전체 정리는 사용자 확인 범위 밖이므로 채택하지 않는다. 기존 관통 방지를 유지한다.

마지막 Activity 점을 제거한 후보는 기존 직결 이동과 동일하게 explicitContacts를 해제해 현재 좌표에서 양쪽 외곽 접점을 다시 계산한다. 기존 접점 좌표를 강제로 유지하지 않는다. 5px는 과거 직선 위치가 아니라 현재 위치로 계산한 유효 직선 후보로부터의 거리다. 그 때문에 과거 접점에서 6px 떨어졌다는 이유만으로 점을 유지하던 회귀 기대를 현재 유효 범위 밖의 거리 검증으로 갱신한다.
