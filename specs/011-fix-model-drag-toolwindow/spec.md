# 기능 명세: 모델 드래그 스레드 오류 및 Tool Window ID 충돌 수정

**작성일**: 2026-10-26
**입력**: modeleditor의 Wire·Child 드래그 시 쓰기 스레드 오류, MyToolWindow 초기화 시 같은 ID가 이미 등록됐다는 오류가 발생한다.

## 사용자 시나리오 및 검증

### 사용자 이야기 1: 모델 연결과 노드 드래그 (우선순위 P1)

사용자는 Wire의 연결점·꺾임점을 드래그하거나 Child를 이동·크기 조절한다. 놓을 때 문서에 반영하며 스레드 오류가 발생하지 않아야 한다.

1. 잠금 없는 UI 이벤트에서 Child 이동·크기 조절을 완료하면 위치·너비가 저장된다.
2. 잠금 없는 UI 이벤트에서 Wire를 편집하면 연결·꺾임이 저장된다.
3. 변경은 실행 취소·재실행과 저장을 지원한다.

### 사용자 이야기 2: 충돌 없는 Tool Window 초기화 (우선순위 P1)

플러그인의 Tool Window는 공통 샘플 이름 MyToolWindow를 쓰는 다른 등록과 충돌하지 않는다. 기존 팩토리와 화면을 유지한다.

1. MyToolWindow가 이미 존재해도 플러그인 고유 ID의 창을 등록할 수 있다.
2. 새 ID의 표시 이름 리소스와 팩토리가 배포본에 포함된다.

### 경계 조건

- 드래그 시작 후 또는 놓기와 예약 실행 사이에 원문이 바뀌면 이전 결과를 덮어쓰지 않는다.
- 편집기·프로젝트 폐기와 읽기 전용 변경 뒤 예약 작업은 안전하게 취소한다.
- 다음 드래그가 시작돼도 이전 요청의 문서 기준 시점을 바꾸지 않는다.
- 기존 모양·메타데이터·선택·미리보기·저장 형식을 보존한다.

## 요구사항

- **FR-001**: Child 이동·크기 조절 및 Wire 드래그 완료가 쓰기 스레드 오류 없이 동작해야 한다.
- **FR-002**: 예약 요청은 드래그 당시 문서 변경 시점을 유지하고 원문 변경·폐기·읽기 전용 시 덮어쓰지 않아야 한다.
- **FR-003**: 기존 실행 취소·재실행·저장·연결 정보와 도형 동작을 보존해야 한다.
- **FR-004**: Tool Window는 플러그인에 고유한 ID로 등록하고 표시 이름을 올바르게 제공해야 한다.
- **FR-005**: 고유 ID 등록과 기존 팩토리·화면 리소스가 설치용 ZIP에 포함돼야 한다.

## 주요 개체

- 드래그 요청: 기존 노드·연결 변경 값과 드래그 시작 문서 변경 시점을 가진다.
- Tool Window: 플러그인 고유 ID, 기존 Factory, 표시 이름을 가진다.

## 성공 기준

- **SC-001**: 잠금 없는 실제 마우스 드래그와 원문 변경 취소 회귀 검증이 통과한다.
- **SC-002**: 기존 모델 드래그·속성 테스트와 Tool Window 충돌·메타데이터 검증이 통과한다.

## 가정 및 명확화

2026-10-26: 사용자가 Tool Window의 직접 원인으로 MyToolWindow ID 중복을 제공했다. 창을 제거하지 않고 고유 ID로 변경한다. 드래그 오류는 이동·너비 변경·Wire 편집의 완료 경로에 한정하여 수정한다. 추가 질문 없이 기존 동작을 보존하며 자동 회귀 검증을 추가한다.
