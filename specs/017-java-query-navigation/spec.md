# 자바 문자열 쿼리 탐색 명세

작성일: 2026-11-03 | 상태: 명확화 완료

## 사용자 시나리오와 검증

### 사용자 이야기 1 — 문자열에서 쿼리로 이동 (우선순위 P1)

개발자는 자바 문자열에 있는 쿼리 ID를 Ctrl+클릭하여 선언 위치와 해당 쿼리 편집기로 이동한다.
독립 검증: 자바 문자열의 참조 대상을 해석하고 검색 이동과 동일한 편집기 탐색을 수행한다.

1. 쿼리 ID와 문자열 값이 정확히 일치하면 해당 쿼리 선언으로 이동한다.
2. 같은 ID가 여러 선언에 있으면 모든 후보를 제공하고 사용자가 선택한다.
3. 존재하지 않는 ID와 부분 일치 문자열은 쿼리 탐색 대상을 제공하지 않는다.

### 경계 조건

이스케이프가 있는 자바 문자열은 실제 문자열 값으로 비교한다. 빈 문자열, 숫자·문자 리터럴, 주석은 대상에서 제외한다. 자바 텍스트 블록은 실제 값이 정확히 일치할 때 지원한다. 파일 삭제·ID 변경 후 오래된 선언으로 이동하지 않는다. 탐색 중 소스 수정이나 쓰기 스레드 오류가 발생하지 않아야 한다.

## 기능 요구사항

- FR-001: 자바 문자열의 전체 값과 대소문자까지 정확히 일치하는 쿼리 ID에 Ctrl+클릭 탐색을 제공한다.
- FR-002: 중복 ID는 모든 유효한 선언을 후보로 제공한다.
- FR-003: 누락·부분 일치·빈 값·문자열 이외 요소는 쿼리 탐색을 제공하지 않고 오류 표시를 추가하지 않는다.
- FR-004: 기존 쿼리 색인의 갱신과 파일 유효성을 반영하며 탐색 해석은 쓰기나 문서 커밋 없이 실행한다.
- FR-005: 선택한 선언으로 이동하면 기존 쿼리 편집기의 대상 선택 기능을 재사용하고 원문을 변경하지 않는다.

## 성공 기준

- SC-001: 정확 일치·중복·음성 사례·이스케이프·변경과 삭제의 자동 검증이 모두 통과한다.
- SC-002: 읽기 액션과 잠금 없는 탐색을 거쳐도 스레드 오류가 0건이다.
- SC-003: 관련 기존 쿼리 색인·탐색 테스트와 컴파일이 통과한다.

## 가정과 명확화

사용자의 자바 문자열은 전체 값이 쿼리 ID인 일반적인 사용 사례로 해석한다. 임의 문자열 내부의 부분 일치와 런타임 문자열 연결·변수 값 추론, 자동 완성, 이름 변경 기능은 범위에 포함하지 않는다. 대상 파일은 기존 색인의 프로젝트 내 .glue_sql 파일이다. 추가 질문이 필요한 불명확한 결정은 없다.
