# 조사 결과

- 결정: 기존 SqlLexer와 메타데이터 구조를 재사용한다. 근거: MetadataSnapshot.tables에 스키마·테이블별 columns가 이미 있으며 현재 완성기는 이를 평탄화해 모든 구역에 제공한다. 새 JDBC 조회나 저장 형식 변경이 필요 없다.
- 결정: 토큰·괄호·쿼리 블록을 분석하는 관대한 구조를 구현한다. 근거: SELECT 커서 뒤의 FROM과 미완성 입력을 처리해야 하므로 앞쪽 정규식만으로는 부족하다. 엄격한 외부 파서는 미완성 입력 복구와 새 의존성을 요구하므로 채택하지 않는다.
- 결정: CTE를 해당 범위의 관계로 등록하고 명시적 컬럼·SELECT 별칭·직접 컬럼·별표를 추론한다. 일반 CTE 내부에는 앞선 정의만 보이고 메인 쿼리에는 정의가 모두 보인다. 재귀 출력은 명시적 목록을 우선하고 방문 집합으로 순환을 차단한다.
- 결정: 안쪽 별칭을 먼저 찾고 상관 서브쿼리만 바깥 관계를 참조한다. 일반 파생 테이블에서는 바깥 별칭을 유출하지 않는다. 별칭이 있으면 원래 테이블명으로 그 별칭을 우회하지 않는다.
- 결정: 같은 이름의 컬럼은 삽입 문자열에 관계 한정자를 넣되 원래 컬럼명도 검색 문자열로 등록한다. 이미 점 앞 한정자가 있으면 컬럼명만 삽입한다.
- 결정: 기존 따옴표·주석·숫자·파라미터 보호를 유지하고 인용 식별자는 이미 작성된 이름을 해석하는 데 사용한다. 모르는 한정자에는 일반 메타데이터를 섞지 않는다.

## 근거 문서

[PostgreSQL 테이블 표현식 문서](https://www.postgresql.org/docs/current/queries-table-expressions.html)는 별칭과 서브쿼리 범위를 설명한다. [PostgreSQL SELECT 문서](https://www.postgresql.org/docs/12/sql-select.htm)는 WITH의 명시적 컬럼 이름과 생략 시 출력 이름 추론을 설명한다. 이 문서는 일반 범위 모델의 근거이며 모든 DB 전용 문법 지원을 의미하지 않는다.

미해결 기술 질문은 없다.
