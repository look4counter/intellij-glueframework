# 기능 명세: SQL 문맥 자동완성

작성일: 2026-11-07
상태: 명확화 완료
입력: QueryEditor에서 SQL 구역에 맞게 테이블·컬럼을 추천하고 테이블 별칭과 WITH의 CTE를 인식한다.

## 사용자 시나리오와 검증

### 사용자 이야기 1: 구역에 맞는 후보 (우선순위 P1)

사용자는 SELECT·WHERE·ON·GROUP BY·HAVING·ORDER BY에서는 사용 중인 컬럼을, FROM·JOIN에서는 테이블을 추천받는다.
독립 검증: 같은 SQL의 커서를 각 구역으로 이동해 후보 종류와 선택 후 저장 내용을 비교한다.

1. SELECT 커서 뒤에 FROM이 있어도 그 테이블의 컬럼을 추천하고 다른 테이블의 컬럼은 제외한다.
2. FROM·JOIN에서는 테이블과 유효한 CTE를 추천하고 컬럼은 제외한다.
3. 키워드·대소문자 무시 접두 검색과 기존 선택 쿼리 편집·저장·Undo/Redo를 유지한다.

### 사용자 이야기 2: 별칭과 쿼리 범위 (우선순위 P1)

사용자는 emp e 또는 emp AS e의 e. 뒤에서 emp 컬럼만 추천받는다.
독립 검증: 여러 테이블·스키마·중첩 쿼리에서 별칭의 대상과 범위를 확인한다.

1. e. 뒤에서는 해당 테이블 컬럼만 삽입하고 기존 e.는 보존한다.
2. 같은 컬럼명이 여러 테이블에 있으면 e.id·d.id처럼 구분해 삽입한다.
3. 안쪽 쿼리가 같은 별칭을 선언하면 안쪽 대상을 우선한다. 상관 서브쿼리는 가려지지 않은 바깥 별칭을 참조할 수 있고 형제 쿼리·다른 SQL 문장의 별칭은 유출하지 않는다.
4. 스키마를 붙인 테이블과 따옴표로 감싼 기존 식별자를 인식한다. 알 수 없는 별칭 뒤에서 무관한 테이블의 컬럼은 추천하지 않는다.

### 사용자 이야기 3: CTE와 파생 테이블 (우선순위 P1)

사용자는 WITH로 정의한 결과와 서브쿼리를 테이블처럼 자동완성한다.
독립 검증: CTE 이름·출력 컬럼·명시적 컬럼 목록·별칭·중첩 범위를 확인한다.

1. WITH active_emp AS (SELECT empno, ename FROM emp) 뒤의 FROM에서는 active_emp를, a.에서는 empno·ename을 추천한다.
2. CTE의 명시적 컬럼 목록을 우선하고 SELECT 출력 별칭과 확인 가능한 별표를 반영한다.
3. 여러 CTE에서 앞선 정의를 참조하고 안쪽 WITH가 같은 이름을 재정의하면 안쪽 정의를 우선한다.
4. 파생 테이블의 별칭에는 해당 SELECT가 출력하는 컬럼만 추천한다. 재귀 CTE는 명시된 출력 이름이나 확인 가능한 초기 SELECT를 활용하며 순환 분석으로 멈추지 않는다.

### 경계 조건

- 작성 중인 접두어·비어 있는 선택 목록·닫히지 않은 괄호에서도 가능한 범위를 분석한다.
- 문자열·주석·숫자·파라미터 안과 읽기 전용 편집기에서는 후보를 표시하지 않는다.
- 문맥을 판단할 수 없는 SQL에서는 기존 키워드·메타데이터 자동완성을 유지한다. 컬럼 구역에서 아직 테이블을 확인할 수 없으면 캐시의 컬럼을 사용하며 테이블은 섞지 않는다.
- 메타데이터가 없어도 키워드와 SQL 자체에 명시된 CTE·출력 이름은 사용할 수 있다.
- 매우 깊거나 긴 입력은 제한 내에서 분석을 중단하고 일반 후보로 복구한다. 자동완성은 DB에 접속하거나 문서를 변경하지 않는다.

## 요구사항

### 기능 요구사항

- FR-001: 커서가 있는 SELECT·FROM·JOIN·ON·WHERE·GROUP BY·HAVING·ORDER BY 구역을 구분해 컬럼 또는 테이블 후보를 제공한다.
- FR-002: 커서 뒤의 테이블 선언도 읽고 AS 유무와 스키마·인용 식별자를 인식한다.
- FR-003: 별칭 뒤에는 그 대상의 컬럼만 추천하고 점 앞부분은 보존한다. 모르는 별칭에는 무관한 후보를 넣지 않는다.
- FR-004: 중첩·상관 쿼리의 범위와 별칭 가림을 지키고 형제·다른 문장의 이름을 유출하지 않는다.
- FR-005: 유효 범위의 CTE와 명시적 컬럼·출력 별칭·확인 가능한 별표, 앞선 CTE 참조 및 파생 테이블 별칭을 반영한다.
- FR-006: 같은 컬럼명이 여러 대상에 있으면 별칭 또는 테이블명으로 구분해 삽입한다.
- FR-007: 불완전·미지원 SQL·메타데이터 부재·순환·과도한 입력에 안전하게 복구하며 자동완성 중 DB 조회나 문서 쓰기를 하지 않는다.
- FR-008: 기존 키워드·접두 검색·읽기 전용·주석·문자열·숫자·파라미터 보호와 선택 쿼리 저장·Undo/Redo를 유지한다.
- FR-009: 분석과 실제 편집기 통합 회귀 검증을 추가하고 지원 범위와 제한을 문서화한다.

### 주요 개체

- SQL 범위: 문장·쿼리 블록·바깥 범위와 그 위치.
- 관계: 실제 테이블·CTE·파생 테이블과 별칭·출력 컬럼.
- 자동완성 후보: 삽입 문자열·검색 이름·종류·출처.

## 성공 기준

- SC-001: 구역·별칭·CTE·범위·모호한 컬럼·불완전 입력의 필수 자동 검증이 모두 통과한다.
- SC-002: 실제 편집기에서 후보 선택 후 SQL과 Source가 일치하고 Undo/Redo가 유지된다.
- SC-003: 기존 전체 회귀 검증에서 실패·오류·건너뜀이 0개이며 설치 ZIP 구조 검사를 통과한다.

## 가정과 명확화

- 질문 0개. 대화에서 승인한 기본 SELECT 문맥·별칭·일반 WITH를 우선하고 파생 테이블과 중첩 범위를 함께 처리한다.
- DB별 전체 문법·타입 추론·SQL 실행·서버 측 구문 검증은 범위 밖이다. 별칭 없는 계산식의 출력 이름은 임의로 만들지 않는다.
- 메타데이터는 기존 전체 데이터 소스 캐시를 사용한다. 스키마 없는 같은 테이블명이 여러 데이터 소스에 있으면 관련 컬럼을 합치며 스키마를 지정하면 대상을 좁힌다.
- 따옴표 안을 편집하는 중의 자동완성 금지는 유지하되 이미 작성된 인용 테이블·별칭은 해석한다.
- 깊이·길이 제한과 복잡한 재귀·DB 전용 구문의 일반 후보 복구를 문서화한다.

## 인접 파생 테이블 별칭 보완

- FR-010: 작성 중인 FROM에 두 파생 테이블이 구분자 없이 이어져도 A와 B의 출력 컬럼을 각각 분리한다. A 뒤의 다음 SELECT 괄호를 A의 명시적 컬럼 목록으로 오인하지 않는다.
- 수용 기준: 사용자 예제의 A. 후보는 DEPT·JOB·SALARY이며 B. 후보는 DEPT2·JOB·SALARY다. DB 메타데이터 없이도 동작하고 실제 후보 선택은 한정자를 유지한다. 정상적인 A(col1,col2) 명시 목록과 JOIN·중첩 범위는 유지한다.
- 명확화 질문 0개. 입력 중 구분자 누락을 관대하게 해석하되 원문을 수정하지 않는다.

## 두 번째 SELECT 항목의 별칭 검증

- FR-011: `SELECT A.DEPT , B.`에서 두 번째 항목 B의 점 바로 뒤에 커서를 두면 B의 출력 컬럼 DEPT2·JOB·SALARY만 제시한다. A의 DEPT는 포함하지 않고 선택 시 B 한정자와 앞의 A.DEPT를 보존한다.
- 명확화 질문 0개. 사용자가 제공한 줄바꿈·선행 쉼표·인접 파생 테이블 형태를 그대로 검증한다. 기존 수정으로 충족하면 불필요한 운영 코드 변경 없이 검증 결과와 설치 파일을 제공한다.
