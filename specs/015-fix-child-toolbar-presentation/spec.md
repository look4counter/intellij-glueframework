# 기능 명세: Child 생성 툴바 초기화 오류 수정

**작성일**: 2026-10-27
**상태**: 명확화 완료
**입력**: 시작 시 발생하는 Trying to reset custom component in a presentation 오류를 커스텀 액션 구성으로 수정한다.

## 사용자 시나리오와 검증

### 사용자 이야기 1 — 오류 없이 생성 툴바 사용 (우선순위: P1)

사용자는 ModelEditor를 처음 열거나 여러 에디터를 전환할 때 오류 없이 Child 생성 툴바를 사용한다.

**독립 검증**: 커스텀 컴포넌트를 등록한 상태로 생성 컨트롤의 표시 갱신을 반복하고 두 에디터의 컴포넌트가 각각 유지되는지 확인한다.

1. 생성 버튼을 처음 만들고 반복 갱신해도 등록된 UI 컴포넌트가 제거·교체되지 않고 보고된 오류가 발생하지 않는다.
2. 생성 모드 켜기·끄기, Child 종류 선택, 프리셋 선택과 표시 이름·아이콘·선택 상태가 유지된다.
3. 읽기 전용에서는 기존과 같이 생성 버튼과 종류 선택이 비활성화되며 편집 가능 상태로 돌아오면 복원된다.
4. 두 에디터가 서로 다른 종류나 프리셋을 선택해도 상태와 UI 컴포넌트가 섞이지 않는다.

### 경계 조건

첫 갱신, 컴포넌트 생성 전 갱신, 반복 새로고침, 프리셋 변경·삭제, 편집 가능 상태 변경을 다룬다. 기존 Wire·Snap·Properties·Commit·Rollback과 생성 메뉴는 유지한다.

## 요구사항

- **FR-001**: 생성 컨트롤 갱신은 기존 커스텀 컴포넌트 등록을 보존하고 보고된 초기화 오류를 발생시키지 않아야 한다.
- **FR-002**: 현재 생성 종류·프리셋·생성 모드·편집 가능 상태를 기존과 같이 표시하고 처리해야 한다.
- **FR-003**: 에디터별 컴포넌트와 상태를 분리하고 기존 종류 선택 메뉴와 다른 툴바 버튼을 보존해야 한다.
- **FR-004**: 오류를 숨기지 않고 원인 경로를 제거하며 회귀 및 툴바 초기화 실행 로그로 검증해야 한다.

## 성공 기준

- **SC-001**: 두 툴바에서 컴포넌트 등록 후 표시 갱신을 각각 10회 반복해도 같은 컴포넌트를 유지한다.
- **SC-002**: 생성 모드·종류·프리셋·읽기 전용 및 기존 툴바 회귀가 모두 통과한다.
- **SC-003**: 검증을 시작한 이후의 IDE 로그에 보고된 컴포넌트 초기화 오류와 해당 툴바 갱신 오류가 없다.

## 가정 및 명확화

기존 텍스트 버튼과 종류 선택 화살표의 UI 및 조작을 유지한다. 사용자와 합의한 커스텀 액션 구성 변경만 수행하며 Canvas 최적화와 저장 동작은 수정하지 않는다. 범위·사용 흐름·실패 정책·완료 기준에 추가 질문이 필요한 모호함은 없다.
