# 기능 명세: SQL 위치 파라미터 색상과 번호 힌트

**작성일**: 2026-10-26
**상태**: 명확화 완료
**입력**: queryeditor에서 ? 파라미터도 :param과 같은 cyan 색상으로 표시하고 몇 번째 물음표인지 IntelliJ 힌트로 보여준다.

## 사용자 시나리오와 검증

### 사용자 이야기 1 - 위치 파라미터 구분 (우선순위: P1)

사용자는 물음표 파라미터를 이름 있는 파라미터와 같은 색으로 구분하고 바인딩 순서를 읽는다.
우선순위 근거는 SQL 위치 파라미터의 가독성과 순서 확인이다.
독립 검증은 SQL 편집기의 실제 토큰 색상과 각 물음표 위치의 번호 힌트를 비교한다.

1. SQL의 ?는 :param과 같은 cyan 계열로 표시한다.
2. 실제 ? 파라미터 앞에 0:, 1:, 2: 형태의 IntelliJ 인레이 번호 힌트를 표시한다.
3. 추가·삭제·쿼리 선택 변경 및 실행 취소 시 현재 SQL 기준으로 번호를 다시 매긴다.
4. 문자열·인용 식별자·주석 안의 물음표는 색상 분류와 번호 계산에서 제외한다.

### 경계 조건

여러 줄, 물음표 0개, 연속 물음표, 미완성 문자열·주석, :param과 혼용, 쿼리 전환 및 편집기 해제를 포함한다.
문자열·주석 인식은 기존 SQL lexer의 범위와 동일하다. 별도 SQL 방언 연산자 판별은 추가하지 않는다.

## 요구사항

- **FR-001**: ? 위치 파라미터는 기존 :param과 동일한 cyan 색상 규칙을 적용한다.
- **FR-002**: 선택된 SQL 안의 실제 ?에 등장 순서대로 0부터 시작하는 인레이 번호를 표시한다.
- **FR-003**: 문자열·인용 식별자·주석과 이름 파라미터는 물음표 순번에 포함하지 않는다.
- **FR-004**: 문서 편집·쿼리 전환·실행 취소 시 번호를 갱신하고 SQL 원문과 XML 저장 내용을 변경하지 않는다.
- **FR-005**: 편집기 해제 시 리스너와 힌트를 정리하고 기존 색상·자동완성·저장 동작을 보존한다.

### 주요 개체

위치 파라미터는 SQL 토큰 위치와 순번을 가진다. 힌트는 편집기의 표시 요소이며 SQL 문서에 저장하지 않는다.

## 성공 기준

- **SC-001**: 밝은·어두운 테마에서 ?와 :param의 색상 값이 같다.
- **SC-002**: 모든 실제 물음표에 1개씩 연속 순번 힌트가 있고 제외 영역의 힌트는 0개다.
- **SC-003**: 편집·전환·실행 취소 후 표시와 SQL 저장 회귀 검증이 통과한다.

## 가정과 명확화

번호 범위는 현재 선택한 쿼리의 SQL 전체다. 이름 파라미터와 세미콜론은 번호를 초기화하지 않는다.
표시 형식은 물음표 앞의 0: 형태로 정한다. 기존 파라미터 색상의 밝고 어두운 테마 팔레트를 재사용한다.
사용자 요구와 기존 lexer로 범위가 명확하여 추가 질문은 0건이다.


## 순번 시작값 수정

사용자의 후속 요청에 따라 첫 힌트는 0:, 다음은 1:로 표시한다. 번호 범위와 문자열·주석 제외 및 SQL 저장 보존은 그대로 유지한다.
추가 모호함이 없어 명확화 질문은 0건이다.
