# 기능 명세: 비정상 Wire를 제외한 Service XML 저장

**작성일**: 2026-10-26
**상태**: 명세 검토 완료
**입력**: modeleditor에서 service.xml 저장 시 비정상 Wire 때문에 오류를 내지 말고 해당 Wire만 무시하고 저장한다.

## 사용자 시나리오 및 검증

### 사용자 이야기 1: 정상 연결을 보존하며 저장 (우선순위: P1)

사용자는 미완성 연결이 있는 다이어그램도 저장하고 정상 Activity와 연결을 Service XML로 생성한다. 저장 전체가 중단되지 않는 것이 목표다. 정상·비정상 Wire가 섞인 모델을 저장하여 독립 검증한다.

1. 비정상 Wire가 섞여 있으면 해당 연결만 제외하고 정상 전이·Activity·속성을 저장한다.
2. 저장을 반복해도 같은 결과가 나오고 원본 다이어그램은 바뀌지 않는다.
3. 기존 출력 파일이 열려 있어도 제외 결과를 파일과 열린 문서에 반영한다.

### 경계 조건

- 끝점 누락, 한 Wire를 여러 번 또는 여러 Child에서 참조, 금지된 State 방향 및 State끼리 연결은 해당 Wire를 제외한다.
- 잘못된 형식이나 범위 밖 참조는 건너뛰되 같은 Child의 정상 연결은 유지한다.
- 유효한 시작 연결이 없거나 여러 개라 모호하면 시작 Activity를 임의 선택하지 않고 빈 initial로 저장한다.
- 비정상 Wire가 전부여도 Activity와 속성은 저장한다.
- Activity 이름·class, Child 식별자·종류, InitialState 개수, 트랜잭션 값, XML 문법 등 연결 외 오류는 기존 검증과 출력 보호를 유지한다.

## 요구사항

### 기능 요구사항

- **FR-001**: 비정상 Wire 또는 잘못된 참조로 저장 전체를 실패시키거나 오류 알림을 표시하지 않아야 한다.
- **FR-002**: 비정상 Wire만 제외하고 정상 전이·Activity·속성·출력 순서를 유지해야 한다.
- **FR-003**: 유효한 시작 연결이 하나면 기존 initial을 유지하고, 없거나 모호하면 빈 initial로 저장해야 한다.
- **FR-004**: 원본을 바꾸지 않고 열린 출력 문서와 디스크를 갱신하며, 연결 외 오류에서는 기존 출력을 보존해야 한다.

### 주요 개체

- Wire: 선언 순서 인덱스로 참조하는 연결이며 원본에는 유지하고 출력 대상만 판단한다.
- Service XML: 기존 Activity·transition·property와 initial을 가지는 생성 파일이다.

## 성공 기준

- **SC-001**: 각 비정상 유형과 정상 Wire가 혼합된 회귀 검증이 모두 통과한다.
- **SC-002**: 기존 정상 출력·출력 순서·자동 저장·연결 외 오류 보호 검증이 모두 통과한다.

## 가정

- 범위는 glue_uml_ad 저장 시 생성하는 Service XML이다. Service XML 직접 편집 모드의 Commit 규칙은 포함하지 않는다.
- 추가 경고창이나 확인창 없이 제외한다.
- 시작점이 없을 때 기존 Service 읽기에서 허용하는 빈 initial을 사용한다.
- 자동 회귀 테스트를 추가한다.
