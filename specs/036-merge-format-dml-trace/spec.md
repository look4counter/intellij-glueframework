# 기능 명세: MERGE 정렬과 변경문 내부 SELECT 컬럼 추적

작성일: 2026-11-08
상태: 구현 및 검증 완료
입력: MERGE 예시 정렬, 대소문자 보존 및 UPDATE·INSERT 등 변경문 안의 SELECT 컬럼 추적.

## 사용자 시나리오와 검증

### 사용자 이야기 1: MERGE 정렬 (P1)

기존 줄바꿈을 유지한 채 MERGE를 정렬한다. MERGE는 0칸, 별도 행의 INTO는 1칸, USING·ON·WHEN·UPDATE·INSERT·VALUES와 바깥 닫는 괄호는 0칸이다. USING의 SELECT는 4칸·FROM은 6칸·SELECT 콤마는 9칸, ON 본문은 4칸, SET은 3칸·콤마는 5칸이다. INSERT·VALUES 목록 첫 항목은 6칸·콤마는 4칸이다. 모든 SQL의 원래 대소문자를 유지한다.

인수 기준: 사용자 예제의 정확 결과와 멱등성이 일치하고 한 줄 MERGE에 줄바꿈을 추가하지 않는다. 기존 포맷·주석·문자열·선택·Undo 보호를 유지한다.

### 사용자 이야기 2: 변경문 내부 SELECT 추적 (P1)

UPDATE SET의 스칼라 SELECT, UPDATE FROM의 파생 SELECT, INSERT SELECT 및 MERGE USING의 SELECT 안에서 컬럼을 선택하면 SELECT·CTE·파생 쿼리 사이의 컬럼 전달 경로를 보여준다. 변경문 컬럼 참조는 대입 관계가 아니라 자신의 테이블·SELECT 출처를 추적하며 선택한 참조 자체도 포함한다. VALUES 상수는 컬럼 참조가 아니다.

인수 기준: SELECT 원본·중간 CTE·파생 출력에서 같은 경로를 확인하고 선택하지 않은 대입 반대편이 섞이지 않는다. MERGE a.deptno는 INTO emp a 선언과 선택한 참조를, b.TEST는 USING SELECT의 TEST 출력과 선택한 참조를 표시한다. SET 좌변·INSERT 대상도 자신의 소스를 추적하고 다른 컬럼과 대입 관계로 연결하지 않는다. WHERE·ON 조건 서브쿼리는 기존처럼 전달 경로에서 제외한다.

## 요구사항

- FR-001: 예시 MERGE 들여쓰기와 기존 줄바꿈·주석·리터럴·이름을 보존하고 반복 결과가 같아야 한다.
- FR-002: UPDATE·INSERT·MERGE 내부 SELECT의 기존 슬롯 기반 경로를 유지한다. 변경문 컬럼은 자신의 소스만 추적하고 대입되는 다른 컬럼과 연결하지 않는다.
- FR-003: CTE·파생 출력·별표·별칭·인용 식별자를 기존 SELECT 규칙으로 구분하고 불명확한 출처를 확정 경로로 만들지 않는다.
- FR-004: 테이블 추적 우선순위·기존 SELECT 트리·탐색과 조건 서브쿼리 격리를 유지한다. 변경문에서 물리 테이블을 참조하는 컬럼은 해당 테이블 선언 위치를 출처로 표시한다.
- FR-005: DB 호출 없이 현재 SQL만 분석하고 길이·토큰·깊이·취소 한도와 문장 격리·문자열·주석 차단을 유지한다.
- FR-006: 정확 포맷·멱등성·줄바꿈 및 변경문 내부 SELECT의 연결·격리·기존 UI 동작을 자동 검증한다.
- FR-007: 모든 SQL 포맷에서 키워드·식별자·함수·별칭의 원래 대소문자를 보존한다. 구문 판별만 대소문자를 구분하지 않는다.

## 주요 개체

변경문은 SELECT 위치와 소스의 가시 범위를 판단하는 문맥이다. 추적 노드는 SELECT 출력·CTE·파생 쿼리 컬럼, 변경문의 물리 테이블 출처 및 현재 선택한 컬럼 참조를 사용한다. 대입 관계나 상수 대입 노드는 만들지 않는다.

## 성공 기준

- SC-001: 사용자 MERGE 예제와 정확히 일치하고 대소문자·줄바꿈 회귀가 통과한다.
- SC-002: 변경문 컬럼 참조에 올바른 소스 선언 또는 SELECT 출력과 선택한 참조가 함께 표시되고 대입의 반대편 컬럼이 섞이지 않는다.
- SC-003: 관련 포맷·컬럼·테이블 추적·자동완성·컬럼 검사·실제 편집기 회귀가 통과한다.

## 가정과 명확화

사용자 답변: 기존 줄바꿈을 유지하며 정렬만 적용한다. 후속 요청: 포매팅 시 대소문자를 바꾸지 않는다. 최신 명확화: “내 의도는 select문을 추적하는거거든”. 따라서 앞선 대입·삽입 대상 계보 구현은 잘못 해석한 범위이며 이번 명세로 대체한다. 일반 SELECT는 028의 출력 단계와 조건절 제외 규칙을 유지하고, 변경문 컬럼은 최신 명확화에 따라 소스와 선택한 참조를 표시한다. DB별 전체 문법·동적 SQL 문자열 내부는 범위 밖이다.

## 최신 명확화: 컬럼의 소스와 선택 위치

사용자 예제에서 a.deptno는 2행의 INTO emp a로 추적되어야 하며 a.deptno·b.TEST 모두 선택한 자기 자신도 추적에 포함해야 한다. 이전의 쓰기 대상 제외·SELECT 밖 참조 숨김 결정은 이 명확화로 대체한다.

- FR-008: 변경문 컬럼의 경로는 자기 소스의 선언·SELECT 전달 단계와 현재 선택한 컬럼 참조를 포함한다. SET 좌변과 INSERT 대상도 같은 규칙을 사용하며, 대입 우변과 연결하지 않는다. 한정자가 없는 SET 좌변·INSERT 대상은 대상 테이블 문맥으로 해석하고, 모호한 일반 입력 참조는 임의로 확정하지 않는다.

인수 기준: 제공된 예제의 a.deptno 각 참조는 2행과 해당 선택 행을, b.TEST는 4행과 해당 선택 행을 표시한다. 선택 위치가 트리 선택·이동 앵커가 된다.
## 최신 명확화: 출처부터 모든 참조와 값 선택

사용자 요청: 4행 TEST를 선택해도 13행 b.TEST가 보여야 하며, 실제 값인 'B'를 선택해도 TEST를 추적해야 한다.

- FR-009: 현재 문장 안에서 SELECT 출력·CTE·파생 컬럼 및 그 소스를 참조하는 변경문 컬럼을 미리 연결한다. 출처·중간·사용처 어디를 선택해도 같은 출처의 모든 참조를 표시한다. 같은 이름이어도 다른 소스·슬롯·문장은 섞지 않으며 대입 좌우를 연결하지 않는다.
- FR-010: SELECT 출력 표현식 안의 리터럴·숫자·파라미터 등 값 토큰을 선택하면 해당 출력 컬럼을 기준으로 전체 경로를 추적한다. SELECT 표현식 밖 문자열·주석·단순 VALUES 값은 추적을 시작하지 않는다. 표현식의 별칭과 값은 같은 출력 슬롯을 사용한다.

인수 기준: 사용자 MERGE에서 TEST·'B'·b.TEST 모두 4행과 13행을 표시한다. a.deptno 두 참조는 어디를 선택해도 2행·13행·19행 전체를 표시한다. 선택한 컬럼 참조는 자기 노드를, 값 선택은 해당 SELECT 출력 노드를 트리 선택 기준으로 사용한다.
