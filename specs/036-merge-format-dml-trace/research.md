# 조사 기록

포매터의 Writer는 원문 토큰 경계의 줄바꿈만 출력한다. MERGE의 USING·ON·SET과 목록 기준을 정리하고 출력 토큰의 대소문자를 보존한다.

컬럼 추적의 목적은 SELECT 출력 전달이다. 기존 테이블 추적용 includeDml 파서는 변경문 내부 SELECT와 소스를 이미 발견하므로 이를 컬럼 추적에서도 사용한다. UPDATE SET의 스칼라 SELECT·UPDATE FROM 파생 SELECT·INSERT SELECT·MERGE USING SELECT는 기존 SELECT 그래프를 재사용한다. WHERE·ON 조건 서브쿼리는 제외한다.

처음에 구현한 대입·삽입 대상 연결은 사용자 의도와 달라 제거했다. SELECT 밖 참조는 선택한 출처를 찾는 역할만 하며 경로의 출력 단계가 아니다. 동일한 이름의 CTE 출력이 있더라도 쓰기 대상을 선택해서 해당 읽기 경로를 열지 않도록 대상 토큰을 구분한다.

## 최신 명확화: 출처와 선택 참조

사용자 MERGE 예제에서 a.deptno는 INTO emp a 선언을, b.TEST는 USING SELECT의 TEST 출력을 출처로 사용하고 선택한 참조 자체도 보여주어야 한다. 따라서 대상 컬럼을 제외하거나 외부 참조를 숨기는 이전 결정은 대체한다. 변경문 컬럼의 소스 노드와 현재 참조 노드를 연결하되 대입 관계는 만들지 않는다. 일반 SELECT의 기존 출력 단계 규칙과 조건 서브쿼리 제외는 유지한다.

## 전체 참조와 값 선택 조사

외부 참조를 커서 위치에서만 생성하던 방식은 출처에서 하위 사용처를 찾을 수 없었다. 현재 문장의 변경문 컬럼 참조를 미리 source에 연결하면 기존 양방향 그래프 순회로 전체 경로를 재사용할 수 있다. 선언 토큰은 별도로 제외하고 키워드 목록에 있는 이름도 한정된 컬럼 또는 명확한 대상으로 쓰이면 인식한다.

SELECT 출력 expression은 원문 토큰 위치를 보존하므로 값 선택을 그 슬롯으로 매핑할 수 있다. 문자열 내용 자체로 검색하지 않아 다른 소스·슬롯·문장의 같은 값이 섞이지 않는다. SELECT 밖 VALUES·주석은 시작 노드로 사용하지 않는다.

## 후속 정렬 결정

- 결정: 등호 정렬은 WHERE·ON·HAVING·SET별로 독립 적용한다.
- 근거: 조건과 대입 모두 동일 옵션으로 읽기 쉽게 정렬하되 서로 다른 절이 영향을 주지 않아야 한다.
- 대안: 전역 정렬은 관계없는 긴 컬럼이 모든 절의 폭을 넓히므로 제외한다. 새 설정 필드는 기존 선택을 잃게 하므로 사용하지 않는다.
- 첫 SET 표현식은 기존 헤더 기준 열을 사용하며 줄바꿈을 새로 만들지 않는다.

## UPDATE 분기 기준 폭

MERGE 문장 종류와 분기별 키워드 정렬 폭을 구분한다. UPDATE의 폭은 6이며 다음 WHEN부터 MERGE의 폭 5를 사용한다. 전체 MERGE 폭을 6으로 바꾸면 INTO·ON의 기존 정렬을 깨므로 제외한다.

ON 조건 개수는 단순 AND 문자열 검색으로 결정하지 않는다. 최상위 논리 연결만 세어 BETWEEN·CASE·서브쿼리가 단일 조건의 들여쓰기를 바꾸지 않도록 한다. 조건 기준 열은 재귀 포매터의 일시 상태이며 새 영속 데이터는 없다.
