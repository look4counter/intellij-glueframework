# 검증 기록

## 구현 전 분석

요구사항 6개와 성공 기준 3개를 작업 8개에 연결했다. 중복·모호성·충돌·미연결 작업은 없었다. 헌법은 미작성 템플릿으로 검사를 생략했다. 명세 품질 점검표 7개가 모두 통과했다.

## 빌드 및 배포

- queryeditor와 modeleditor 및 루트 Kotlin 컴파일 성공.
- buildPlugin 성공: 25개 작업 실행.
- 배포물: build/distributions/intellij-glueframework-1.0.0-SNAPSHOT.zip.
- ZIP 메인 JAR에서 두 모듈 클래스, 등록 XML 두 개, 루트 plugin.xml, 기존 도구 창 클래스를 확인했다.
- 기존 플러그인 ID 및 XML과 소스 연결 검사를 통과했다.

## 실행 환경

기본 캐시와 Gradle 실행본의 쓰기 권한 문제를 해결하기 위해 작업 폴더에 Gradle과 캐시를 복사하고 로컬 Java 21 경로를 지정했다. 검증 보조 파일은 .gitignore에 등록했다.

## 통합 테스트 및 수렴 점검

최초 통합 실행은 오프라인 테스트 의존성 해석에서 실패했다. 설정 캐시 없이 재시도하니 테스트 소스 컴파일까지 진행되었으나 루트 테스트의 모듈 클래스 참조가 해석되지 않았다. 조립 의존성과 별도로 테스트 컴파일 의존성을 명시하는 보완 작업을 수렴 목록에 추가했다.

루트에 두 모듈의 testImplementation을 추가한 뒤 compileTestKotlin과 테스트 코드 계측이 성공했다. buildPlugin도 최신 상태로 확인했다. 실제 테스트 실행은 다음 캐시 누락으로 실패했으며 테스트 성공으로 처리하지 않는다.

- org.assertj:assertj-core:4.0.0-M1
- com.jetbrains.intellij.java:java-resources-en:253.33813.55

## Design/Source 멀티뷰 확장 결과

이하 결과가 이전 단계의 테스트 실행 제한을 대체한다. 기존 명세에 FR-007~FR-013과 사용자 이야기 3·4를 추가하고 명세·계획·작업 분석을 진행했다. 요구사항 총 13개가 모두 작업에 연결됐고, 중복·모호성·충돌은 없었다. 명세 품질 항목 13개가 통과했다.

### 구현

- queryeditor와 modeleditor가 각각 Design과 Source 제공자를 갖는다.
- Design은 기본 안내 화면이며 원본 파일을 수정하지 않는다.
- Source는 실제 IntelliJ TextEditor를 재사용하고 두 파일 형식은 XML 언어를 사용한다.
- 기본 텍스트 탭은 숨기고 Design을 Source 앞에 배치한다.
- Source의 문서·실행 취소·상태·탐색·하이라이터·구조 뷰 및 수명을 원래 편집기에 위임한다.
- XML 플랫폼 모듈 의존성을 선언하고 단일 배포 구조를 유지했다.

### 자동 검증

## 쿼리 Design 확장 결과

이하 결과가 쿼리 Design의 이전 안내 화면 범위를 대체한다. 명세·명확화·계획·작업·분석을 순서대로 갱신하고 구현했다. 추가 요구사항 FR-014~FR-023의 10개를 T019~T026에 연결했으며 명세 품질 점검표는 총 20개 항목이 통과했다. 기존 FR-010과 관련 문서는 현재 쿼리 편집 범위에 맞춰 조정했다.

### 구현 내용

- queryMap의 desc를 오른쪽 최상단에 표시하고 id·desc·resultType 입력, isNamed 체크박스와 query.id 목록을 배치했다.
- 목록은 직접 query 태그를 문서 순서로 표시하고 첫 행을 기본 선택한다. 선택에 따라 왼쪽 SQL과 속성이 함께 바뀐다.
- 왼쪽은 IntelliJ EditorTextField 기반의 다중 행 편집기로 줄 번호·스크롤·편집기 글꼴을 사용한다. SQL 문법과 실행 기능은 추가하지 않았다.
- 선택 태그의 스마트 참조를 사용하여 중복 id와 id 변경에도 대상 쿼리를 구분한다. 선택 전환 전 대기 수정을 처리한다.
- SQL 본문만 CDATA로 교체하고 속성은 XML 이스케이프 후 수정한다. SQL 표시와 속성 표시에는 디코딩된 값을 사용한다. 다른 query·주석·네임스페이스는 보존한다.
- Source 원문 문서와 연결하여 수정·실행 취소·다시 실행·저장이 반영된다. SQL 표시 문서는 쿼리별로 분리한다.
- 오른쪽 패널은 선호 320픽셀·최소 220픽셀이고 사용자가 분할 구분선을 이동할 수 있다.
- 빈 목록·잘못된 XML·읽기 전용·중첩 본문을 처리하며 편집기 해제 시 리스너와 SQL 편집 컴포넌트, 대기 작업을 정리한다.

## 설명 편집과 화면 정리 검증

추가 요구사항 FR-024~FR-026과 SC-011을 T027~T030에 연결했다. 명확화 검토에서 중요 미해결 사항은 없었다. 구현 전 분석에서 추가 요구사항의 작업 연결률은 100%이고 중복·충돌·미연결 작업은 없었다. 명세 품질 점검표 22개가 통과했다. 헌법은 미작성 템플릿이므로 검사를 생략했다.

## 파일 형식 아이콘 검증
