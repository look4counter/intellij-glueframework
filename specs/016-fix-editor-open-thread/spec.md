# 편집기 열기 스레드 오류 수정 명세

작성일: 2026-11-03 | 상태: 명확화 완료

## 사용자 시나리오와 검증

### 사용자 이야기 1 — 찾기 결과에서 쿼리 열기 (우선순위 P1)

찾기창에서 쿼리 파일을 열면 오류 없이 대상 쿼리를 선택한다.
독립 검증: 쓰기 의도 잠금 없는 문맥에서 편집기를 생성하고 검색 위치로 이동한다.

1. 닫힌 파일을 검색 결과로 열면 해당 쿼리가 선택된다.
2. 열린 파일에서 연속 이동하면 마지막 요청을 선택한다.
3. 미반영 원문 변경이 있으면 최신 내용으로 이동한다.

### 사용자 이야기 2 — 모델과 서비스 열기 (우선순위 P1)

찾기창과 일반 파일 열기로 모델과 서비스 파일을 열면 다이어그램을 표시한다.
독립 검증: 잠금 없는 생성과 선택 통지 후 예약 갱신의 노드 표시를 확인한다.

1. 모델 파일의 초기 노드를 오류 없이 표시한다.
2. 서비스 직접 편집 모드에서도 초기화와 재선택이 성공한다.

### 경계 조건

쓰기 불가능한 모달 문맥은 창 종료 후 실행한다. 폐기된 편집기와 무효 파일의 지연 요청은 취소한다. 연속 이동은 마지막 요청을 보존한다. 읽기 전용 파일도 표시와 탐색이 가능하다.

## 기능 요구사항

- FR-001: 생성·초기화·선택 통지·검색 이동을 두 편집기에서 조사하고 쓰기 스레드 위반을 제거한다.
- FR-002: 쿼리 ID와 위치 이동은 안전한 문맥에서 최신 원문을 반영한다.
- FR-003: 지연 요청은 마지막 이동을 보존하고 폐기·무효 파일 접근을 차단한다.
- FR-004: 모델 및 서비스 초기 갱신의 안전성을 회귀 검증한다.
- FR-005: 단순 열기와 이동은 원문과 저장 상태를 변경하지 않는다. 기존 열기 시 SQL 정규화 정책은 유지한다.

## 성공 기준

- SC-001: 잠금 없는 열기·탐색 회귀 테스트의 스레드 오류가 0건이다.
- SC-002: 연속 이동과 폐기 취소 테스트가 모두 통과한다.
- SC-003: 관련 쿼리·모델 테스트와 컴파일이 통과한다.

## 가정과 명확화

사용자가 확인한 재현 경로는 찾기창이다. 파일 검색과 본문 검색의 공통 진입점을 포함한다. XML 정책과 기존 기능은 유지한다. 명확화 검토에서 추가 결정이 필요한 모호성은 발견하지 못했다.

## 파일 열기 호환성 보완 (2026-11-03)

사용자 제보: 파일을 열 때 메서드가 없다는 오류가 발생한다. 명확화 검토 결과 핵심 모호성은 없으며, 기존 지원 환경과 파일 형식을 유지하는 호환성 수정으로 범위를 한정한다. 실제 사용자 IDE 버전은 확인되지 않았으므로 해당 환경에서의 재현 완료를 주장하지 않는다.

### 사용자 이야기 3 — 호환되는 파일 열기 (우선순위 P1)

쿼리·모델·서비스 파일을 열면 메서드 누락 오류 없이 Design과 Source 보기가 생성되어야 한다.
독립 검증: 편집기 생성 네 경로의 호출 의존성과 기존 잠금 없는 생성 회귀 검증을 함께 확인한다.

1. 닫힌 쿼리 파일을 열면 두 보기를 생성한다.
2. 닫힌 모델 또는 서비스 파일을 열면 두 보기를 생성한다.
3. 쓰기 의도 잠금이 없는 생성 경로에서도 기존 스레드 안전성을 유지한다.

- FR-006: 편집기 생성 네 경로에서 버전별 메서드 서명 차이로 인한 누락 오류를 제거하고 기존 잠금 보호를 유지한다.
- SC-004: 생성 네 경로에서 문제 메서드에 대한 바이너리 참조가 0개이며 기존 파일 열기 회귀 검증이 모두 통과한다.
