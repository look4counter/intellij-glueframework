# 기능 명세: Activity 편집 쓰기 스레드 오류
**작성일**: 2026-10-26
**상태**: 명세 검토 완료
**입력**: Activity 편집창에서 Access is allowed from write thread only 오류가 발생한다.

## 사용자 시나리오 및 검증
### 사용자 이야기 1: 속성 편집 복구 (우선순위: P1)
사용자는 Activity를 더블클릭하여 현재 이름·속성·설명을 확인하고 수정한다.
기본 기능이 차단되므로 최우선으로 복구한다. 실제 캔버스 더블클릭으로 독립 검증한다.

1. 유효한 Activity를 더블클릭하면 스레드 오류 없이 현재 값이 전달된다.
2. 취소하면 원문을 유지한다.
3. 확인하면 변경을 반영하고 실행 취소로 복구한다.

### 경계 조건
- 편집 중 원문 변경 시 덮어쓰지 않는다.
- 읽기 전용 문서와 유효하지 않은 노드는 기존 제한을 따른다.
- 동일 원인의 Diagram·Transition 편집과 화면 갱신도 접근 규칙을 지킨다.
- 예약 후 편집기가 폐기되면 요청을 무시한다.

## 요구사항
### 기능 요구사항
- **FR-001**: Activity 편집 진입은 보고된 오류 없이 동작해야 한다.
- **FR-002**: 확인·취소·실행 취소 및 동시 변경 방지 동작을 보존해야 한다.
- **FR-003**: 동일 원인의 Diagram·Transition 편집 및 화면 갱신 경로에도 같은 실행 규칙을 적용해야 한다.

### 주요 개체
- Activity: 기존 이름, 속성 목록, 설명을 가진 노드.
- 편집 문서: 원문·변경 시점·실행 취소 이력을 유지하며 저장 형식은 유지한다.

## 성공 기준
- **SC-001**: 쓰기 권한이 없는 UI 이벤트에서 시작한 Activity·Transition·Diagram 편집 검증이 오류 없이 통과한다.
- **SC-002**: 확인·취소·실행 취소와 기존 속성 편집 검증이 모두 통과한다.

## 가정
- 새 기능과 저장 형식 변경은 범위에 포함하지 않는다.
- Tool Window 초기화 오류와 같은 원인인지는 로그 없이 단정하지 않는다.
- 자동 회귀 검증을 추가한다.
