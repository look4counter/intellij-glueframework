# 조사 결과

- 기존 GlueQueryEditor 설정 화면은 프로젝트 DataSource 서비스에 연결돼 있다. 별도의 포매팅 상태 서비스가 기존 DataSource 교체·선택 setter에 의해 옵션이 초기화되는 위험을 줄인다.
- 기존 포매터는 구문별 range와 Writer 열을 사용해 괄호·CASE 들여쓰기를 계산한다. 결과 문자열을 나중에 단순 공백 치환하면 서브쿼리 들여쓰기가 어긋날 수 있어 토큰별 추가 공백을 계산한 뒤 재렌더링한다.
- 기존 단축키 액션에서 옵션을 읽으면 저장만으로 SQL이 변경되지 않고 선택 포매팅·Undo 경로를 그대로 유지할 수 있다. 미해결 기술 질문은 없다.
