# 검증 안내

CTE 두 단계에서 마지막 SELECT 컬럼을 Ctrl+클릭해 한 단계 입력으로 이동하고 CTE 이름·별칭 한정자도 확인한다. 복합 출력은 출처 선택 목록을 확인한다. TRACE 트리 이동과 Ctrl 이동을 섞어 뒤로·앞으로 및 뒤로 간 후 새 이동을 검증한다. SQL 수정과 쿼리 전환 뒤 기록이 혼동되지 않는지 확인한다.

자동 검증: 기존 로컬 Gradle·캐시 JBR 21·오프라인 초기화 설정으로 SqlTraceNavigationTest, SqlColumnTraceTest, SqlTableTraceTest, SqlTraceGraphTest, QuerySqlEditorTest를 실행한다.

## 자동 검증 결과 (2026-11-10)

로컬 Gradle 9.7.1 및 캐시된 IDEA 2025.3.6.1의 JBR 21을 지정하여 다음 회귀를 실행했다.

```powershell
$env:GRADLE_USER_HOME = "$PWD/.gradle-user-home"
$sqlJbr = "$PWD/.gradle-user-home/caches/9.7.1/transforms/41d2ee0b381ac1ce59d15aa3eb4932b1/transformed/idea-2025.3.6.1-win/jbr"
& .gradle-validation/gradle-9.7.1/bin/gradle.bat test --tests 'com.look4counter.Sql*Test' --tests com.look4counter.QuerySqlEditorTest --offline --no-configuration-cache -I .gradle-validation/press-position.init.gradle "-Porg.gradle.java.installations.paths=$sqlJbr"
```

총 188개가 실패·오류·건너뜀 없이 통과했다. 새 출처 해석 5개, 실제 편집기 51개, 포매터 45개 및 기존 컬럼·테이블·그래프·자동완성·검증기 회귀를 포함한다. Ctrl+클릭·다단계 이동·팝업 선택·뒤로·앞으로·새 이동 후 앞으로 기록 삭제·문서 편집 초기화·쿼리별 기록·트리 이동·SQL/XML 보존을 검증했다. 팝업은 IntelliJ UiInterceptors로 캡처하여 실제 후보 선택 콜백과 이동 결과를 확인했다. 인용된 출력의 출처 오프셋은 기존 그래프와 동일하게 출력 별칭 위치를 사용한다.

세미콜론이 앞 테이블로 잘못 연결되는 경계 회귀를 확인하고 구두점·공백·주석 차단으로 해결했다. diff 공백 검사를 통과했다. 실제 사용자 IDE의 수동 조작이나 배포 ZIP 생성은 수행하지 않았다.

## 후속 검증 시나리오

`WITH a AS (SELECT id FROM physical) SELECT id FROM a`의 마지막 id에 Ctrl hover를 하여 토큰만 밑줄이 생기는지 확인한다. Ctrl 해제·이탈·편집 후 사라져야 한다. 같은 위치에서 Ctrl+클릭의 누름·뗌·클릭을 모두 보내 전용 출처 액션이 한 번 실행되고 기본 GotoDeclaration은 실행되지 않는지 검사한다.

`WITH a AS (SELECT id AS renamed FROM physical) SELECT renamed FROM a`에서 바깥 renamed는 안쪽 renamed까지만 이어지고 id와 연결되지 않아야 한다. 같은 이름의 서로 다른 테이블·별칭·문장은 격리되어야 한다. 조건절 참조는 회색 배경에 포함하되 트리의 출력 단계 목록에는 추가하지 않는다. 같은 이름의 두 소스가 합쳐지는 표현식으로 복수 출처 팝업·트리 재합류·선택 상태를 검증한다.

## 후속 자동 검증 결과 (2026-11-10)

위 전체 SQL·실제 편집기 명령으로 192개가 실패·오류·건너뜀 없이 통과했다. 실제 편집기 53개, 컬럼 추적 33개, 출처 탐색 7개와 기존 포매터·테이블·그래프·자동완성·검증기 회귀를 포함한다.

Ctrl hover의 실제 토큰 범위, Ctrl 해제·정지 상태 Ctrl 누름·마우스 이탈·편집 시 밑줄 제거, 회색 배경의 정확한 컬럼 범위와 소스 격리·테이블 선택·쿼리 전환 시 해제를 검증했다. IDE 마우스 디스패처에 누름·뗌·클릭을 모두 보내 3번의 사용자 클릭이 전용 출처 액션 3번으로 처리되고 기본 GotoDeclaration은 0번 실행되는 것을 확인했다. 기존 마우스 누름만 보내던 검증을 실제 단축키 경로로 바꾸었다.

이름 변경 전달을 기대했던 회귀는 새 동명 계약으로 갱신했다. AS 별칭·명시 CTE 컬럼·파생 컬럼·UNION의 이름 변경에서 경로가 끊기고 같은 이름의 분기·재합류는 유지된다. 표현식 안에서 원래 이름을 직접 선택하면 그 입력 이름의 구간만 추적한다. SELECT 값 선택은 해당 출력 슬롯 기준을 유지한다. 이름만 같은 다른 소스는 회색 배경에 포함되지 않으며 조건절 참조는 강조에만 추가하고 트리 출력 단계는 유지한다.

메인·테스트 컴파일 및 diff 공백 검사도 통과했다. 실제 사용자 IDE에서의 수동 검증과 배포 ZIP 생성은 수행하지 않았다.

## 테이블 강조·동명 경계·버튼 제거 검증 (2026-11-10)

사용자가 별칭을 같은 테이블의 참조로 취급하는 기준을 선택했다. 테이블 이름 경로가 다른 간선은 끊고 선택된 관련 노드의 CTE 정의·소스 이름·별칭 선언·한정자 참조에 회색 배경을 제공한다. 같은 이름의 다른 FROM 바인딩·셀프 조인·중첩 CTE·문장은 섞지 않는다. 테이블 이름 변경을 넘나들던 과거 기대를 최신 계약으로 갱신했다.

추적 목록의 뒤로·앞으로 JButton과 NORTH 영역을 제거했다. 기록은 IDE ACTION_GOTO_BACK·ACTION_GOTO_FORWARD의 활성 키맵 단축키를 SQL 에디터에 등록한 로컬 액션으로 유지한다. 새 도구 모음이나 대체 버튼은 없다.

위 전체 SQL·편집기 검증 명령으로 총 200개가 실패·오류·건너뜀 없이 통과했다. 테이블 추적 18개·출처 탐색 7개·실제 편집기 56개와 기존 포매터·컬럼·검사기·자동완성·그래프 회귀를 포함한다. 정확한 회색 범위, 별칭·스키마·인용 이름·바인딩 격리, 테이블 정의의 Ctrl 이동 중단, 컬럼/테이블 강조 교체·쿼리 전환 제거, 버튼 및 빈 버튼 영역 부재와 키맵 바인딩, 쿼리별 이동 기록·새 분기·편집 초기화를 확인했다.

트리 접기·펼치기·선택 유지와 재귀 중단을 동명 테이블 예제로 검증했다. 표시 한도는 서로 다른 CTE 이름의 다이아몬드 계보 대신 동일 이름의 재귀 참조 1,050개로 검증하여 2,048개 제한을 유지했다. 메인·테스트 컴파일과 diff 공백 검사도 통과했다. 실제 사용자 IDE 수동 조작 및 배포 ZIP 재생성은 수행하지 않았다.
