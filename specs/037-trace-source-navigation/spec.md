# 기능 명세: 추적 출처 이동과 탐색 기록

작성일: 2026-11-10
상태: 명세 완료
입력: SQL 컬럼·테이블을 Ctrl+클릭하여 어디에서 왔는지 한 단계 이전 출처로 이동하고 앞으로·뒤로 이동한다.

## 사용자 시나리오와 검증

### 사용자 이야기 1: 출처로 바로 이동 (P1)

SQL에서 컬럼·테이블을 Ctrl+왼쪽 클릭하면 현재 추적 경로의 직전 출처로 이동한다. CTE·파생 출력은 가장 가까운 입력 단계로 이동하며 테이블 한정자는 해당 소스 선언으로 이동한다.

인수 기준: CTE 컬럼 참조에서 중간 출력으로, CTE 테이블 참조에서 정의로, 테이블 별칭 한정자에서 선언으로 이동한다. 입력이 여럿이면 출처 선택 목록을 제시한다. 단일 입력은 바로 이동하고 출처 없는 항목·주석·공백에서는 이동하지 않는다.

### 사용자 이야기 2: 이동 기록 되짚기 (P1)

TRACE 패널의 뒤로·앞으로 버튼으로 Ctrl+클릭 및 기존 트리 이동을 되짚는다. 기록이 없는 방향은 비활성화한다. 뒤로 간 뒤 새 위치로 이동하면 이전 앞으로 기록은 제거한다.

인수 기준: A → B → C 이동 후 뒤로를 두 번 누르면 A, 앞으로를 누르면 B다. 기록은 쿼리별로 독립적으로 유지하며 SQL 변경 시 해당 쿼리 기록을 지운다.

## 요구사항

- FR-001: Ctrl+왼쪽 클릭한 실제 토큰 위치의 기존 컬럼·테이블 추적을 사용해 한 단계 이전 출처로 이동한다. 테이블 추적 우선순위를 유지하고 대입 좌우를 연결하지 않는다.
- FR-002: 복수 출처는 이름·행·SQL 문맥을 표시한 선택 목록을 제공한다. 출처 없음·자기 자신·미지원·주석·리터럴 외부 추적 실패에는 이동하지 않는다. 기존 SELECT 값 추적은 유지한다.
- FR-003: 일반 클릭·오른쪽 클릭·여백 클릭은 새 출처 이동을 수행하지 않는다. 기존 트리 클릭·Enter·확장 상태·편집 동작은 유지한다.
- FR-004: Ctrl+클릭 및 트리로 이동한 시작·도착 위치를 기록하고 뒤로·앞으로 버튼을 제공한다. 새 이동은 앞으로 기록을 버리고 연속 중복은 저장하지 않으며 기록은 최대 100개로 제한한다.
- FR-005: 기록은 쿼리 문서별로 분리하며 문서 변경 시 무효화하고 문서 전환·에디터 해제 뒤 지연 분석 결과로 이동하지 않는다.
- FR-006: 이동은 SQL·원본 XML·Undo 기록을 변경하지 않으며 UI 분석은 백그라운드에서 수행하고 기존 분석·취소 한도를 유지한다.
- FR-007: 출처 해석·분기·클릭·트리·기록·쿼리 전환·편집 무효화와 기존 추적·편집기 회귀를 자동 검증한다.

## 주요 개체

출처 후보는 기존 추적 그래프의 직전 입력 노드이며 이름·행·오프셋을 가진다. 탐색 기록은 문서 식별값·수정 번호·위치 목록·현재 인덱스를 가진다.

## 성공 기준

- SC-001: 단일 출처는 한 번의 Ctrl+클릭으로 이동하고 다중 출처는 한 번의 후보 선택으로 이동한다.
- SC-002: 새 이동·뒤로·앞으로·쿼리 전환·편집 무효화 회귀가 모두 통과하며 SQL과 XML이 변경되지 않는다.
- SC-003: 기존 SQL 추적 및 실제 편집기 회귀가 모두 통과한다.

## 가정과 명확화

사용자가 “컬럼이나 테이블이 어디에서 왔는지”라고 명확히 하여 이전 위치는 커서 이력이 아니라 직전 출처로 확정했다. 커서 이력은 별도의 앞으로·뒤로 요청으로 처리한다. 쿼리를 넘는 자동 이동 대신 쿼리별 기록을 제공하며 SQL 편집 시 잘못된 오프셋 재사용을 막기 위해 기록을 초기화한다. 새 단축키는 기존 IDE 탐색 단축키와 충돌하지 않도록 추가하지 않는다.

## 후속 명세: 링크 안내·동명 컬럼 강조·이름 변경 경계 (2026-11-10)

### 사용자 이야기 3: 이동 가능 링크 안내 (P1)

Ctrl을 누른 채 이동 가능한 컬럼·테이블 위에 마우스를 올리면 해당 토큰에 밑줄과 손 모양 커서를 표시한다. 클릭은 SQL 출처 탐색만 실행하고 IntelliJ 기본 선언 탐색 오류를 띄우지 않는다.

### 사용자 이야기 4: 같은 이름의 컬럼 추적과 회색 강조 (P1)

컬럼 선택 시 같은 출처·같은 컬럼명의 연결 구간을 회색 배경으로 표시한다. 다른 이름으로 바뀌는 별칭·CTE 명시 컬럼·UNION 출력 경계에서는 추적을 멈춘다. 같은 이름이어도 다른 테이블·문장은 섞지 않는다.

- FR-008: Ctrl hover 밑줄은 실제 출처가 있는 토큰에만 표시하며 Ctrl 해제·마우스 이탈·편집·쿼리 전환·해제 시 제거한다. Ctrl을 마우스 정지 상태에서 눌러도 안내를 표시한다.
- FR-009: SQL 에디터의 Ctrl+왼쪽 클릭은 전용 액션으로 처리하여 IntelliJ 선언 탐색과 중복 실행하지 않는다. 누름·뗌·클릭 전체 이벤트 경로와 이동 기록 중복 방지를 검증한다.
- FR-010: 컬럼 추적은 기존 식별자 비교 규칙에 따라 이름이 같은 간선만 연결한다. id AS employee_id 등의 이름 변경은 경계다. 테이블 추적 규칙은 유지한다.
- FR-011: 현재 컬럼 추적 연결 구간의 선언·별칭·참조 토큰을 회색 배경으로 강조한다. 한정자·테이블 선언·주석·문자열 및 같은 이름의 다른 소스는 제외한다. 조건절의 같은 소스·이름 참조도 강조하되 기존 트리의 표시 단계는 바꾸지 않는다.
- FR-012: 컬럼·커서·문서 변경 시 회색 강조를 갱신하고 테이블·공백 등 컬럼 추적 대상이 아닌 위치에서는 제거한다. 기존 진단·파라미터·괄호·포맷·Undo 및 탐색 기록을 유지한다.
- FR-013: Ctrl 안내·전체 클릭 경로·기본 탐색 충돌 방지·회색 토큰 범위·이름 변경 경계·소스 격리·지연 결과 차단을 회귀로 검증한다.

SC-004: 후속 UI·분석 회귀와 최신 동명 계약으로 갱신한 기존 회귀가 전부 통과한다.

명확화: 사용자가 컬럼명이 같을 때만 계속 추적하도록 요청했으므로 다른 이름의 별칭으로 이어가던 기존 계약과 해당 기대는 FR-010으로 대체한다. 이름 비교는 SQL의 기존 비인용 대소문자 무시·인용 이름 구분을 따른다. 밑줄·회색 강조는 텍스트를 변경하지 않는다. 추가 질문은 없다.

## 후속 명세: 동명 테이블 추적과 회색 강조 (2026-11-10)

### 사용자 이야기 5: 같은 테이블의 참조 확인 (P1)

테이블·CTE·파생 테이블 별칭을 선택하면 해당 테이블 바인딩의 이름·별칭 선언·한정자 참조를 회색 배경으로 표시한다. 컬럼과 마찬가지로 테이블 이름이 다른 경계에서는 추적을 멈춘다.

- FR-014: 테이블 추적 간선은 기존 식별자 비교 규칙으로 테이블 이름 경로가 같은 경우에만 연결한다. CTE t는 t 정의·참조끼리 연결하며 다른 이름의 물리 테이블·다른 CTE·파생 테이블 내부로 이어가지 않는다. 스키마 경로와 인용 이름도 비교한다.
- FR-015: 선택한 테이블과 연결된 정의·FROM/JOIN 이름·별칭 선언·컬럼 한정자 참조를 기존 회색 배경으로 표시한다. employee e의 employee와 e.id의 e는 같은 바인딩의 참조로 함께 표시한다. 컬럼 부분·주석·문자열은 포함하지 않는다.
- FR-016: 같은 철자의 다른 FROM 인스턴스·셀프 조인 바인딩·다른 쿼리 문장·중첩 CTE 가림은 임의로 합치지 않는다. 같은 CTE 정의를 참조하는 분기들은 같은 테이블로 취급한다.
- FR-017: Ctrl 밑줄·이동도 새 테이블 경계를 지킨다. 한정자에서 자기 소스 선언으로 이동하고 CTE 참조에서 같은 이름의 정의까지만 이동한다. 배경은 커서·편집·쿼리 전환 시 최신 결과로 교체하고 기존 컬럼 추적·기록·진단을 유지한다.
- FR-018: 테이블 이름 변경 경계·정확한 배경 범위·별칭·소스/문장 격리·인용/스키마·재귀·실제 편집기 회귀를 자동 검증한다.

SC-005: 최신 테이블 계약으로 갱신한 기존 회귀 및 전체 SQL·편집기 회귀가 통과한다.

명확화: 사용자가 employee e의 employee·e 참조를 함께 표시하고 t에서 employee로는 이어가지 않는 기준을 선택했다. 별칭은 테이블의 참조 이름이며 별도 이름 변경 경계로 취급하지 않는다. FR-014~FR-018은 이전 034 및 이번 명세의 다른 이름 테이블까지 전달하던 기대와 테이블 배경을 비우던 규칙을 대체한다. 컬럼의 이름 제한·표시는 유지한다.

## 추가 명확화: 추적 목록의 탐색 버튼 제거

### 사용자 이야기 6: 추적 목록의 불필요한 버튼 제거 (P1)

- FR-019: 오른쪽 추적 목록 위의 뒤로·앞으로 버튼과 해당 버튼 영역을 제거한다. 목록·트리의 기존 여백과 동작은 유지한다.
- FR-020: 이전에 요청한 이동 기록은 유지하고 SQL 에디터에서 IDE의 뒤로·앞으로 액션에 설정된 단축키로 사용한다. 쿼리별 기록·편집 초기화·앞으로 분기 삭제·Ctrl 이동은 유지한다. 화면에 대체 버튼이나 새 도구 모음을 추가하지 않는다.

명확화: 사용자는 목록 위의 버튼 삭제를 요청했으므로 표시 UI만 제거하고 기존 탐색 기록 기능은 유지한다. FR-019~FR-020은 앞서 뒤로·앞으로 버튼을 제공하던 UI 계약을 대체한다.
