# 기능 명세: 확정 출력 컬럼 오류 표시와 주석 색상

작성일: 2026-11-07
상태: 명확화 완료
입력: QueryEditor에서 CTE·서브쿼리의 확실한 출력 컬럼을 기준으로 잘못된 참조를 전체 구역에서 오류로 표시하고 주석 글자색을 녹색 계열로 바꾼다.

## 사용자 시나리오와 검증

### 사용자 이야기 1: 확정된 컬럼 오타 발견 (P1)

WITH t AS (SELECT id FROM physical) 뒤에서 t.missing을 SELECT·WHERE·JOIN ON·GROUP BY·HAVING·ORDER BY 등에 쓰면 missing에 오류 표시가 생긴다. 파생 테이블·명시 컬럼 이름·다단계 CTE에서도 동일하게 동작한다. UPDATE·DELETE·MERGE 등의 구역에서 확정 관계를 참조하는 경우도 검사한다.

### 사용자 이야기 2: 불확실한 경우의 오탐 방지 (P1)

물리 테이블의 컬럼을 알 수 없거나 물리 테이블 SELECT *가 전달된 결과는 오류라고 단정하지 않는다. 일부 컬럼 이름을 안다는 이유만으로 나머지 이름이 없다고 단정하지 않는다. 올바른 별칭·함수·문자열·주석·파라미터·출력 별칭에 오류를 표시하지 않는다.

### 사용자 이야기 3: 편집 중 확인 (P1)

오류 컬럼은 IDE 테마에 맞는 빨간 오류 물결선과 설명으로 표시되고 수정하거나 쿼리를 바꾸면 갱신된다. SQL·Source·Undo 기록을 바꾸지 않는다. 한 줄·블록 주석은 밝은 테마와 어두운 테마 모두 녹색 계열로 표시한다.

## 요구사항

- FR-001: 명시 SELECT 출력·출력 별칭·명시 컬럼 목록·확정 가능한 별표로 CTE·파생 관계의 컬럼 집합과 확정 여부를 구분한다.
- FR-002: 확정 관계의 존재하지 않는 컬럼을 구역에 관계없이 검사한다. SELECT·WHERE·JOIN ON/USING·GROUP BY·HAVING·ORDER BY와 해석 가능한 DML의 조건·SET·VALUES 등을 포함한다. 오류 범위는 컬럼 식별자 부분이다.
- FR-003: 한정자 없는 참조는 접근 가능한 모든 관계가 확정돼 있고 어디에도 컬럼이 없을 때만 오류로 표시한다. 알 수 없는 물리 테이블·함수·별표·순환·미완성 구문에는 단정하지 않는다. 알 수 없는 별칭 자체의 검증과 DB의 전체 문법 검증은 범위 밖이다.
- FR-004: 쿼리 범위·별칭 가림·상관 참조·문장 격리·인용 이름을 지킨다. 출력 별칭의 허용 가능한 참조, 함수명·자료형·주석·문자열·파라미터·DB 의사 컬럼을 일반 컬럼 오타로 취급하지 않는다.
- FR-005: SQL 편집기에 오류 물결선과 설명을 표시한다. 입력·문서 전환 시 즉시 이전 표시를 지우고 지연 분석 후 최신 결과만 반영한다. 편집기 종료 후 결과를 버리고 리스너·표시를 정리한다. 오류가 있어도 저장·포매팅을 임의로 차단하지 않는다.
- FR-006: 분석 중 DB에 접속하거나 SQL·Source·Undo를 변경하지 않는다. 길이 262,144자·토큰 20,000개·깊이 48 등 기존 제한과 취소를 지키며 분석은 UI 밖에서 수행한다.
- FR-007: 확정/불확정 경계·전체 구역·DML·범위·인용 이름·미완성·편집기 갱신을 자동 검증하고 사용법과 한계를 기록한다.
- FR-008: 한 줄·블록 주석의 텍스트를 녹색 계열로 표시하고 밝은 테마·어두운 테마 각각 적절한 색을 사용한다. 기존 다른 토큰 색상과 주석 내용·편집 기능은 유지한다.

## 주요 개체

- 출력 스키마: 알려진 이름·위치와 이름/개수의 불확정 여부.
- 컬럼 오류: 식별자 시작·끝 오프셋과 설명.
- 표시 요청: 문서 식별자·변경 시각·요청 세대와 분석 결과.

## 성공 기준

- SC-001: 확정 관계의 잘못된 컬럼은 각 지원 구역에서 정확한 범위로 표시되고 올바른 컬럼과 불확정 관계에는 오탐이 없다.
- SC-002: 입력 수정·쿼리 전환·종료 후 이전 오류가 남지 않고 SQL·Source·Undo가 보존된다. 주석의 두 테마 색상 검증이 통과한다.
- SC-003: 전체 회귀·설치 ZIP·플러그인 구조 검사가 통과한다.

## 가정과 명확화

질문 0개. 사용자의 후속 지시에 따라 SELECT 절에 제한하지 않는다. 물리 테이블 메타데이터에 기반한 부재 판정은 하지 않고 SQL 자체로 확정한 관계만 검사한다. 불확실한 별표의 출력 개수·남은 이름을 모르므로 명시적 이름 일부만으로 전체 스키마가 닫혔다고 추정하지 않는다. 오류는 편집기의 의미 오류 표시이며 SQL 실행이나 서버 문법 검사와 연결하지 않는다. 주석 색상 변경은 추가 요청으로 함께 반영한다.

## 후속 명세: NULL 리터럴 오탐 방지 (2026-11-10)

### 사용자 이야기 4: 정상 NULL 표현식 보호 (P1)

SELECT NULL 및 NULL AS 별칭을 포함한 정상 SQL에서 NULL에 빨간 오류 표시가 생기지 않아야 한다. 실제로 없는 컬럼의 오류 표시는 유지한다.

- FR-009: 대소문자를 구분하지 않는 비인용 단독 NULL은 값 리터럴로 취급하여 SELECT 직접 출력·별칭 출력·함수·CASE·IS NULL 조건·DML 값에서 컬럼 부재 오류를 표시하지 않는다.
- FR-010: 한정된 t.NULL 및 인용된 "NULL"은 컬럼 식별자 검증을 유지한다. 같은 SQL의 실제 누락 컬럼 진단과 오류 범위·문서 비변경 동작을 유지한다.
- FR-011: 확정된 CTE·파생 출력과 실제 편집기에서 NULL 오탐 방지 및 실제 오류 유지를 자동 검증한다.

SC-004: 후속 단위·편집기 회귀 및 기존 SQL 회귀가 모두 통과한다.

명확화: NULL은 SQL의 값 리터럴이며 전체 DB 문법 검증을 추가하지 않는다. 인용·한정 식별자는 별개다. 기능 범위와 검증 기준에 중대한 모호함이 없고 추가 질문은 0개다. 기존 산출물·코드 변경은 보존한다.
